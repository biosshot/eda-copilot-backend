# Native PCB solver

`src/block_solver.rs` assembles blocks; `src/solver.rs` packs the board; `src/post_place_refine.rs` refines completed placements; `src/micro_router.rs` estimates route cost; `src/model.rs` defines native data. Before adding a scorer, cache, or geometry utility, search these modules and the TypeScript encoders in `src/pcb-layout/pcb-auto-place-v2/native/` for the existing representation. Keep contract versions and both sides of each changed field synchronized.

Preserve deterministic candidate reduction and hard-constraint checks. Profile expensive paths on saved exact inputs before optimizing, and compare quality plus wall time afterward. Use the existing bounded Rust parallelism; account for process/subtree workers so threads do not multiply beyond the CPU budget. The addon is isolated in process workers, not multiple Node worker threads in one process.

After Rust changes, run `cargo test --manifest-path native/pcb-board-packer/Cargo.toml` and `npm run native:build` from the repository root, then focused TypeScript tests and native replay for the affected solver. Do not infer full-board speed from a single warm replay.

For CubeCL block placement, first read [the roadmap and source reuse map](../../docs/experimental/pcb/cubecl-backend/ROADMAP.md). Preserve the proven compact-pose/resident-frame/fixed-segment-cache architecture: full mass candidate scoring, safe pruning and shortlist belong on GPU for Beam, singles and applicable pairs; do not leave a CPU score/hard-count pass over every GPU candidate. The first GPU stage may use F64; CPU backend/generator remain F64 for now. The user intends all CPU/GPU floating computation to become F32 in a separate future task with no date; the approved CPU F64 / GPU F32 intermediate path remains allowed. Keep IDs, ordinals and hard counts integer. Reuse archived OpenCL algorithms. On GPU failure discard partial results/checkpoints and restart the entire current block on CPU from its original input, without GPU retries in that attempt; verify release panic handling permits recovery. Capability guards must match the chosen precision: first-stage F64 requires GPU F64, a validated F32 path does not. Measure both the historical 8.318 s FPGA Beam reference and full-block/singles time. CPU/GPU validation belongs in separate tests, outside production scoring and timing. Preserve exact CPU reference and hard constraints; validate numerical boundaries and pruning on/off within one precision, then measure CPU/GPU quality differences under the roadmap policy.

The new GPU implementation uses CubeCL/Rust exclusively; archived OpenCL is an algorithm/performance reference, never a new runtime dependency or helper DLL. Keep one reusable GPU runtime/device/client per process shared by native threads; isolate job buffers and measure workspace-pool contention/throughput before choosing pool size. CPU code runs as native Rust with no LLVM/CPU JIT backend; target one platform `.node` within roughly 20 MB. The pre-existing USB regression is explicitly accepted temporarily and remains open in [TECH_DEBT.md](../../docs/experimental/pcb/cubecl-backend/TECH_DEBT.md).
