# Что означают режимы эксперимента

Названия получились слишком техническими. Это сохранённые настройки одного плейсера для сравнительных запусков. В обычном запуске программа **не запускает все режимы и не выбирает лучший из них**.

В этой ветке по умолчанию используется **Full Micro**. Предыдущие улучшения размещения включены, для оценки сложности соединений внутри блока используется существующий микро роутер, а у блока сохраняются несколько вариантов внутренней расстановки. Установленный отдельно backend EasyEDA этим изменением не обновлялся: название режима в отчёте не означает, что открытая в EasyEDA плата уже использует его.

## Где вообще участвует микро роутер

Плейсер решает, где стоят компоненты. Чтобы сравнить две расстановки, он вычисляет оценку: длины связей, компактность, выполнение ограничений и другие штрафы. Микро роутер добавляет приблизительную оценку сложности будущих соединений через ограниченный поиск путей.

В этих экспериментах переключается именно **маршрутизационная добавка к оценке размещения внутри обычного блока**. Эти режимы сами по себе не создают готовые дорожки на плате и не заменяют полноценный трассировщик.

Существующий алгоритм микро роутера здесь не переписывался. Добавлены выбор способа оценки, улучшения поиска расстановки и работа с альтернативными формами блоков. На уровне упаковки всей платы и в проверках postrefine существующий микро роутер продолжает использоваться даже при `Full Off` и `Full Geometry`. Независимая маршрутизационная проверка в отчёте — отдельный тест после размещения; она не выбирает победителя обычного запуска.

## Из чего составлено название

Есть три независимых решения:

1. **Как искать расстановку внутри блока:** прежний набор настроек (`legacy`) или полный экспериментальный набор (`full`).
2. **Как оценивать сложность соединений внутри блока:** микро роутер (`micro`), геометрические штрафы (`geometric`) или отсутствие этой добавки (`off`).
3. **Как использовать альтернативные расстановки блока:** оставить одну, пробовать несколько на уже упакованной плате или дополнительно переупаковать плату с другими формами блоков.

| Название в обсуждении | Имя для запуска | Поиск внутри блока | Оценка соединений внутри блока | Что делаем с формами блоков |
|---|---|---|---|---|
| Legacy | `legacy` | Прежние настройки | Существующий микро роутер | Одна форма каждого блока |
| Full Micro | `full-micro` | Предыдущие улучшения включены | Существующий микро роутер | Сохраняем до трёх форм, пробуем их после упаковки платы |
| Full Geometry | `full-geometric` | Те же улучшения | Геометрические штрафы | Тот же выбор форм после упаковки |
| Full Off | `full-off` | Те же улучшения | Маршрутизационная добавка отключена | Тот же выбор форм после упаковки |
| Full Micro Repack | `full-micro-repack` | Те же улучшения | Существующий микро роутер | Дополнительно пробуем до трёх полных упаковок платы с разными наборами форм |
| Full Geometry Repack | `full-geometric-repack` | Те же улучшения | Геометрические штрафы | Такой же дополнительный перебор упаковок платы |

В таблицах есть ещё `full-micro-single` и `full-geometric-single`. У них сохраняется только одна форма блока. Они нужны, чтобы отдельно измерить пользу хранения нескольких форм. **Single не отключает beam search**: внутри блока поиск остаётся расширенным. В итоге восемь настроек × три платы = 24 прогона.

`Legacy` — контрольный запуск прежних настроек в текущем коде ветки, а не переключение Git на старую версию программы.

## Что именно включено в Full

Для обычных блоков с 2–12 дочерними элементами одного электрического блока основной вариант получает:

- генерацию позиций возле связанных площадок и для обычных сетей;
- beam search шириной 4: удерживаем несколько промежуточных решений;
- более стабильный вес сетей, дополнительные штрафы за длинные двухконтактные связи;
- меньший вес площади общего контура и плавный штраф за вытянутую форму;
- дополнительные проходы локального улучшения, обмены парами и повторную вставку пары компонентов;
- сохранение оценки доступа к плотным выводам при расширенном поиске.

Это изменения плейсера. Парные перемещения внутри поиска блока и финальный postrefine — разные этапы. Назначение и генерация ходов postrefine не менялись.

Для незакреплённых подходящих блоков Full также сохраняет до трёх различных форм. Основная строится полным набором улучшений, две дополнительные — более простыми вариантами поиска. Это намеренно даёт разные формы, а не три одинаковых результата. Семейства и модули не получают автоматически все настройки обычного блока.

## Micro, Geometry и Off подробнее

**Micro:** при сравнении расстановок используется существующий ограниченный поиск маршрутов. Это оценка для плейсера, а не окончательная трассировка платы.

**Geometry:** вместо этого поиска проверяется небольшой набор предполагаемых линий: прямая, два Г-образных пути и четыре пути с обходом. Добавляются штрафы за обход, пересечения чужих площадок, близость к ним и пересечения с приблизительными линиями других сетей. Для связей наружу оценивается доступ к границе блока. Близость к площадкам служит приблизительной оценкой тесных проходов; полноценный анализ пропускной способности каналов здесь не реализован.

**Off:** отключается только эта маршрутизационная добавка. Обычная оценка длины связей, компактность, ограничения, проверки столкновений и прочие включённые улучшения продолжают работать. Поэтому Full Off не означает «все улучшения выключены» или «на всей плате больше нигде нет микро роутера».

## Что программа действительно выбирает автоматически

В Full Micro / Full Geometry / Full Off сначала блоки упаковываются на плате. Затем для каждого подходящего блока проверяются сохранённые внутренние формы и небольшие сдвиги на один-два шага сетки. Теперь учитываются и связи с остальной платой. Замена принимается при улучшении общей оценки и прохождении проверок геометрии и ограничений. Соседний блок этот локальный этап сам не отодвигает.

В Repack дополнительно строятся три полные упаковки: с основным набором форм и с двумя альтернативными наборами. Из них выбирается допустимый результат с лучшей общей оценкой, затем выполняется описанный локальный выбор. Это ограниченные три гипотезы, а не перебор всех сочетаний форм всех блоков.

Таким образом, автоматически выбираются **расстановки внутри выбранного режима**. Между Legacy, Micro, Geometry и Off автоматического соревнования нет. И «лучшая общая оценка» не означает автоматически «самая короткая сумма связей» или «лучше всего трассируемая плата»: оценка объединяет несколько требований. Именно поэтому мы отдельно измеряли длины и запускали маршрутизационную проверку.

## Зачем столько настроек

Это контрольные сравнения, чтобы не смешать разные причины изменения результата:

- Legacy ↔ Full Micro Single: что дали предыдущие улучшения поиска;
- Full Micro ↔ Full Geometry ↔ Full Off: полезен ли микро роутер именно в оценке блока;
- Single ↔ обычный Full: помогает ли выбор формы после упаковки;
- обычный Full ↔ Repack: помогает ли возможность заново разложить соседние блоки под другие формы.

Мы не выбирали победителя всех восьми режимов автоматически и не установили такой механизм в backend. Сейчас это инструменты эксперимента. На этих платах не получился универсальный победитель: USB локально улучшился, но вся Telemetry по сумме двухконтактных связей стала хуже. Repack сократил связи на ESPower, но не подтвердил общего выигрыша по маршрутизационной проверке и не помог Telemetry.

## Как переключать

Для повторения сохранённой Telemetry проще использовать имя настройки в тестовом скрипте. Из каталога `eda-copilot-backend`:

```powershell
node --import tsx scripts/experiment-placement-architecture.mjs Telemetry full-micro
node --import tsx scripts/experiment-placement-architecture.mjs Telemetry full-geometric
node --import tsx scripts/experiment-placement-architecture.mjs Telemetry full-off
```

Последний аргумент выбирает один режим одного запуска. Скрипт сам выставляет нужные переключатели в своём процессе. Он читает сохранённый тестовый вход, пишет результаты в `debugging/architecture/Telemetry/<имя-режима>/` и не меняет открытую плату EasyEDA. Выбранный им режим не сохраняется как новый режим backend для последующих запусков.

В обычном backend используются переменные окружения процесса:

| Настройка | `PCB_BLOCK_PROFILE` | `PCB_BLOCK_ROUTING` | `PCB_BLOCK_PORTFOLIO` |
|---|---|---|---|
| Legacy | `legacy` | `micro` | `0` |
| Full Micro — значение по умолчанию | `full` | `micro` | `1` |
| Full Geometry | `full` | `geometric` | `1` |
| Full Off | `full` | `off` | `1` |
| Full Micro Repack | `full` | `micro` | `2` |
| Full Geometry Repack | `full` | `geometric` | `2` |
| Full Micro Single | `full` | `micro` | `0` |
| Full Geometry Single | `full` | `geometric` | `0` |

Например, перед запуском backend из той же PowerShell-сессии:

```powershell
$env:PCB_BLOCK_PROFILE = 'full'
$env:PCB_BLOCK_ROUTING = 'geometric'
$env:PCB_BLOCK_PORTFOLIO = '1'
# Затем запустить собранный backend из этой же сессии.
```

Эти значения не переключают уже запущенный backend в другом процессе. Для него нужны соответствующее окружение и перезапуск. Нового переключателя в интерфейсе EasyEDA или в DSL платы не добавлено. Если все три переменные отсутствуют, код этой ветки использует Full Micro. Отдельно установленный backend должен сначала получить эту сборку; это в выполненной работе не делалось.
