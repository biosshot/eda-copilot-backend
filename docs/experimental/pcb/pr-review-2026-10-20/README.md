### Локализация причины

RouteCache не вызывается block solver или board packer; они по-прежнему выполняют полный route score. Новая incremental-реализация, однако, добавляет вызовы общих `arithmetic::obstacle` и `arithmetic::crossing`, которыми пользуется полный evaluator.

Диагностические CPU-сборки разделили время локализации/подготовки, построения route plan и вычисления его штрафов. По 320 вызовов каждой версии с чередованием:

| Часть native-вызова | main, мс | #25, мс |
|---|---:|---:|
| Подготовка внутри Rust | 1.491 | 1.463 |
| Построение плана | 1.442 | 1.406 |
| Вычисление готового плана | 5.608 | 6.239 |

Эти времена не включают всю N-API конверсию и освобождение данных, поэтому не должны суммироваться в полное wall time. Рост сосредоточен в исполнении геометрических штрафов, примерно **+11.3%**. Возврат старых тел `nets_plan` и `Plan::path` при сохранении остального PR почти не помог: 14.639 против 14.684 мс в соответствующей CPU-серии. Следовательно, объяснять регрессию исключительно переносом строк из layout.rs/plan.rs или обслуживанием кэша было бы неправильно.

Контрольная правка добавляет только `#[inline(always)]` к двум функциям obstacle/crossing. Сверка всех Rust/Cargo исходников диагностической копии с PR, с нормализацией CRLF/LF, подтвердила: содержательно изменён только arithmetic.rs, две строки. Полный вызов в последней попарной серии: CPU main **13.892 мс**, CPU PR **14.722 мс**, CPU PR с подсказками **14.072 мс**. Score неизменен.

Затем выполнена отдельная серия полного board packing: PR / inline / inline / PR, четыре потока, подробный native profile включён одинаково у обеих версий:

| CPU-вариант | Времена, с | Медиана, с | Накопленное route worker time, медиана, с |
|---|---|---:|---:|
| #25 | 36.22; 34.36 | 35.29 | 81.61 |
| #25 + две inline-подсказки | 32.53; 33.00 | 32.77 | 73.34 |

Wall time уменьшился на **7.15%**, route worker time примерно на **10.1%**. Worker time суммируется по потокам и не равно wall time. Во всех четырёх решениях одинаковые placements/rank и те же 12 634 route evaluations, 199 305 full-rank evaluations; изменение количества кандидатов не объясняет ускорение.

**Подтверждено:** регрессия исполнения общего CPU route evaluator на этом хосте, сохранение его результатов и устранение большей части лишних расходов двумя указаниями inlining. **Наиболее вероятный механизм:** новые места вызова изменили решения Rust/LLVM по встраиванию общего горячего кода. Сравнение машинных инструкций и решения inline-pass не выполнялось, поэтому это сильная экспериментальная локализация механизма, не доказательство конкретного решения LLVM.

[Диагностический патч](pr25-inline-diagnostic.patch) не применён к production-исходникам. Проверена CPU-only release сборка и 320 score probes без изменений; GPU-enabled сборка этого патча и GPU kernels в этом дополнении не проверялись. Это материал для доработки PR, а не готовое разрешение на merge. Сравнивать абсолютное время диагностических CPU-only сборок с первоначальной серией GPU-enabled бинарников напрямую нельзя.

Выборка репрезентативная, не исчерпывающая: оставшиеся дорогие block hypotheses ограничены сохранённым временем batchWallMs/batchSize до 2 с; уже завершённые более тяжёлые случаи включены. Board inputs с более чем 20 primitives не включены в завершённый replay: ESP32_C3_MAN прерван при длительном решении, PortableScope имел незавершённый исторический capture, полный board Portable_AC_DC_Telemetry не запускался. Их block cases и отдельные route-score probes частично/полностью присутствуют в таблицах. Времена corpus replay не используются для оценки производительности, поскольку одновременно собирались диагностические бинарники.
