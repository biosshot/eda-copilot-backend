## Границы задачи и обязательные правила

1. Только native block solver и его CPU/GPU backend. Контрольный тяжёлый вход — сохранённый FPGA из PortableScope. Board packing, общий post-placement refinement и вся плата исключены из текущей реализации.
2. CubeCL, исходно F64. Координаты, расстояния, веса и score не переводить в F32 или приближённые целые без решения пользователя. Целочисленные ID и индексы допустимы.
3. CPU остаётся полноценным backend. Нет совместимого GPU/драйвера, недостаточно F64 возможностей, ошибка инициализации/исполнения или неподдерживаемый вход — корректный CPU fallback. Маленькие задачи направляются на CPU до подготовки GPU буферов.
4. На GPU переносится **вся массовая оценка кандидатов**, включая дешёвую нижнюю границу, активные члены полного score, hard count, отсечение и shortlist. Не оставлять CPU проход по всем кандидатам для вычисления части score, hard count или опорных полных оценок.
5. CPU генерирует компактные poses, управляет Beam и восстанавливает полную геометрию выбранных кандидатов. Ориентации, площадки, правила, фиксированное состояние и кеши остаются на GPU; буферы переиспользуются. Обрабатывать независимых кандидатов массово, без dispatch/readback на каждого кандидата или каждый term. Последовательные зависимости Beam не объединять ценой изменения алгоритма.
6. CPU работа на малом маршрутном shortlist допускается в уже проверенной гибридной схеме: она давала 8.318 с. Это не разрешение оставить массовый base score на CPU. Новые границы CPU/GPU согласовывать, если они меняют эту архитектуру.
7. Переиспользовать существующую быструю организацию OpenCL: compact poses, resident frames, fixed MST/pad caches, GPU pruning и bounded ranking. Перевод OpenCL C в Rust/CubeCL требует адаптации языка; заново придумывать генератор, Beam, формулы или алгоритм отбора не требуется.
8. Минимум дублирования: общий Rust код вычислительных правил там, где CubeCL позволяет; разные CPU/GPU оболочки исполнения допустимы. Не достигать общности ценой потери уже измеренной скорости. Архитектурное противоречие выносить пользователю.
9. Все изменения структур, вычислений, кешей и порядка отбора проверять на результатах. Сохранять hard constraints, inventory, locked poses, ориентации, checkpoints, score и положение компонентов. По умолчанию конечная расстановка должна совпасть с CPU reference; допустимый дрейф не назначать самостоятельно.
10. Подробные CPU/GPU сравнения выполняются **в отдельных валидационных тестах**, вне таймера. В обычном GPU режиме не пересчитывать его кандидатов на CPU ради проверки. Проверка валидности GPU ответа и fallback при ошибке не являются двойной оценкой каждого кандидата.
11. Итоговая поставка — один `.node` для каждой поддерживаемой OS/arch без отдельно поставляемого helper/compiler DLL; системные библиотеки и GPU драйверы внешние. OpenCL helper остаётся только сохранённым эталоном.
12. Новое решение об алгоритме, backend архитектуре, численной точности, допустимом дрейфе или компромиссе скорости/качества: записать конкретные варианты и данные, остановить зависимую работу и спросить пользователя. Разрешение и его основание записать сюда.
