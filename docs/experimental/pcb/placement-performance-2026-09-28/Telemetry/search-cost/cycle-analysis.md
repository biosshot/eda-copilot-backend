# Current ISO: этапы и параллельность

Профиль одного изолированного прогона 2026-09-28: три текущие гипотезы, geometric, без board pack и общей post-place оптимизации. `PCB_BLOCK_SOLVER_PROFILE=1` и `PCB_BLOCK_SOLVER_DETAIL=1`; полный журнал — `cycle-profile.log`. Входы и результаты — `cycle-profile/current_iso.json.gz`. Выбранные положения и оценки точно совпали с сохранёнными.

| Этап | Работа | Время стены |
|---|---|---:|
| Подготовка | Разбор групп, проверка ролей, подготовка примитивов и входных данных | В этом изолированном прогоне отдельно не измерена |
| Beam + одиночные, группы | 8 примитивов; 2,006 с beam и 0,937 с одиночные | 2,942 с внутри потока |
| Beam + одиночные, разобранные группы | 12 примитивов; 3,858 с beam и 1,235 с одиночные | 5,093 с внутри потока |
| Beam + одиночные, C9 как passive | 12 примитивов; 3,840 с beam и 1,287 с одиночные | 5,128 с внутри потока |
| Пакет трёх гипотез | Три независимых native-потока | **5,136 с** |
| Выбор продолжения | Отбор по единой оценке и различию компоновок | Отдельно не измерен; в этот прогон выбрана только гипотеза C9 |
| Парные перемещения | 66 пар 12 примитивов, обе очередности повторной вставки | **7,342 с**, один native-поток |
| Итого изолированный native-поиск | Пакет гипотез, затем парный проход | **12,477 с** |

Полная функция `solveBlockNode` дополнительно проверяет допустимость каждого checkpoint, считает единый `blockQuality`, запускает block postrefine для неповторяющихся допустимых результатов, выбирает до трёх вариантов и сохраняет альтернативы для размещения на плате. Отдельная проверка семи сохранённых checkpoint через `refineBlockPrimitives` заняла суммарно около **0,50 с** (одиночный холодный замер). Реальное число вызовов в дереве может быть меньше из-за устранения почти одинаковых состояний. Затем родители собирают модули и board pack; это уже не время решения одного блока.

В парном проходе генератор вызывается 396 раз: для каждой из 66 пар два первых поиска и четыре поиска второй детали после двух лучших положений первой. Профиль: 646 332 проверки hard-ограничений, 376 373 кандидата отброшены по hard-рангу до оценки, 271 158 начали оценку, 232 167 дошли до её конца. У этих 271 158 оценок суммарное время **4,81 с** из 7,34 с прохода; генерация заняла 0,69 с. Внутри оценки: сигнальные коридоры 1,17 с, пересечения с падами 0,88 с, длинные локальные сети 0,55 с, доступ внешних выводов 0,53 с, топология путей 0,45 с. Вложенные времена не складываются с общим временем, и профиль не отделяет CPU self-time от вложенных вызовов.

Победивший парный checkpoint улучшил общую оценку блока с **12 531,87** после одиночных перемещений до **11 640,26**. Убирать парный этап без замены пока нельзя. Простая эвристика пропуска далёких несвязанных пар уже ухудшила USB Charge на 3,1%.

Параллельность двух уровней сейчас разная. Независимые гипотезы одного блока передаются в `solveBlockPrimitivesBatch`: native создаёт до `min(число задач, лимит потоков, доступный параллелизм)` потоков. На этом хосте доступно 12 логических CPU, бюджет блока по умолчанию 6; для Current ISO работают три потока в первом пакете и один в парном продолжении. Сам beam, одиночные и парные операции внутри одной гипотезы однопоточны.

Async-дерево может отправлять независимые дочерние блоки board в отдельные процессы, но пул `PCB_LAYOUT_SUBTREE_WORKERS` **по умолчанию равен 0**. Поэтому обычный запуск не распределяет блоки по отдельным ядрам; `Promise.all` при выключенном пуле не делает синхронные `solveNode` параллельными. Синхронный API также последователен на уровне блоков. При включённом пуле берутся только непосредственные дети board типа block/module без фиксированных или краевых компонентов, от заданного минимума (по умолчанию 8 компонентов). Проверка графа показала: Current ISO — непосредственный ребёнок board с 12 компонентами без фиксированных/краевых потомков, то есть пригоден для этого пула. Бюджет потоков для гипотез внутри каждого процесса делится на число subtree workers: при четырёх subprocess на этом хосте это один поток на блок. Такой режим может ускорить полную плату, но сделать отдельный Current ISO медленнее; нужен замер полной платы перед настройкой по умолчанию.

Главный резерв для времени самого Current ISO — 396 повторных поисков позиций и сотни тысяч оценок в парном проходе. Полезные дальнейшие проверки: измерить, сколько каждой паре даёт улучшение, попробовать безопасное раннее отсечение кандидатов пар до полной оценки и переиспользовать расчёты между двумя порядками вставки. Менять порядок/набор пар нужно с проверкой качества на разных блоках: одна уже испытанная грубая фильтрация дала регрессию. Для полного времени платы отдельно сравнить пул ветвей дерева с текущей параллельностью гипотез и замерить ожидание свободных ядер.
