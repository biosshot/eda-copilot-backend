# Откуда берутся кандидаты Current ISO

Изолированный geometric прогон: три текущие гипотезы (исходные группы, разобранные группы, C9=passive), одно выбранное парное продолжение. Micro не запускался. Дополнительные счётчики включались только через `PCB_BLOCK_SOLVER_DETAIL=1`; этот диагностический прогон занял 14,53 с против предыдущих 12,48 с, поэтому его время не служит сравнением производительности. Все checkpoints и score совпали с сохранёнными. Сырые категории считаются до удаления точных дублей; итоговое «уникальных» — сумма выходов отдельных вызовов генератора, без устранения повторов между разными вызовами.

| Этап | Вызовы генератора | Сырые позиции | После удаления дублей в каждом вызове |
|---|---:|---:|---:|
| Исходные группы, beam + singles | 208 | 307 712 | 254 352 |
| Разобранные группы, beam + singles | 352 | 496 608 | 437 728 |
| C9=passive, beam + singles | 352 | 495 712 | 436 147 |
| Парный проход C9=passive | 396 | 736 432 | 646 332 |
| **Всего** | **1 308** | **2 036 464** | **1 774 559** |

Состав сырых позиций во всём прогоне: **674 256** у корпусов и габарита уже собранной части блока, **707 544** из явных правил (`hint`, `critical_pair`), **652 680** от совпадающих сетей на падах, **1 984** от сигнальных мостов. Точные дубли составили 261 905 позиций, около 12,9% сырого списка. В отчёте счётчик `candidate_net_pad_pairs` равен **17 894**; одна такая пара может породить до 60 сырых позиций при включённых трёх кольцах и пяти сдвигах. Это исходные данные для генерации, а не 17 894 разных электрических связей.

Обычный вызов перебирает допустимые вращения (для большинства элементов Current ISO — 0/90/180/270), позиции по восьми сторонам/углам каждой поставленной детали и блока целиком, точные и округлённые координаты, позиции из правил, положения рядом с совпадающими падами и сигнальные мосты. У правила дополнительно создаются четыре направления около целевой точки, положения около корпуса и при наличии ограничения расстояния дополнительные кольца. Дубли удаляются по точной позе. Близкие, но разные точки остаются.

Beam имеет ширину 4 на одну последовательность уже поставленных компонентов и может сохранить до трёх разных последовательностей. Однако все кандидаты каждого расширения сначала проходят дешёвую проверку ограничений и частичную/полную оценку, затем отбираются лучшие. Ограничение ширины beam не ограничивает число предложенных позиций. Раннее отсечение полного score также происходит **после генерации**.

В парном проходе 12 примитивов дают 66 пар. Для каждой пары solver убирает обе детали и:

1. пробует обменять их центры с разрешёнными вращениями;
2. ставит их заново в обоих порядках: первый поиск оставляет до двух позиций, после каждой позиции второй ищет до двух;
3. оценивает полученные полные блоки, для четырёх лучших проверяет маршрутную добавку и принимает только улучшение.

Получается до шести запусков генератора для одной пары, **396 вызовов** на Current ISO. Они породили 646 332 точных позиций после локальной дедупликации, в среднем около **1 632 на вызов**. Позже 376 373 из них были отброшены по hard-рангу до дорогого score; 271 158 начали score и 232 167 дошли до конца. Поиск следующей пары уже видит изменения, принятые на предыдущих парах. Этот этап может освободить хорошее место одной детали перемещением другой и может дать более сильное изменение, чем простая перестановка центров.

Важно для реального запуска: текущий `blockPolicy` всё ещё задаёт `routingMetric: 'micro'`. Эти числа и сохранённые времена относятся к **принудительному geometric** для изолированного эксперимента. При micro число создаваемых позиций при тех же входах останется тем же, но цена оценки лучших вариантов может быть выше. Повторный запуск micro здесь не выполнялся.
