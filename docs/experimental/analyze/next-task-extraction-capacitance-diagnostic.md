# P7: локализация ошибки ёмкости перед следующим изменением сетки

2026-10-24. Продолжение P7 в `analyze-p7-extraction`, не новый анализатор.

## Решение ревью

Просмотрены §8.12 исходного задания, saved paired matrices, независимая
positive-range/common/differential норма в audit и PNG. Диагностика выполнена
корректно; готовность извлечения **не подтверждена**. Full ошибка XY/z controls
9.9235/9.9996%, differential 5.1978/5.3023% при независимом допуске 5%.
Малый residual и малое изменение соседних сеток не заменяют accuracy.
Production P7 не принимается и не коммитится как готовый анализатор.

## Задание

1. Переиспользовать сохранённые baseline D16, D8 и оба paired решения.
   Не повторять их solves. Вычислить распределение энергии для common и
   differential возбуждений по слоям и пространственным областям:
   внутренний gap, metal edge/sidewall, переход между близкой и дальней
   сеткой, внешний домен. Сумма регионов должна воспроизводить полную энергию
   с относительной ошибкой <=1e-8, с явно определённой обработкой нулевой энергии.
2. Оценить локальную недоразрешённость поля: flux jumps и/или residual в
   обоснованном обогащённом пространстве. Привести определение и размерности.
   Высокая энергия сама по себе НЕ означает высокую ошибку; не использовать
   алгебраический residual уже решённой системы как spatial error estimator.
   Показать вклад coarse transition regions, а не только metal edges.
3. Проверить, действительно ли paired controls обогащали нужные пространственные
   функции. Если новый mesh не вложен, не ссылаться на гарантированную
   монотонность энергии. Не терять source trace, foil thickness или far boundary.
4. Кратко сформулировать наиболее вероятную причину и один различающий контроль.
   До запуска записать меняемый параметр, неизменные условия, ожидаемый эффект,
   actual symbolic memory и критерий опровержения гипотезы.

После пунктов 1–4 разрешён **один** дополнительный диагностический solve:
прежние 25000 nodes / 3 million local terms / 512 MiB / 60 s, общий heavy slot
с Thermal/P6. Не обходить caps разбиением одного solve на подпроцессы. Если
обоснованный контроль не помещается — только proposal архитектору, без запуска.
Не делать цепочку новых refinement экспериментов без решения после результата.

## Границы и результат

- Не менять production solver/DSL, допуск 5%, физику, внешние references,
  исходные captures и существующие матрицы. Не начинать новый общий FEM/BEM engine.
- L conditioning/cost blockers остаются отдельными; этот блок их не закрывает.
- Сохранить script/input/output hashes, короткую таблицу гипотез/доказательств,
  численные региональные суммы и один понятный PNG. Проверить независимые
  full/common/differential ошибки, а не только сравнение с baseline.
- Итог: установленная причина с проверкой либо явно неразрешённый blocker
  и максимум два технических варианта следующего шага с оценкой затрат.
  Если точность по-прежнему не доказана, это не production acceptance.
- Обновить §8.13 исходного задания и handoff; не коммитить до родительского
  ревью. Не перечитывать всю историю и не повторять неизменные тесты.
  Сообщение родителю — готовый пакет или конкретный blocker, максимум 8 строк.
