# Analysis DSL: назначение и принятая основа

Обновлено **2026-10-20**. Документация будущего API, без реализации. [Контекст](README.md), [справочник](dsl-reference.md), [матрица](dsl-data-matrix.md), [решение B](dsl-responsibility-options.md).

Analysis DSL предназначен человеку и LLM: Rust выполняет ядро, обычный JavaScript/TypeScript описывает расчёт, проверку, подбор и графики. Предметные параметры всё равно требуют понимания поставленной задачи; специальный язык выражений поверх JS не вводится.

## Принято

- [Уточнения сценариев](dsl-scenario-decisions.md): differential — helper; CAN и аккумулятор без отдельных методов; автоматический подбор развязки отложен. Приняты channels([...]), timing(options) у результата, excitations и измерение наведённого напряжения через EMI. Отдельный DDR-интерфейс не нужен; [детали и аудит покрытия](dsl-readiness-review.md).
- analysis({ board }) хранит плату и отчёт. analysis() работает без платы.
- Каждый анализ получает собственный builder, физические дополнения и условия. Выполняется через run(); prepare необязателен.
- components — массив физических описаний с designator. Потребление и нагрев задаются в сценариях.
- stackup(...) возвращает описание слоёв для передачи в конкретный анализ; материалы и профили — явные ресурсы.
- Глобальные board/profiles/models доступны сценарию. Холодная/горячая среда, колебания и резкие изменения предусмотрены профилями.
- Конструкторы объектов ничего не вычисляют. Check/plot работают с результатами; sweep/solve/optimize сохраняют evaluate.
- Ручные поля заменяют автоматические целиком. Обязателен отчёт источников, ограничений и готовности.
- Check не является assert: pass/fail/unknown не прерывают код. Ошибка solver отличается от провала требования.

## Возможности

| Действие | Результат |
| --- | --- |
| Рассчитать самостоятельное сечение/цепь/тепловую сеть | Значения, единицы и границы модели без PCB |
| Рассчитать существующую PCB | Извлечение реальной геометрии и расчёт с заданными моделями/режимом |
| Проверить требования | Записи в отчёте с измерениями и неопределённостями |
| Подобрать параметр | Найденный допустимый вариант либо объяснение отсутствия результата |
| Сравнить режимы/варианты | Серии и карты с привязкой к условиям каждого запуска |
| Построить графики | Частота, время, TDR, eye, пространственные карты, исследования параметров |

Для PI согласовано автоматическое извлечение из PCB + модели компонентов + сценарий DSL. Для радиатора используется характеристика охлаждения, без CFD. Подробный full-wave по выбранной структуре задаётся явно; backend/материалы/возбуждения обязательны и не подменяются простым расчётом молча.

## Открыто

Принято равномерное распределение нагрузки по контактам выбранной сети и возврата GND с отдельными ручными токами на обеих сторонах. Обязательная семантическая детекция всех выводов не требуется. Распределение по площади остаётся кандидатом. Подробности — [компоненты](dsl-components-simple.md).

Также открыты полные ресурсные форматы, допустимая физика и точность методов, исполнение JS/TS, лимиты/прогресс/отмена, кэширование, формальные типы результатов и проверка полноты RoutingBoardV2. Перед реализацией нужен общий пересмотр плана. BER, механика, CFD и моделирование корпуса устройства/кабелей отложены. Статистический sweep не выдаётся за BER или подтверждённую вероятность.

Передача контекста из Routing DSL сейчас не проектируется. Сходство stackup-полей и объектных параметров не означает общий mutable context. Применение найденных изменений в CAD — отдельная операция, за пределами расчётного DSL.
