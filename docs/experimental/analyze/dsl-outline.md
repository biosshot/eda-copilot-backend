# Analysis DSL: очертания, без спецификации

Дата: **2026-10-19**. Статус: **рабочее обсуждение**. [Общий контекст](README.md).

## Назначение

Analysis DSL предназначен и для инженера, и для LLM. Пользователь, знакомый с JavaScript и документацией предметных функций, должен уметь читать и создавать расчётные сценарии. Rust выполняет расчётное ядро; TypeScript/JavaScript предоставляет пользовательский способ задания задач.

Наличие отдельного DSL согласовано как направление. Конкретная грамматика, API, имена функций, ограничения исполнения и организация модулей не утверждены. Ниже описаны возможности, а не существующие команды.

## Пользовательские действия

| Действие | Пример вопроса | Ожидаемый вид результата |
| --- | --- | --- |
| Рассчитать | Какой импеданс у линии с заданной геометрией? | Значение, единица, модель и ограничения |
| Проверить | Соответствует ли существующая линия требованию 50 Ом с заданным допуском? | Измерение и отклонение от требования |
| Подобрать | Какая ширина обеспечивает нужный импеданс при заданном stackup? | Допустимые параметры либо объяснение отсутствия решения |
| Рассчитать текущую плату | Какое напряжение получит каждый потребитель при заданной нагрузке? | Значения на выводах и пространственная карта |
| Изменять параметры | Что происходит при изменении зазора, температуры или нагрузки? | Серия расчётов, таблица и график |
| Сравнить | Как отличаются два варианта разводки или набора конденсаторов? | Сопоставимые результаты при указанных условиях |
| Построить график | Как выглядит Z(f), T(t) или зависимость Z0 от ширины? | Подписанные оси, единицы, легенда и исходные данные |

## Два равноправных способа задания модели

### Самостоятельный расчёт

Плата может отсутствовать. Пользователь описывает сечение линии, проводник, RLC-цепь, тепловую сеть или другую поддерживаемую модель. Это позволяет проектировать до появления PCB и изучать влияние параметров.

### Расчёт по проекту

Пользователь выбирает реальные объекты текущей платы и добавляет необходимые условия: источники, нагрузки, модели компонентов, частоты, температуры и прочее. Конкретный механизм получения платы пока не выбран.

Для PI согласован основной путь: **автоматическое извлечение из PCB + модели компонентов + сценарий в DSL**. Для радиатора сценарий задаёт характеристику охлаждения при выбранных условиях; движение воздуха не рассчитывается.

Рассматривается явное требование подробного full-wave расчёта выбранной линии/перехода или антенны через внешний решатель, например openEMS. Нужны область расчёта с существенным окружением, порты/возбуждение, материалы и частотный диапазон. При отсутствии решателя/данных нельзя незаметно подменять требуемый метод упрощённым. Синтаксис и способ интеграции пока не утверждены.

Требование необязательно для вычисления: можно рассчитать импеданс и построить график, не задавая pass/fail. Валидация — одно из применений расчётной модели.

## Примеры сценариев на естественном языке

Имена функций специально не фиксируются.

1. Описать микрополосковую линию → задать материалы и размеры → рассчитать импеданс и задержку → подобрать ширину под целевое значение → построить график чувствительности к толщине диэлектрика.
2. Выбрать питание и возвратную сеть платы → указать выводы источника и потребителей → рассчитать DC-падения и потери → проверить минимальное напряжение каждого потребителя → показать проблемные участки меди.
3. Описать тепловую сеть компонента и теплоотвода → задать мощности и температуру среды → рассчитать температуры → подобрать параметр теплоотвода в пределах применимости модели.
4. Описать PDN и модели конденсаторов → задать частотный диапазон → получить импеданс в точке потребителя → сравнить варианты развязки → проверить целевую характеристику.

## Связь с существующими DSL — открытый вопрос

Routing DSL уже содержит часть требований к геометрии, импедансу, matching и питанию. Analysis DSL должен уметь работать с такими требованиями, но способ совместимости пока не выбран.

Обсуждавшееся предложение: импортировать готовые требования, а условия расчёта задавать отдельно. Временное изменение цели для исследования не должно неявно изменять правила проекта. Не решено, будет ли это импорт, общий слой требований или другой механизм.

Новые анализы не должны ограничиваться тем, что умеет выразить Routing DSL. Фронты драйверов, модели нагрузок, теплоотвод и частотные исследования относятся к постановке анализа.

## Свойства для дальнейшего обсуждения

- Явные единицы и проверка размерностей; конкретная запись единиц не выбрана.
- Сохранение и повторное выполнение сценария, одинаково понятного человеку и агенту.
- Разделение физической модели, условий исследования и проверяемых требований.
- Указание неизвестных параметров и происхождения принятых приближений.
- Повторное использование результатов между расчётами, например потерь DC PI в thermal.
- Ограничения подбора: диапазоны, фиксированные параметры, целевая функция, несколько решений и отсутствие решения.
- Sweep, sensitivity, corners и Monte Carlo как разные режимы: перебор параметров не равен оценке статистической вероятности.
- Численные результаты должны оставаться доступными без графического интерфейса.
- Графики согласованного набора: зависимости по частоте, времени и параметрам, TDR, базовый eye diagram и пространственные карты там, где их поддерживает физическая модель. Smith chart остаётся предложением; BER и механика отложены.
- У пространственных карт должны быть слой, координаты, единицы и связь с рассчитанной версией платы.
- Пределы бюджета, отмена и прогресс длительных исследований.
- Подбор параметров и применение изменения к плате рассматриваются как разные действия.

Это предложения по качеству будущего DSL. Ни форма сериализации, ни конкретный графический движок, ни исполнение произвольного JavaScript этим документом не утверждены.
