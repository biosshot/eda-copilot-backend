# Компоненты и нагрузки Analysis DSL

Дата: **2026-10-20**. Только документация, без реализации. [Справочник](dsl-reference.md) — единая текущая форма API.

**Зафиксировано:** вариант B, независимые builders анализов, массив components с designator, физические модели отдельно от условий эксперимента, ручные поля без скрытого дополнения, отчёт происхождения и пригодности данных.

**Дополнительно согласовано:** для нагрузки компонента на выбранной сети ток по умолчанию распределяется поровну между её контактами; возврат через GND — также поровну. Ручные токи питания и возврата независимы. Допущения и фактические токи выводов обязательны в отчёте. Это принятое поведение будущего DSL, не работающая реализация. Распределение по площади площадок пока только кандидат для явного дополнительного режима.

## 1. Компоненты описывают физические свойства

```ts
const components = [
  ic({
    designator: "U1",
    ground: ["3", "4", "7"],
    supplies: { core: ["1", "2"], io: ["5"] },
  }),
  resistor({ designator: "R7", resistanceOhm: 1000 }),
  capacitor({ designator: "C3", capacitanceF: 10e-6, esrOhm: 0.02, eslH: 1e-9 }),
];

const a = analysis({ board });
const task = a.dc()
  .components(components)
  .stackup(profiles.stackups.project)
  .materials(models.materials.project)
  .sources(sources)
  .loads(loads)
  .temperatureC(25);
const preparation = await task.prepare();
const dc = await task.run();
```

sources/loads — заранее заданный сценарий. Массив не является полным BOM: отсутствующие в нём компоненты остаются в плате. Указываются только дополнения/замены. Повторный designator в одном массиве — ошибка. Конструкторы ic/resistor/capacitor/inductor описывают соответствующие модели; device({ designator, model, pins?, thermalNodes? }) связывает иной поддерживаемый ресурс. Они не создают детали в CAD.

В компоненте допустимы роли выводов, номиналы, модели и тепловые узлы. Потребление, waveform, мощность нагрева, среда и охлаждение принадлежат конкретному анализу. Даже постоянный ток 100 mA — условие работы, а не обязательное свойство корпуса.

Автоматическое распознавание R/C/L требует типа, номинала, числа/связности выводов и отсутствия противоречий. Префикса R/C или размера footprint недостаточно. Известная ёмкость не доказывает знание ESR/ESL. В текущем RoutingBoard полнота передачи этих метаданных ещё не подтверждена; адаптер надо перепроверить. Парсинг даташитов не входит в первоначальное требование.

## 2. Ручные значения и происхождение

Уточнение входа: [RoutingBoardV2](routing-board-v2-shape.md) предлагает optional `partUuid` (переиспользуемый PartUuid) и `value` экземпляра. Их отсутствие не делает плату невалидной. Подготовка разрешает параметры только компонентов, участвующих в выбранной физической модели, из доступного ресурса/снимка либо ручного `.components([...])`. Геометрия всей относящейся к задаче меди при этом сохраняется. Неизвестные обязательные параметры перечисляются в prepare; LLM/пользователь может явно их задать, библиотека и сеть для ручного пути не нужны. UUID не обещает наличие ESR/ESL/thermal model, а полный BOM параметров не является обязательным входом каждого анализа. Подтверждённое значение экземпляра важнее библиотечного номинала; противоречивые модели не смешиваются молча. Явные параметры DSL имеют приоритет над обоими источниками.

- Отсутствующее поле допускает получение из поддерживаемых CAD-данных/модели или разрешённого приближения; для простой нагрузки действуют правила выбора по сети ниже.
- Указанное поле используется ровно в заданном виде. ground: ["3"] не расширяется до ["3", "4", "7"].
- supplies: { core: ["1", "2"] } задаёт весь объект supplies; автоматически найденный домен io не добавляется.
- ground: [] — явный пустой список, а не просьба включить автоматику. Пустое значение может оказаться непригодным для выбранной задачи.
- Ground и supplies независимы. Число 0 известно; пропуск не равен нулю.
- Найденные кандидаты вне ручного списка записываются как warning. Если постановка разрешима, расчёт продолжается, а зависимые результаты имеют явно ограниченную пригодность.
- Несуществующие контакты, противоречивые подключения и неразрешимая постановка остаются ошибками подготовки.

Не требуется писать source: "manual" в каждом входе: наличие поля уже означает ручной ввод. В отчёте source записывается для фактического значения каждого поля, отдельно от ready/ready-with-assumptions/missing/not-needed.

.prepare() не решает задачу и показывает значения, происхождение, замены, кандидаты, конфликты и отсутствующие данные. .run() делает ту же подготовку автоматически. Обязательная неоднозначность блокирует численное решение; неопределённость ненужного этому анализу поля — нет. Допущение не превращает неизвестную величину в ноль.

## 3. Массовые условия и исключения

```ts
const loads = {
  rail: net("+3V3"),
  defaultCurrentA: 0.02,
  overrides: {
    U1: { currentA: 0.1 },
    U2: { currentA: 0.05 },
  },
};

const heat = await a.thermal()
  .components(thermalComponents)
  .stackup(profiles.stackups.project)
  .materials(models.materials.project)
  .heat({
    category: "ic",
    defaultPowerW: 0.05,
    overrides: { U1: { powerW: 0.4 } },
  })
  .environment(profiles.environments.hot)
  .cooling(profiles.cooling.project)
  .initialC(25)
  .time({ stopS: 600, sampleStepS: 1 })
  .run();
```

Форма defaults/overrides сохраняется. Здесь thermalComponents — предоставленный массив физических тепловых моделей, без powerW. Default заполняет только недостающее значение среди определённых потребителей выбранной группы. Это не назначение токов всем резисторам/конденсаторам и не удвоение мощности, уже полученной из электрического анализа. Известный режим модели и явный сценарный источник должны иметь однозначно выбранное владение нагрузкой; конфликт не разрешается суммированием.

Для агрегированной loads-формы действуют правила следующего раздела. Пример выше не утверждает, что экспорт уже позволяет автоматически распознать все типы потребителей. Несколько шин задаются раздельно; один полный ток микросхемы нельзя назначать каждому домену.

## 4. Принято: нагрузка компонента на сети

По умолчанию используется равномерное распределение. Семантическая классификация каждого вывода не обязательна: выбираются контакты указанного компонента на указанной сети. Это явно принятое упрощение нагрузки, а не достоверное распознавание внутреннего устройства микросхемы.

```ts
const loads = [{
  designator: "U1",
  rail: net("VCC"),
  currentA: 0.1,
  // Можно опустить: это принятые значения по умолчанию.
  return: net("GND"),
  distribution: "equal",
  returnDistribution: "equal",

  // Индивидуальные значения ВХОДЯТ в общий ток 0.1 A.
  pinCurrentsA: { "1": 0.04 },
  returnPinCurrentsA: { "7": 0.06 },
}];
```

pinCurrentsA задаёт ток, входящий в компонент через контакт питания; returnPinCurrentsA — ток, выходящий из компонента через возвратный контакт. В обоих словарях используются неотрицательные величины в амперах. Они не суммируются между собой как два потребления: каждая сторона отдельно должна дать общий ток нагрузки.

### Выбор контактов

- По умолчанию: все контакты данного designator на точной выбранной rail, а для возврата — на точной сети GND. Это не выбор всех площадок платы на сети.
- return можно переопределить другой сетью. Если точной сети GND нет, имя неоднозначно или подходящих контактов нет, подготовка сообщает ошибку; AGND/PGND и другие похожие имена не угадываются и не объединяются.
- Ручное физическое ground/supplies ограничивает выбор, не дополняется автоматически. Контакты обязаны реально принадлежать заданным сетям. При нескольких описанных доменах на одной rail необходимо явно указать domain; отсутствие нужного домена в вручную заданном supplies не восстанавливается автоматикой.
- Для конкретной нагрузки можно дополнительно задать pins: ["1", "2"] и returnPins: ["3", "7"]. Это полные списки выбранных контактов этой нагрузки, заменяющие выбор из физического описания с записью замены. Пустой список не включает автоматику. Противоречие подтверждённой модели подключения остаётся ошибкой.
- pinCurrentsA/returnPinCurrentsA уточняют значения внутри выбранного множества. Они сами не добавляют контакты и не сужают множество до перечисленных ключей. Ток 0 явно исключает отбор/возврат через выбранный контакт; неуказанные контакты получают остаток.
- Площадки на нескольких слоях не считаются несколькими выводами. Несколько разных физических площадок с одним номером требуют явного разрешения контактов; точная расширенная форма привязки к padId ещё подлежит формализации и не заменяется молчаливым выбором первого совпадения.

Например, при пяти контактах питания и 100 mA каждый получает 20 mA. Если один явно потребляет 40 mA, четыре остальных получают по 15 mA. При трёх контактах возврата, один из которых явно возвращает 60 mA, два остальных возвращают по 20 mA. Питание и возврат могут иметь разное число контактов.

Для КАЖДОЙ стороны отдельно:

```text
remaining = totalCurrent - sum(explicitPinCurrents)
currentOfEachUnspecifiedPin = remaining / countOfUnspecifiedPins
```

Отрицательный остаток, ключ вне выбранной группы и отсутствие контактов — ошибки подготовки. Если незаданных контактов не осталось, сумма ручных токов должна совпадать с total. Допуск сравнения должен соответствовать численной политике проекта и ещё требует формализации. Для нескольких шин одна и та же группа GND может возвращать сумму токов нескольких нагрузок: каждый домен учитывается один раз, без идеального замыкания площадок друг с другом.

Частичные токовые overrides не противоречат запрету дополнять ручные списки: список определяет допустимые контакты, а overrides задают значения в пределах списка. Нельзя скрыто расширить pins, чтобы распределить остаток.

### Рабочая точка и переходный режим

currentA задаёт рабочую точку. Если задан waveform нагрузки, он задаёт полный ток во времени. Равномерное распределение применяется к каждому моменту времени. Предлагаемое уточнение для динамических overrides: значения pinCurrentsA/returnPinCurrentsA допускают число или Waveform; число остаётся постоянным током, а не скрытым процентом суммарного. Во всём интервале токовые суммы должны оставаться допустимыми. Эта динамическая форма требует итоговой проверки; базовое правило DC уже согласовано.

### Отчёт

Показываются designator/rail/return, фактические контакты, полный ток, ручные значения, остаток и присвоенные автоматические токи. Для каждого значения различаются manual и derived-equal. Допущение «все выбранные контакты на сети считаются токовыми контактами этой нагрузки» записывается явно. Кандидаты вне ручного списка дают warning; известные противоречия роли вывода показываются и требуют уточнения, а не скрываются распределением.

Equal задаёт граничные токи, а не решает внутреннюю модель кристалла. Реальная медь между источником и этими контактами всё равно рассчитывается. Никакого идеального соединения всех GND/VCC-площадок таким распределением не добавляется.

## 5. Распределение по площади — кандидат, не автоматическое правило

Пользователь предложил учитывать размер площадки. Возможное явное расширение — distribution: "pad-area" и независимо returnDistribution: "pad-area". Ручные токи имеют тот же приоритет; остаток распределяется пропорционально весам только незаданных контактов:

```text
current_i = remaining * area_i / sum(area_of_unspecified_contacts)
```

Этот режим ещё не принят как готовая физическая модель. Нужно определить, какая площадь используется (контакт пайки, маска, медь, отверстия, дубликаты на слоях), и проверить доступность геометрии. Нельзя незаметно перейти к equal при неизвестной площади.

Большая площадка не доказывает большой электрический ток; маленькая — сигнальное назначение. Exposed pad может служить теплоотводу и иметь различное электрическое соединение внутри корпуса. Поэтому площадь допустима как явно выбранная эвристика для исследования, без обещания большей точности и без автоматической классификации роли. По умолчанию остаётся equal; подробная модель корпуса при необходимости заменяет приближение. См. [Analog Devices: exposed pads](https://www.analog.com/en/resources/design-notes/2022/07/16/08/51/exposed-pads-a-brief-introduction.html).

## 6. Границы этого приближения

- DC: задаёт сценарий и позволяет оценивать падение напряжения/потери; локальные плотности тока зависят от распределения. Equal не является гарантированным worst case.
- Thermal: потери меди можно передать в thermal с теми же допущениями. Тепловыделение микросхемы задаётся отдельно или получается из энергетически согласованной модели; V × I не всегда целиком остаётся теплом в корпусе.
- AC/transient PI: постоянного суммарного тока недостаточно. Нужны временной/малосигнальный режим, импедансы компонентов, возвраты, а для подробного результата — влияние корпуса и контактов. Распределённая упрощённая нагрузка возможна с указанной областью применимости.
- SI/EM: роли Tx/Rx, сигнальный путь, возвраты и возбуждения не заменяются общим током питания.

Отчёт перечисляет фактические контакты, ток каждого, правило распределения, возврат и область применимости. Это видимое приближение, а не скрытая успешная детекция. Check получает unknown, если неразрешённая неопределённость существенна для проверяемого утверждения; в рамках принятого приближения пригодные метрики остаются проверяемыми.

Основания для разделения моделей: [COMSOL: заданный суммарный ток и эквипотенциальная граница](https://www.comsol.com/support/learning-center/article/manually-implementing-a-boundary-terminal-condition-143492) — иное граничное условие, чем фиксированные равные токи; [Analog Devices: пути аналоговых/цифровых токов и корпусные соединения](https://www.analog.com/en/resources/analog-dialogue/articles/staying-well-grounded.html). Эти источники не утверждают точность предлагаемого equal-приближения для произвольной микросхемы.
