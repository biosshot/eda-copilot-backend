## Постановка вопроса

Пользователь предложил перейти от каталога анализов к обсуждению модели платы и рассмотреть Gerber как стандартизованный источник всей меди. Также предложено пока отложить 3D-модели. Ниже уточняется, какие данные действительно можно получить таким путём и какие решения ещё нужны.

## Что даёт Gerber

- Gerber описывает номинальную геометрию слоёв производственного экспорта. Это ценный источник уже сформированной меди с вырезами, зазорами и термобарьерами, если экспорт актуален и корректен.
- Утверждение «Gerber не сохраняет сети» верно не для всех вариантов: X2 поддерживает CAD-netlist и атрибуты компонентов/выводов. Но наличие этих атрибутов в конкретном экспорте не гарантировано. [Ucamco: отображение X2-метаданных](https://www.ucamco.com/en/news/ucamco-releases-version-2-8-of-the-reference-gerber-viewer).
- X3 добавляет компонентную информацию. Она не заменяет электрические и тепловые модели компонентов. [Ucamco: Gerber X3](https://www.ucamco.com/en/gerber/gerber-x3).
- Gerber Job передаёт производственные параметры, включая данные о материалах и толщине; допускаются частичные реализации. Поэтому наличие job-файла не означает полноту всех физических свойств для анализа. [Ucamco: Gerber Job](https://www.ucamco.com/en/gerber/gerber-job-file).

Практический вход из производства — набор файлов слоёв, контура, отверстий и доступных метаданных. Один файл медного слоя не является описанием всей платы. Изображения площадок по слоям недостаточны для определения проводящего ствола via, его металлизации и вертикального диапазона.

Стандартность формата не устраняет работу импортера: нужно корректно интерпретировать апертуры, макросы, полярности, регионы, дуги и преобразования. Растеризация для просмотра не должна незаметно становиться геометрической основой точного расчёта. Возможная аппроксимация кривых требует явного допуска.

## Предлагаемое разделение источника и расчётной модели

Предложение: принимать Gerber через импортёр и CAD через адаптер, приводя их к общей нормализованной модели. Расчётное ядро работает с этой моделью; ему не требуется знать синтаксис Gerber или SDK редактора.

Это ещё не выбор сериализации и не обещание двух импортёров в первой версии. Открыты три варианта старта: Gerber с дополнениями, прямой CAD-адаптер или оба пути.

| Часть описания | Что требуется обсудить |
| --- | --- |
| Геометрия платы | Контур, вырезы, медь по слоям, отверстия, вертикальные соединения; точность и правила контакта |
| Stackup и материалы | Порядок и толщины слоёв, необходимые электрические/тепловые свойства и их происхождение |
| Электрическая идентичность | Сети, компоненты, выводы, связь выводов с медью; неизвестная принадлежность должна оставаться неизвестной |
| Объектная привязка | Связь с исходными дорожками, площадками и полигонами для отчётов и исправлений; один объект CAD может соответствовать нескольким фрагментам расчётной геометрии |
| Полнота снимка | Версия/актуальность, отсутствующие слои, неподдержанные объекты и принятые приближения |

Источники, токи нагрузок, драйверы, временные стимулы, модели компонентов и условия охлаждения нужны анализу, но не обязаны быть частью самой платы. Их размещение обсуждается отдельно.

Нельзя автоматически смешивать Gerber одной ревизии с netlist или объектной картой другой. При гибридном входе необходимы проверка согласованности и явный выбор источника геометрии.

## Медь, объекты и связность

Предложение: физическую геометрию меди хранить независимо от разрешения её редактировать. Разделение router на fixed/editable не является физическим свойством проводника.

Для DC PI важна объединённая медь: пересечение дорожки и полигона не создаёт двойной толщины. Для длины, пути, локальной ширины и исправления полезны исходные дорожки и их идентификаторы. Поэтому сведение всего только к безымянным объединённым полигонам также может потерять нужную информацию.

Имя сети задаёт ожидаемую принадлежность. Оно не доказывает физическое соединение. Два островка с меткой GND остаются разорванными, а соприкосновение меди с метками разных сетей нельзя скрыть объединением «по net». Нужны отдельно электрическая принадлежность и геометрически установленная связность.

## Какие 3D-данные можно отложить

### Рабочая договорённость о компонентах от 2026-10-19

- На текущем этапе не получаем готовые 3D-модели компонентов из редактора CAD.
- Можно получать обозначения корпусов и строить по распознанным стандартным вариантам приближённые геометрические модели.
- Обозначение семейства может быть неоднозначным: для выбора шаблона могут потребоваться размеры, число выводов, шаг или уточнение варианта. Неизвестный вариант не считается достоверно восстановленной геометрией.
- Полученная модель является приближением внешней формы. Внутренняя структура корпуса, кристалл, leadframe, свойства материалов и тепловые пути из одного обозначения автоматически не определяются.
- Эта договорённость не выбирает единый формат, экспорт, контракт меди, структуру библиотеки шаблонов или численные методы. Пользователь отдельно уточнил, что экспорт и единый формат продолжаем обсуждать.

### Предложения о геометрии платы и окружения

Предложение: на старте описывать PCB слоями с толщиной и вертикальными соединениями — условно 2.5D — без обязательного импорта произвольных STEP/BREP-сборок.

| Данные | Значение для анализов |
| --- | --- |
| Толщина меди и диэлектриков, положения по Z | Уже нужны для сопротивления, импеданса, задержки и теплопередачи |
| Диапазон via, отверстие, металлизация, остаточный stub/backdrill при соответствующих анализах | Нужны для DC- и высокочастотных моделей переходов |
| Подробная внешняя STEP-модель каждого компонента | Не обязательна для большинства первых моделей; сама по себе не задаёт свойства материалов или внутреннюю структуру |
| Упрощённый корпус и тепловые контакты | Могут потребоваться для thermal; иногда достаточно компактной тепловой модели |
| Разъёмы, экраны, корпус устройства, радиаторы, кабели | Могут быть важны для RF/EMI и охлаждения; не ограничиваются механическими задачами |

Тепловые модели используют геометрию и граничные условия теплопередачи; электромагнитные — геометрию проводников, диэлектриков и окружения. Примеры профессиональных областей применения: [Ansys Icepak](https://www.ansys.com/content/ansysincprogram/en-us/home/products/electronics/ansys-icepak.html), [Ansys HFSS](https://ansys.synopsys.com/products/electronics/ansys-hfss).

Поэтому отложить импорт полных 3D-сборок возможно; исключить физическую геометрию по Z из модели платы — другое решение, несовместимое с рядом уже рассматриваемых расчётов.

## Что обсуждать следующим

1. Основу физической геометрии: сформированная медь по слоям и вертикальные соединения, с сохранением доступных объектов и привязок.
2. Первый способ получения этой геометрии и электрических данных: реальный экспорт Gerber либо прямой CAD-адаптер. Перед выбором полезно проверить фактическую полноту экспорта наших CAD.
3. Минимальное описание stackup, материалов и via для выбранных моделей SI/DC PI/thermal.
4. Представление сетей, выводов и неизвестной/противоречивой связности.
5. После этого — конкретные типы, обязательные поля, сериализацию и правила совместимости.

Первоначальная рекомендация ассистента рассматривала Gerber как один из источников общей модели. В последующем обсуждении основой выбран существующий `RoutingBoard`; необходимость Gerber-импортёра не утверждена. Развитие модели ведётся через обсуждение конкретных расширений, без создания ещё одного независимого описания платы.
