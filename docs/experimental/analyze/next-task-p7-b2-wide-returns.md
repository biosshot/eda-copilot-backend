# P7-B2: широкие возвратные проводники и выбор области

2026-10-31. Реализация разрешена. Родитель: p7-real-channel-closure-plan.md, B2–B4. R1/R2 приняты родительским ревью: 15/15 focused tests. B1 геометрия ранее принята в своих границах. A дал независимый малый coupled AC контроль, но не подтверждение полноразмерного канала.

## Цель

Устранить геометрическую причину, по которой любая широкая опора автоматически исключает однородный участок. Сохранять исходную медь и физический обход разрывов. Разделить геометрически допустимый кандидат сечения и окончательное электрическое разрешение его использования. Не просто удалить guard из run-corridors.ts:151.

## Перед работой и владение

Прочитать AGENTS.md, CHANGELOG, единый план, p7-b-geometry-results.md, p7-route-partition-results.md, текущие run-corridors.ts, board-channel-plan.ts, route-partition.ts и их tests. Переиспользовать capturedBoardGeometry, native board-section и существующие unions/intersections.

Владение: src/analyze/run-corridors.ts, src/analyze/board-channel-plan.ts; минимально необходимые изменения route-partition.ts; tests/analyze-run-corridors.test.ts, tests/analyze-board-channel-plan.test.ts и новый tests/analyze-wide-return-domain.test.ts; scripts/verify-p7-wide-return-domains.ts; docs/experimental/analyze/p7-b2-wide-return-results.md. Новые fixtures только tests/fixtures/analysis-p7-wide-return/. Не менять native, DSL, executor, общие старые fixtures, отчёт соседа, общий roadmap/CHANGELOG. Все накопленные изменения сохранять.

Сосед p7_c1_wide_sections владеет электрическим выбором ширины/поля. Передать ему компактное описание кандидата, source/island/layer mapping и исходную медь для расширения. Согласовать внутренний интерфейс сообщением до использования; не плодить параллельные геометрические типы. Нативные сборки выполняет только сосед при реальной необходимости.

## Реализация

1. Боковое продолжение классифицировать по реальной объединённой меди и принадлежности физическим островам: однородная продолжающаяся опора, значимый край/щель/ветвь/соединение/сосед, неподдержанная неоднородность. Имена GND/AGND/VCC ничего не соединяют. Решение не зависит от того, сколько CAD объектов описывают ту же медь.
2. По полным контурам и событиям определить интервалы, где кандидат сечения действительно однороден. Сохранить события отверстий, cutout, изменения материалов, пересечений и ветвей; нескольких удобных срезов недостаточно. Проводники нескольких линий, попавших в совместную область, не разделять на независимые single-line модели.
3. Исходную геометрию хранить целиком. Численную поперечную область строить как часть физических источников с явным описанием боковой границы, использованных/исключённых фрагментов и необходимых проверок расширения. Не брать весь огромный polygon только по одному пересечению и не выдавать обрезанную медь за физический край.
4. Через разрыв сохранить обход и подключение переходов; если локальное сечение не может их представить — направить неоднородность в joint-кандидат с конкретной причиной. Никаких идеальных соединений по net, искусственной земли или замалчивания пропавших ветвей.
5. Геометрические кандидаты сделать доступными соседнему C1 через существующий planner/audit с минимальным внутренним расширением. Пока электрическая пригодность бокового интерфейса не подтверждена, существующий рабочий executor не должен молча принимать такой кандидат. Не менять отказ на success только из-за успешной геометрии. Не запускать прежний механизм слияния всех return-only faces как доказательство уменьшения задачи.

## Приёмка

- Широкая однородная плоскость даёт непустые кандидаты section; диагностируется, какая физика/проверка ещё нужна для численного admission.
- Один polygon и его физически эквивалентное разбиение дают одинаковые интервалы/области/геометрическое решение с точностью принятой геометрии; source provenance может различаться.
- Отдельные tests: реальный конечный край, узкая щель, щель между прежними sample locations, обход вне первоначальной ширины, branch, stitching via, отдельные острова с одинаковым net, 0/45 градусов, два соседних сигнала. Значимые события/топология не исчезают.
- У полного исходного STM32 U5→J5 через существующий no-scope planner сохранены endpoints, D5/JP2 ветви, слои, return mapping. Таблица before/after: кандидаты и их длины, local/joint причины, число затронутых источников, время/RSS/private. Не обязательно все участки станут section.
- NanoScope4layer и ThunderF7226layer: геометрическая проверка тех же выбранных полных каналов, без тяжёлого магнитного расчёта. Изобразить исходную медь, выбранные области, разрывы/обходы, контакты; просмотреть графики.
- Focused TS tests. Typecheck/build согласовать с соседом. Исходные STM32 geometry guards не ослаблять. Геометрический успех не является EM или memory-acceptance P7.

## Ресурсы и завершение

Один существенный численный/геометрический run одновременно с соседом. Для геометрического corpus измерять, а не запускать весь joint solver. Не повторять неизменные известные отказы и успешные тяжёлые runs. Без новых dependencies, субагентов, коммитов, очистки чужих файлов. Итог — рабочие изменения кандидатов, tests, отчёт и handoff C1. После результата остановиться. Если для корректного admission нужен D, точно обозначить это, не подменять его отключением guards.
