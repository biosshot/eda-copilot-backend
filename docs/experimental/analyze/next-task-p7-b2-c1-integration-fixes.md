# P7 B2→C1: исправления ревью и реальное сечение STM32

2026-10-31. Пользователь разрешил продолжение одним агентом GPT-6.1-sol medium. Это продолжение B2/C1 по p7-real-channel-closure-plan.md, не новый solver и не переход к D/P8/P11. Предыдущие отдельные задания остаются контекстом; владение для этого продолжения объединено ниже.

## Обязательный результат

Исправить три замечания ревью и довести автоматический выбор хотя бы одного настоящего однородного участка полного выбранного канала STM32 до совместного извлечения C/C0/L и частотного отклика существующим board-section/polygon-section путём. Показать источник геометрии, физический возврат, портовое соответствие, реальную проверку границ и сетки, время и память. Малый лабораторный контроль остаётся regression/reference, но не заменяет этот результат.

Это приёмка участка и его внутренней интеграции. Полный канал с переходами, разрывами и распределёнными интерфейсами всё ещё требует D. Не обещать общую точность/экономию памяти STM32 по одному сечению.

## R1. Длина теряется в board adapter

В src/analyze/segmented-channel.ts, extractWideBoardSectionCoefficients, input.lengthMm присутствует только в physicalIdentity, но отсутствует в request.line. Native без lengthMm возвращает complete без network; selectSectionDomain затем отказывает из-за отсутствия network.

Передавать проверенную положительную конечную длину в реальный native request. Добавить regression через adapter, а не только helper. Положительный тест должен проверить network, полосу и зависимость отклика от заданной длины при неизменных погонных коэффициентах. Переиспользовать field cache; не повторять полевое решение только ради другой длины. Проверить отрицательные длины/NaN/отсутствие необходимых данных. Не ослаблять требование наличия отклика вместо исправления транспорта.

## R2. Настоящие уточнения вместо названий этапов

В src/analyze/section-domain.ts сейчас четыре одинаковых request с axis physical-width/physical-width/air-boundary/mesh дают coefficients-only с нулевыми errors. Воспроизводится даже с настоящим сохранённым report.

До численных вызовов валидировать фактические переходы геометрии и mesh:
- повтор идентичного request — reuse, но не доказательство расширения/уточнения;
- physical-width расширяет область включённой физической меди по исходным данным; не двигает сигналы, опору по высоте и не меняет материалы/контакты;
- air-boundary расширяет внешнюю область поля, сохраняя включённую медь;
- mesh действительно уточняет разрешение при той же физике и внешней области;
- изменения нескольких независимых параметров не засчитываются как отдельная оценка чувствительности каждого;
- при изменении топологии, набора значимых проводников/материалов или условий задачи прежние сертификаты не переиспользуются;
- сравнения должны относиться к принятой конфигурации: не сохранять успешную проверку из другой области после её несогласованного изменения.

Не доверять только caller physicalIdentity и строке axis. Использовать реальные contours/размеры/request и небольшой внутренний план. Не создавать универсальный язык описания уточнений. Не требовать лишних дорогих прогонов при корректной последовательности, но обосновать применимость сохранённых сравнений.

Tests: одинаковые requests под разными axis; сужение вместо расширения; укрупнение вместо уточнения; смещение reference; изменение dielectric contour при том же id/epsilon; одновременные изменения; корректный план и допустимый cache reuse. Зафиксировать <=2% sensitivity и прежние floors, не подгонять их по новому результату.

## R3. Конечная область B2 и её интеграция с C1

Сейчас proposeCorridors сначала расширяет inspected extent до всей платы. Любая удалённая неоднородность блокирует кандидат. На STM32/NanoScope/Thunder before=0 и after=0. Это не выполненная приёмка B2.

Сохранить полную исходную медь/связность, но проверять геометрическую однородность внутри конкретной конечной области-кандидата. Все границы, щели, отверстия, материалы и ветви ВНУТРИ проверяемой области должны учитываться полными contour-event checks, не редкими sample slices. Отдельно сохранять внешнюю геометрию, физические связи/обходы и условия, которые ограничивают локальную модель. Нельзя просто игнорировать всё за прямоугольником или превращать обрезанную плоскость в физический край.

Связать эту проверку с ограниченной последовательностью расширений C1: при каждой изменённой области заново проверять геометрическую применимость, возвращать конкретную причину, если в область вошли значимые события/соседи/изменился состав проводников. Выбор ширины и сечения автоматический по исходному каналу, stackup и меди. Пользовательский DSL не получает ручной scope, служебные прямоугольники/срезы формируются внутри.

Если имеется требующий совместного расчёта разрыв/обход, участок не объявляется однородным и остаётся local/joint. Геометрическая связность сама не доказывает электрическое отсутствие влияния удалённого пути. Принятый локальный C/L результат не разрешает присоединить distributed interfaces без D. Сохранить self/mutual matrices, source/island/layer/terminal identity; никакого объединения по имени GND.

Нужно довести обычный настоящий однородный участок STM32, а не обязательно каждый участок её полного канала. Не вырезать новую упрощённую плату и не менять исходные endpoints/ветви ради pass. Положительный результат обязан пройти именно board adapter из R1. Если автоматический выбор предлагает несколько вариантов, использовать один детерминированный критерий, записать причину выбора; не перебирать методы решателя.

## Приёмка

1. R1/R2 покрыты meaningful regressions, которые ломаются на нынешнем дефектном поведении.
2. На исходной STM32 U5→J5 появился геометрически пригодный участок с физическим возвратом и выполнен положительный coefficients-only расчёт через board adapter. Сохранены реальные origin/direction/length, source/region/island mapping и причина выбора; нет ручного подменного coupon вместо платы.
3. Измерены реальные width/air/mesh sensitivities, конечные совместные C/C0/L и complex response. Не называть это независимой точностью самой STM32. Не переносить ошибку малого эталона на неизвестную реальную геометрию.
4. Старый независимый малый контроль и A-guards не регрессируют. Использовать сохранённые hash-bound результаты, где numerical producer не изменён; при изменённом admission проверить настоящий план, а не только сохранённую надпись pass.
5. NanoScope и Thunder — повтор геометрического выбора после исправления с before/after и конкретными ограничениями. Не требуется полный их магнитный solve.
6. Сохранить отрицательные topology cases: узкая щель, удалённый обход возврата, bore/ветвь, физически разные острова с одним net, source subdivision и rotated case. Проверить независимость от CAD-разбиения меди.
7. Графики реального участка на исходной меди, ширин уточнения, контактов/возврата, C/L/response/sensitivity; открыть и проверить. Ресурсы: cold end-to-end board adapter, warm same-input, process-tree sampled RSS/private, число native calls/cache hits, этапы времени. Вычисление геометрии включать в wall; sampled peak обозначать честно.

## Выполнение и остановка

Один агент, один heavy run одновременно. CPU/F64. Использовать существующие cache/worker/supervisor; не держать все полные geometry/results уточнений без нужды, не добавлять новый глобальный cache. До run зафиксировать ограниченный план. Максимум диагностической попытки 300s/2GiB с host headroom; для малого участка назначить меньший разумный budget. Не повышать лимиты и не повторять unchanged failures автоматически. Не запускать большой магнитный STM32/полную батарею local-volume tests.

Focused tests + typecheck/build. Native rebuild не нужен, hash addon сохранить. Не создавать субагентов, не коммитить, не чистить чужие файлы. После выполнения — отчёт с командами/числами/ограничениями и остановка для ревью. Если положительный реальный участок не получен, результат неполный: назвать конкретный оставшийся blocker с входом и evidence, не объявлять лабораторный pass завершением задания.
