# Короткий маршрут P7 → P8/P11

Текущее поручение: [единая интеграция P6/P7, кэш и реальные DSL-сценарии](next-task-p6-p7-integration-cache.md). Пользователь принял уточнённую электрическую модель после проверки сходимости в 2366190; исторические 88,8% не являются текущим основанием блокировать интеграцию. Новую кампанию методов/уточнений не начинать. Ограничения проверки и исходные обязательства сохраняются.

Поручение пользователя: ускорить выбранный путь, получить сквозной P7/P6/DSL и перейти к следующим этапам. Один local direct sparse FEM; принятые P7a/P7b для линий сохраняются. 2ГиБ,300s холодного пользовательского сценария, физические наблюдаемые<=5%. Новые методы не исследовать. Этот документ уточняет порядок текущего single-method задания, не объявляет выполненными исходные обязательстваP7.

## 1. Разделить расчёт и проверочный стенд

Выделить prepare/extract, solve и developer verification. Добавить времена geometry, assembly, factorization, basis training, reduction, P6 и validation. Текущий train содержит4 полных training solve,17-frequency reduced response и до51 full validation solve. Полный validation остаётся обязательным стендом приёмки, но не запускается автоматически в пользовательском запросе. Отдельно публиковать cold user / full validation / warm / disk restore timings.

Параллельно воспроизвести конкретный opposite-drive1kHz отказ KVL1.24828e-7 против1e-8. Проверить scaling, residual computation и iterative refinement существующего решения. Исправить с регрессией; не заменять numerical guard на5% и не удалять этот случай из стенда.

## 2. Ограниченное ускорение CPU

В текущем direct пути magnetic factor/solve и sparse_potential явно используют faer Par::Seq. Исторический DenseField имеет1..4 column workers, но новый requested-RHS путь не получает от этого автоматического ускорения. Отдельный Node worker не означает многопоточный численный solver.

После измерения стадий использовать поддержанную установленной версией faer многопоточность factor/solve там, где она реально работает. Сравнить1 и до4 доступных CPU threads на одинаковом запросе и binary. Учесть workspace всех threads в общем2ГиБ; один bounded pool, без вложенного размножения потоков. Если конкретная sparse factorization фактически последовательна, не обещать ускорение и не менять семейство решателя ради него.

Переиспользовать factorization между RHS/частотами там, где оператор неизменен; пакетировать RHS поддержанными операциями. Не факторизовать одну и ту же матрицу повторно. Удалять только доказанно дублирующие подготовки. Выбор узких оптимизаций по stage timings, не новый перебор solver/сетки/полиномов.

## 3. Сквозная интеграция и дисковый кэш

Извлечение подключить к существующему worker и DSL: request определяет область, контакты, материалы и частоты/полосу. DC не вызывает AC extraction. Single-frequency не запускает полный sweep; необходимые дополнительные частоты подготовки reduced model допустимы и учитываются в cold time. Соседняя медь/реальный return сохраняются по физической необходимости, а не только по именам выбранных сетей.

В Rust worker удерживать prepared geometry/operators/factors по неизменяемому ключу. Диск v1: сериализуемая сокращённая модельP6, port/source mapping, recovery для заявленных токов/потерь, диапазон применимости, provenance и статус валидации. Не писать opaque factorization dump без поддержанного формата.

Ключ: канонический хеш физических данных платы + ROI/порты + stackup/materials/plating/температура при влиянии + настройки метода/точности/полосы + версия формата/ядра. Консервативно допустим full-board hash. Возбуждение/частоты относятся к ключу результата, если не меняют подготовленную модель; изменение условий вне её применимости требует пересчёта. Смена только a.plot/a.check не запускает extraction.

Переиспользовать подход PCB Layout: binary identity, атомарная запись, промах при несовместимости/повреждении. Добавить bounded disk eviction и контроль checksum/размеров/схемы; не грузить произвольный повреждённый объект как доверенную модель. Ошибка/незавершённая физическая валидация не превращаются в accepted cache entry. Проверки cold/warm/restart/hit/miss/corruption и изменённого stackup/port/board. При hit не выполнять полевую сборку и обучение заново; время восстановления измерить отдельно.

## 4. Приёмка и переход

Один реальный STM32 via+return сценарий через compiled worker/direct DSL с графиками; затем сохранённые TPS63060DSCR и BandAmp по применимым сценариям. На согласованных физических наблюдаемых независимый эталон и mesh/domain checks с общим бюджетом<=5%, абсолютные floors задать заранее. Полный17-frequency стенд и оба/противоположное возбуждение сохраняются отдельно от user runtime. Ordinary addon build, typecheck, P6/DSL и cache regressions обязательны.

P8 gate: проверенный multiport PDN resource, units/references/port mapping, валидный DC/AC диапазон и пригодная пассивная временная модель для заявленного transient. P11 gate: проверенные coupled lines/channels, delays/losses/returns, frequency coverage для сигнала, композиция с drivers/receivers. Low-frequency via PASS не разрешает произвольные USB/DDR/RF случаи. Составить отдельную матрицу supported/rejected/gap; не скрывать исходные обязательстваP7.

Как только соответствующие gates выполнены, можно переходить кP8/P11 в подтверждённой области, без дальнейшего улучшения точности сверх5% и без новой кампании оптимизации. ВесьP7 объявлять закрытым только по исходной матрице, иначе назвать принятую поставку и конкретные оставшиеся расширения. План сам не запускает агентов и не разрешает выполнять P8/P11 сейчас.
