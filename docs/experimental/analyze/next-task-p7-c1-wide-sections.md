# P7-C1: совместное сечение над широкой опорой

2026-10-31. Реализация разрешена. Родитель: p7-real-channel-closure-plan.md, начало C и электрическая часть B3. Выполняется параллельно геометрии B2; интеграция только после его handoff. Это ограниченное рабочее расширение существующего section path, не новый объёмный solver и не полное закрытие C/D/P7.

## Цель и владение

Переиспользовать native board-section/polygon-section, совместный C/C0/L solve и существующий cache. Реализовать внутренний выбор достаточной поперечной области для однородного участка с широкой физической опорой, с явной проверкой влияния границ. Не заменять совместное поле независимыми линиями или табличной формулой.

Прочитать AGENTS.md, CHANGELOG, единый план, отчёты A/B1, native extraction polygon_section.rs/board_section.rs и TS pipeline. Владение: новый небольшой src/analyze/section-domain.ts (только если нет уже подходящего helper), минимальное необходимое расширение src/analyze/segmented-channel.ts для использования проверенного helper; tests/analyze-section-domain.test.ts; scripts/verify-p7-wide-sections.ts; tests/fixtures/analysis-p7-wide-section/; docs/experimental/analyze/p7-c1-wide-section-results.md. Native менять только при доказанном недостатке существующего интерфейса, в extraction polygon_section.rs/board_section.rs и соответствующих tests; не трогать magnetic/geometry core. Не менять planner/run-corridors/route-partition: ими владеет p7_b2_wide_returns. Не менять public DSL, зависимости, общие старые fixtures/эталоны, общий roadmap/CHANGELOG.

## Порядок

1. До B2 handoff работать на реальной геометрии малого физического coupon с двумя сигналами и одной широкой конечной опорой. Зафиксировать порты, материалы, ширины, наблюдаемые, допуски и ресурсный план до численного результата. Прочитать готовый независимый stripline FD reference; не использовать его для несовпадающей геометрии.
2. Реализовать ограниченное расширение численной области из исходной меди. Сопоставлять одну и ту же задачу/порты/materials при расширении; отдельно отличать уточнение сетки, внешней границы поля и включённой ширины физического возврата. Сохранять все совместные матрицы и неизменную физическую идентификацию проводников. Изменение топологии/набора значимых проводников при расширении требует явной обработки или отказа, не сравнения разных задач как будто одной.
3. Использовать существующие cache/budgets/cancellation, последовательные refinements без удержания всех больших промежуточных данных. Небольшое заранее ограниченное число расширений, раннее завершение при выполнении criteria. Cache identity включает всю физическую геометрию, материалы и boundary policy; не только net/диаметр via. Не добавлять второй глобальный cache.
4. Проверять self/mutual C/L, modal impedance и complex response при неизменных портах. Численная/граничная чувствительность <=2% с заранее выбранными absolute floors. Независимая физическая ошибка плюс оценка неопределённости reference <=8%. Крупное сечение тем же solver — только перекрёстный numerical reference; нужно отдельное сопоставимое независимое вычисление/аналитический benchmark хотя бы для базового coupled случая. Не выдавать TEM velocity identity за проверку абсолютных C/L.
5. После handoff B2 извлечь реальные выбранные однородные участки STM32 из board, без ручного прямоугольника в пользовательском DSL. Подключить helper к реальному внутреннему пути получения section coefficients там, где это корректно; совместно с B2 определить границу между candidate и admission. Сохранить audit/почему принят/почему отклонён. Если общий канал пока не может использовать section из-за D, показать реальное получение совместных coefficients из board и явный integration blocker, не создавать мнимый complete full-channel.

## Физические ограничения, которые нельзя обойти

- Электрическая пригодность C/L сечения не доказывает, что обрезанный возврат имеет правильное DC сопротивление или распределение продольного тока. Нынешние 1/(sigma*w*t) и mu*t/(12*w) в board-channel-plan.ts зависят от ширины среза. Не включать широкую опору в старый полный RLC путь без соответствующего обоснования/проверки. Для этой задачи допустим честно ограниченный C/L/PEC результат; finite-R loss и distributed interfaces остаются явными условиями D.
- Не объединять независимые опоры по названию сети; несколько независимых опор/floating conditions, via fence, разрывы и неравномерные пути — следующие части C/D. Нужны отрицательные случаи, но их реализация сейчас не требуется.
- Не добавлять глобальную plane L/C поверх уже включённой энергии. P6 сам не восстанавливает пропущенные межблочные магнитные связи. Отсутствие боковой меди на рисунке не является условием отсутствия связи.
- Полоса определяется квазистатической применимостью и моделью потерь. Успешный PEC section на MHz не расширяет полосу реального lossy автоканала.

## Приёмка и отчёт

Рабочий переиспользуемый helper, реальные native polygon/board-section вызовы, meaningful tests для convergence/cache identity/неполных результатов/изменившейся топологии. Один positive coupled EM контроль с ненулевой взаимной связью, понятной независимой точностью и графиками; положительное извлечение на выбранных STM32 sections или конкретный доказанный blocker. Сохранять ограничения целого канала. Графики области/проводников, C/L и mutual response по ширине/ошибке; просмотреть.

Таблица: размеры входа/число неизвестных, solver/factor bytes если доступны, peak process-tree private/RSS, cold wall и этапы; same-input warm reuse. Сравнивать до/после на одной задаче. Нельзя объявить экономию whole-STM32 magnetic по времени малого section. Максимум одной диагностической попытки 300s/2GiB с headroom, малые cases должны иметь меньшие budgets. Один heavy run одновременно с B2; не повышать лимит и не повторять unchanged failure автоматически.

Ты владеешь сборками: штатная native:build только при native изменении, предупредить B2 о замене addon; зафиксировать новый hash и повторить необходимые regression checks. После TS изменений — focused tests и общие typecheck/build, сообщить соседу. Без субагентов, коммитов, нового DSL/внешнего обязательного solver/F32/GPU. Сохранить чужую работу. По завершении остановиться для родительского ревью; не переходить к D/P8/P11 самостоятельно.
