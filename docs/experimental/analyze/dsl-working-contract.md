# Рабочий контракт DSL: SI, модели и измерения

Дата: **2026-10-20**. **Базовый пользовательский DSL согласован; реализации нет.** Подтверждены drivers/receivers, привязки port/ports, timing у результата, простые модели через a.model и операции измерений. Предложение отдельного механизма контроля границ/двойного учёта моделей отклонено и исключено. Общая основа — [решения по сценариям](dsl-scenario-decisions.md).

## 1. Одна форма активности SI

Выбор — `.channels([...])` либо альтернативный `.network(network)`. Источники активности — `.drivers([...])`, электрические входы — `.receivers([...])`. `stimulus` находится у конкретного driver. Отдельные setters transmitter/receiver/stimulus/aggressors исключены. Для соседней активной линии добавляются её канал, driver и receiver; существенная пассивная медь не исчезает при отсутствии driver. Требуемые окончания/модели остаются явными.

```ts
const signal = await a.si()
  .channels([dataChannel, neighbourChannel])
  .stackup(projectStackup)
  .materials(materials)
  .drivers([
    { port: dataTx, model: gpioOutput, stimulus: dataPattern },
    { port: neighbourTx, model: gpioOutput, stimulus: neighbourPattern },
  ])
  .receivers([
    { port: dataRx, model: digitalInput },
    { port: neighbourRx, model: digitalInput },
  ])
  .time(simulationTime)
  .run();
```

Все внешние переменные здесь — предоставленные сценарием порты/модели/условия. Новая форма не предполагает новый SI-solver.

### dataPattern — обычное описание переключений

Это имя пользовательской переменной, не встроенная функция или модель компонента. Она передаётся в driver.stimulus:

```ts
const dataPattern = {
  kind: "bits",
  bits: "01011010",
  bitRateBps: 10e6,
  riseS: 2e-9,
  fallS: 2e-9,
  repeatCount: 1,
};
const drivers = [{
  port: dataTx,
  model: gpioOutput,
  stimulus: dataPattern,
}];
```

Это восемь бит по 100 ns, всего 800 ns на одну передачу. riseS/fallS задают фронты источника в принятой простой модели, не обещают такую же форму у нагруженного приёмника. Модель driver задаёт уровни 0/1 и электрическое поведение. Одинаковые соседние биты не создают переключения. Повторение увеличивает длительность последовательности; это не период частоты тактирования.

Также предусмотрены `kind: "prbs"` с order/seed/bits/bitRateBps/riseS/fallS для воспроизводимой тестовой последовательности и `kind: "waveform", voltageV: Waveform` для заданной временной формы. Паттерн не симулирует протокол USB/CAN/DDR; он задаёт электрическую активность.

## 2. Привязка: один порт или именованные порты модели

`port` — сокращение для модели с единственным электрическим портом. `a.port({ positive, negative })` привязывает два физических контакта, включая возврат. `ports` — карта имён портов многопортовой модели к port handles. Одновременно port и ports запрещены.

```ts
const txP = a.port({ positive: pad("U1", "10"), negative: pad("U1", "4") });
const txN = a.port({ positive: pad("U1", "11"), negative: pad("U1", "4") });
const rxP = a.port({ positive: pad("U2", "20"), negative: pad("U2", "2") });
const rxN = a.port({ positive: pad("U2", "21"), negative: pad("U2", "2") });

const pair = a.differential({
  positive: a.channel({ from: txP, to: rxP }),
  negative: a.channel({ from: txN, to: rxN }),
});

const drivers = [{
  ports: { positive: txP, negative: txN },
  model: models.electrical.differentialOutput,
  stimulus: dataPattern,
}];
const receivers = [{
  ports: { positive: rxP, negative: rxN },
  model: models.electrical.differentialInput,
}];
```

Номера условные. Ресурсы в примере объявляют порты с именами positive/negative и поддерживают общий reference. Имена карты соответствуют схеме конкретной модели, а не произвольным догадкам DSL. Такой mapping не объединяет геометрические участки разных GND-площадок в идеальную точку.

В модели с отдельным питающим портом он также сопоставляется явно. Модель с фиксированными уровнями не приобретает зависимость от PI автоматически. Связи питания, общий режим и допустимые references задаются схемой ресурса; отсутствующий обязательный порт или несовместимая привязка — ошибка подготовки.

Для network-resource сохраняется существующий a.network({ model, ports }): там карта именует внешние порты ресурса, а не привязывает его к PCB. Отличие зафиксировано явно: например { input: "port1", output: "port2" } создаёт handles для последующего a.connect. Компонентные pins и model ports — разные уровни, не взаимозаменяемые названия.

Для измерения пары используются два исходных порта и differentialVoltage либо отдельный измерительный a.port между P и N; измерительный порт не заменяет многопортовую модель общего режима драйвера.

## 3. Простые модели задаются параметрами

Используем уже предусмотренный a.model, а не дополнительные фабрики для каждого интерфейса. Ресурс из models и локальный ModelRef используются одинаково. Простая модель имеет явно ограниченный смысл, не получает неуказанные сложные свойства автоматически.

```ts
const gpioOutput = a.model({
  kind: "linear-driver",
  lowV: 0,
  highV: 3.3,
  outputResistanceOhm: 25,
});

const digitalInput = a.model({
  kind: "rc-input",
  capacitanceF: 5e-12,
});

const mosfetThermal = a.model({
  kind: "thermal-network",
  nodes: [
    { id: "junction", heatCapacityJPerK: 0.02 },
    { id: "case", heatCapacityJPerK: 0.2 },
  ],
  links: [
    { from: "junction", to: "case", resistanceKPerW: 2 },
  ],
});
```

Числа учебные, не модель реального MOSFET/GPIO. Эти виды — кандидаты стартовых параметрических моделей. linear-driver: управляемый источник с фиксированными low/high и одним линейным последовательным сопротивлением. Временная последовательность и фронты задаются stimulus; это не гарантированный фронт на нагруженной площадке. При waveform фактический вход/выход определяется схемой модели, нельзя одновременно задавать конфликтующие способы формирования фронта.

rc-input: ёмкость между контактами порта; необязательный resistanceOhm добавляет параллельное сопротивление. Пропуск resistanceOhm по определению этого вида означает отсутствие резистора, а не неизвестное конечное сопротивление. Защитные диоды/паразитики корпуса не добавляются молча. Пороги логики задаются в измерении, не являются ёмкостью/сопротивлением.

thermal-network описывает только внутренние узлы и связи компонента. Мощность, охлаждение, начальная температура и среда — в thermal-сценарии. Внешние тепловые связи явно подключаются к именованным узлам; один и тот же путь не включают повторно в model и cooling. Параметры не определяются по имени корпуса.

Модельные объекты проверяются по схеме kind; неизвестный kind/поле или невозможные параметры дают диагностику до расчёта. Поддержка IBIS, Touchstone и других файловых форматов — отдельная матрица реализации; произвольный файл нельзя считать поддержанным по одному его имени.

## 4. timing у результата: два измерения одной операцией

Две задачи имеют разные параметры, поэтому используем один метод с явным kind. Повторного физического расчёта нет.

### sampling: запас до и после выборки

```ts
const timing = signal.timing({
  kind: "sampling",
  data: dataInputs.map(port => ({ port, lowV: 0.8, highV: 2.0 })),
  clock: {
    port: clockInput,
    thresholdV: 1.65,
    edges: "rising",
    sampleOffsetS: 0,
  },
  window: { startS: 100e-9, stopS: 800e-9 },
});

a.check({ name: "Setup", actual: timing.setup.min(), min: 5e-9, unit: "s" });
a.check({ name: "Hold", actual: timing.hold.min(), min: 2e-9, unit: "s" });
```

Все числа иллюстративны, не требования DDR/USB. dataInputs — обычный массив измерительных портов, не модели приёмников. lowV < highV: напряжение <= lowV считается допустимым нулём, >= highV — единицей, между ними — неопределённым уровнем.

Момент выборки — выбранное пересечение clock.thresholdV плюс sampleOffsetS. edges: rising/falling/both. Смещение — настройка сценария, не автоматически вычисленное обучение приёмника. Дифференциальный clock измеряется портом между двумя сигнальными контактами, thresholdV задаётся в этих единицах.

Для каждой выборки измеряется непрерывный интервал сохранения того же допустимого логического состояния вокруг неё: часть до — setup, после — hold. Выход из допустимого диапазона из-за звона разрывает интервал. Если в момент выборки уровень неопределён, sample помечается invalid, измеренный запас принимается 0 с диагностикой; при полном покрытии требование положительного запаса проваливается. Это не доказательство правильности переданного бита: сравнение с ожидаемыми данными — отдельная задача.

Нет clock-фронтов, нет данных или недостаточно разрешения — unavailable, не успешный check. Пересечения clock не отбрасываются/не объединяются скрыто; дополнительные фронты входят в перечень samples. Если интервал стабильности упирается в границу доступного наблюдения, точная длительность неизвестна: хранится нижняя граница с диагностикой, а обычный exact-агрегат остаётся unavailable. Интервал window выбирает события анализа; данные вне window не используются для скрытого расширения измерения.

Результат содержит samples (момент, линия, состояние, setup/hold, validity), общие setup/hold для редукции и diagnostics. min не скрывает неизвестные строки. Пороги и интерполяция пересечений видны в inputs/diagnostics.

### propagation: задержка и разброс прихода

```ts
const arrival = signal.timing({
  kind: "propagation",
  paths: [
    { from: data0Output, to: data0Input, sourceThresholdV: 1.65, destinationThresholdV: 1.65 },
    { from: data1Output, to: data1Input, sourceThresholdV: 1.65, destinationThresholdV: 1.65 },
  ],
  edges: "rising",
  maxDelayS: 10e-9,
  window: { startS: 100e-9, stopS: 800e-9 },
});
```

Измерение from/to порта — напряжение относительно его reference. Для каждого исходного события ищется соответствующее пересечение того же направления на приёмнике в пределах maxDelayS. Если кандидатов несколько, окно перекрывается со следующим запуском, данных недостаточно или соответствие не доказано, результат unavailable с диагностикой; не выбирается произвольный первый фронт.

delay — время приёма минус время запуска по заданным порогам. Skew получаем только по общей группе соответствующих исходных событий: одинаковая последовательность/seed и индекс события, сохранённые в stimulus-метаданных, с учётом заданных задержек запуска. Для произвольных несвязанных waveform без общей идентичности событий skew unavailable; отдельно измеримые delays сохраняются. Skew — разброс фактических времён приёма группы; разброс delays отражается отдельно как delaySpread, чтобы не скрыть рассинхронизацию отправителей.

Результат содержит события/пути, delay, skew, delaySpread и diagnostics. Это сохраняет одну операцию timing, не смешивая измерение прохождения фронта с проверкой окна выборки.

## 5. Согласованные результаты и несколько наблюдений

Accessor возвращает объект величины/серии с unit, validity, diagnostics, а не голое число. Пользовательские check и plot принимают его напрямую. Непригодные значения не становятся 0.

| Операция | Смысл |
| --- | --- |
| min(), max() | Редукция действительных значений, с сохранением единиц и пропусков |
| abs() | Модуль действительной величины/серии, полезен для пика помехи |
| real(), imaginary(), magnitude(), phaseDeg() | Явная работа с комплексными данными |
| at({ timeS }) / at({ frequencyHz }) | Значение по подписанной оси; без неявной экстраполяции |
| voltage(port) | Напряжение между контактами порта; ось определяется выполненным расчётом |

Скалярные min/max допустимы как тождественная редукция для совместимости примеров. Комплексные min/max требуют предварительного real/magnitude. Неподдержанная операция даёт unavailable и диагностику по существующему правилу результатов. Проверки учитывают единицы и не игнорируют неизвестную часть данных. Пустая серия не даёт проходящую проверку.

Для EMI сохраняем имя `.measurement(...)`, принимая одно описание либо массив описаний:

```ts
const measurements = [
  { port: adcInput, quantity: "voltage" },
  { port: sensorSupply, quantity: "voltage" },
];
// ... a.emi().measurement(measurements).time(observationTime).run()
```

Простое напряжение порта не добавляет нагрузку. Поле model в описании физической измерительной сети, напротив, задаёт её реальную нагрузку. Совместные измерения с физическими приборами означают их одновременное подключение; для разных экспериментальных подключений нужны разные запуски. Для простых наблюдений voltage(port) остаётся однозначным; для разных детекторов/полос вводится явный id и result.measurement(id). voltage(port) означает исходную временную/частотную серию, не нормативный detector output.

complete/partial описывают доступность результата, а не pass/fail требований. Заданный применимый упрощённый model не делает каждый check автоматически unknown: допущение отражается, а проверка действительна в его границах. Существенные неизвестные данные дают unknown. Ошибка постановки отклоняет run; check(pass/fail/unknown) не останавливает код.

## Статус после этой редакции

Пункты о привязках, timing, a.model и измерениях подтверждены пользователем. Отдельный механизм referencePlane/coverage, контроля перекрытий и замены частей моделей не вводится по решению пользователя; это не открытый блокер DSL. Ранее согласованные channels/network/connect и обычная проверка аргументов сохраняются.

Базовый DSL закрыт как рабочая договорённость. Формальные типы, поддержка классов моделей, численные методы и проверка точности остаются задачами реализации. Изменения DSL возможны при обнаружении конкретных ограничений, без предварительного расширения на редкие случаи.
