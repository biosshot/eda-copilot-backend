# Следующее задание: физическая геометрия меди и связность

Статус: задание после приёмки analysis worker, 2026-10-21. Реализовать один законченный геометрический блок и вернуть на проверку. Это часть P4, а не завершение всего P4 и не DC solver.

## Результат

Для RoutingBoardV2 получить фактические медные области по слоям, отверстия, физические контакты и межслойные связи. Показать, какие участки соединены, где одна заявленная сеть распадается на островки и где физически соприкасаются разные сети. Сохранить связь результата с исходными объектами. Получить проверяемый отчёт и геометрический снимок для каждого из восьми fixtures через существующий process runtime и launcher.

Имя сети — атрибут исходной меди, **не команда объединить её электрически**. Граф связности не означает нулевое сопротивление области: распределение потенциала будет рассчитывать последующий DC solver.

## 1. Границы и модули

- Основная работа в `native/analyze`: геометрия и topology используют существующий `model::Board`, не читают DTO/EasyEDA напрямую. Сохранить `import_json` и его прежний отчёт без изменения семантики.
- Разделить преобразование примитивов, операции над областями, пространственный поиск и построение связности. Достаточно обычных модулей внутри текущего crate; не создавать новую общую библиотеку или универсальный CAD framework.
- Политика F64 относится к координатам/вычислениям анализатора. Не использовать F32/FTZ packer или его увеличенные контуры препятствий как физическую медь. Составные точные предикаты либо контролируемое целочисленное представление внутри геометрической библиотеки допустимы только с явным описанием точности/масштаба, без изменения внешней F64-политики.
- До выбора geometry dependency проверить существующие реализации, первичную документацию, лицензию, target portability и отсутствие внешнего executable/runtime. Разрешена минимальная необходимая библиотека boolean/predicates; не писать сложный polygon clipping с нуля без причины. Версии/features и ограничения записать. Не подключать faer, FFT или spade до задачи, которая их использует; meshing здесь не нужен.

## 2. Что считать медью

Поддержать все текущие формы `model::PadShape`, tracks fixed+editable, vias и доступные CAD fills обоих видов зон.

| Объект | Обязательное поведение |
| --- | --- |
| Track | Полоса заданной ширины вдоль polyline; корректные caps/joins, изгибы, замкнутые пути и соединение дорожек разных ширин. Не растягивать BBOX вместо построения полосы. Семантику caps/joins сверить с текущим экспортёром/сохранёнными native примерами, документировать. |
| Pad | Circle, rect, round-rect, oval, polygon с holes; использовать `layer_shapes` при наличии. Локальную форму преобразовать по pad.at/rotation один раз. Не применять повторно component transform или зеркалирование bottom. |
| Via | Медные lands и отверстие в подтверждённом span; связь через металлизированный barrel. Through и blind/buried не смешивать. Никаких связей со слоями за пределами span. |
| Pour / Fill | Использовать `fills` с `Available.polygons`; boundary и refill rules не являются существующей медью. Available с пустым массивом — пустая медь. Нельзя одновременно складывать CAD fill с предполагаемой сплошной зоной. |
| Неизвестная сеть | Сохранить физическую геометрию и контакт с известной сетью, не отбрасывать и не присваивать ей сеть автоматически. |

Кольца `outer/holes` описывают материал и отсутствие материала. Hole полигона не означает самостоятельный drill. Раздельные островки не соединяются через внешний контур зоны. Перекрывающаяся медь учитывается по площади один раз, но сохраняется provenance всех участвовавших объектов, включая разные сети.

Повторяющаяся замыкающая вершина и нулевые последовательные рёбра могут быть удалены как эквивалентная нормализация с тестом. Самопересечения, holes вне outer и иная недопустимая топология не должны молча «исправляться» библиотекой в произвольную область. Проверить их до использования либо диагностировать результат с ясной причиной отказа. Не удалять маленькие островки/зазоры ради удобства алгоритма.

## 3. Отверстия, границы и преобразования

- Построить round/slot drills с pad-local offset и rotation; отдельно поддержать independent drills. Проверить значение slot length по контракту и экспортёру, не угадывать длину центрального отрезка.
- Учитывать board outline и cutouts. Сохранять различие выреза, NPTH, plated hole и keepout. Keepout ограничивает проектирование, но сам по себе не удаляет уже существующую медь.
- Drill удаляет медь в области отверстия на затронутых слоях, даже когда эта медь принадлежит соседнему объекту. Для blind/buried применим только подтверждённый span; не превращать его в сквозной вырез.
- Для pad holes и independent holes без явно переданного span сначала проверить документированную семантику экспортёра. Если сквозной характер не подтверждён, выдать limitation вместо придуманного span. Independent plated drill не имеет автоматически известной сети или lands.
- Металлизация связывает реально контактирующие области на соответствующих слоях; круглый пустой центр отверстия проводником не становится. NPTH не создаёт вертикальных связей. Отсутствие толщины металлизации мешает расчёту сопротивления, но само по себе не отменяет подтверждённую топологическую связь.
- Выход меди за край платы выявлять явно. Не скрывать его автоматическим исправлением исходника. Для производной геометрии документировать, учитывается ли подтверждённое пересечение с материалом платы; неоднозначные edge/castellated случаи отмечать как ограничение. Не объявлять их корректными по одной картинке.

## 4. Точность и контакты

Не вводить новый тип дуги. Входные polyline/polygon уже аппроксимированы экспортёром. Внутренние круги, овалы, скругления и strokes переводятся в области с **ограничением максимального отклонения границы в mm**, а не фиксированным числом сегментов для любой окружности.

Задать и документировать внутренние параметры точности, ограничение числа генерируемых вершин и диапазон координат. Начальная целевая погрешность собственной аппроксимации — 0.001 mm, с возможностью уточнения. Это не допуск на электрическое соединение и не обещание точности уже экспортированных CAD полигонов. При превышении ресурса сообщать об ошибке/ограничении, а не тайно увеличивать погрешность.

Положительный зазор нельзя замыкать условием `distance < epsilon`. Различать перекрытие по площади, общую границу ненулевой длины, точечное касание и неопределённость в пределах ошибки представления. Точечное касание либо неразрешимый малый контакт должны иметь отдельную диагностику и не превращаться в надёжный путь для будущего conduction solver. Геометрический контакт и допустимость будущей FEM-модели — разные свойства.

Для расстояний/контактов сначала отбирать кандидатов пространственным индексом либо sweep по bounding boxes, затем применять точный для выбранного представления narrow phase. Нельзя ограничиться пересечением BBOX. Не требовать полного all-pairs обхода всей платы. На купонах, близких к порогу точности, проверять уточнение аппроксимации и честную диагностику неопределённости.

## 5. Результат связности

- Области и компоненты связности получают стабильные идентификаторы внутри результата, ссылки на слой, исходные пути/IDs, pad/component references и native fill fragment IDs, когда они есть.
- Сохранять список исходных net labels. Если физический путь объединяет разные известные сети, выдавать finding о коротком с участвующими объектами. Не разделять их искусственно по net и не выбирать победившее имя.
- Для одной net перечислять физически отдельные компоненты. Это диагностический факт; без схемного намерения не каждый островок следует объявлять ошибкой платы.
- Учитывать связь pad ↔ track ↔ fill ↔ via по реальной геометрии, включая промежуточные слои и неизвестную net. `connectedPadIds` — свидетельство CAD, не замена физического контакта; противоречие должно быть видно.
- Не соединять выводы компонента друг с другом через имя корпуса, номер компонента, resistor value или electrical model. На этом этапе считается только медь PCB и подтверждённая металлизация.
- `disable_routing` и fixed/editable не меняют существующую физическую проводимость.

## 6. Полнота и диагностический отчёт

Разделить невозможность подготовки, неполноту исходной геометрии и выявленный дефект самой платы. Реальное short не должно уничтожать геометрический снимок; его нужно показать и локализовать.

Минимальный отчёт: статус подготовки (`complete` / `partial` / `invalid`), диагностика с code/path/source ID, статистика по слоям и источникам, площади объединённой меди, островки, контакты/вертикальные связи и findings. Отдельно сохранять статус/freshness CAD fills. `complete` относится к обработке подтверждённого геометрического входа и не означает готовность DC либо доказанное совпадение всей платы с CAD.

Missing/failed/unsupported fill не заменять boundary и не «забывать» в отчёте; известные области можно показать с `partial`. Stale/unknown freshness сохранять и явно ограничивать вывод о текущем состоянии CAD. Отсутствующий stackup не мешает чисто планарной геометрии/топологии, но не разрешает придумывать толщины, материалы или сопротивление via.

Невалидную геометрию нельзя передавать дальше как обычную подготовленную плату. Если возвращается частичный снимок, перечислить исключённые объекты и не выдавать его за полную модель. Старый import report и его `geometry_not_prepared` не переписывать: новый preparation report отдельно объясняет выполненный этап и оставшиеся ограничения.

## 7. Сквозная интеграция

Добавить ровно одну внутреннюю операцию подготовки геометрии к общему addon и `AnalysisProblem`, например `prepareAnalysisGeometry` / `kind: 'prepare-geometry'`. Принимается V2 JSON и небольшие явные настройки собственной геометрической точности. Исходная `import-board` операция и её возвращаемый тип остаются прежними; результаты двух операций должны быть типобезопасно различимы. Не превращать всё в `any` или общий нетипизированный JSON.

Через process worker возвращать сериализуемый геометрический снимок/отчёт, не весь внутренний `model::Board`. Тяжёлые данные готовятся в Rust; TypeScript только запускает и сохраняет. Сохранить отмену, deadline и dispose, не дублировать scheduler. Декларации новой native-операции принадлежат `native/analyze`, host их агрегирует.

Добавить `geometry.ts` для восьми плат через общий helper и существующий `test:pcb-analyze`. Каждый запуск сохраняет `report.json` и пригодную для независимого просмотра геометрию по слоям: JSON плюс простой SVG overlay с outline, медью, отверстиями и выделенными findings. Сохранить единицы, ориентацию Y-down и исходные IDs. Это отладочные артефакты, не новый PCB Preview/UI.

При `invalid` сценарий завершается ненулевым кодом; `partial` печатается явно и сохраняет все ограничения. Short findings сохраняются независимо от успешности геометрической операции. Не ослаблять проверки исходных fixture hashes; не менять платы ради зелёных тестов.

## 8. Приёмка

1. **Аналитические купоны:** прямоугольник, круг/кольцо, capsule/oval, round-rect, полоса с caps, две перекрывающиеся полосы и polygon с отверстиями. Ожидаемые площади/границы получают независимо от production-алгоритма. Допуск обосновать погрешностью границы; проверить уменьшение ошибки при уточнении. Площадь пересечений не учитывается дважды.
2. **Топология:** разрыв одной net; геометрический short разных nets; соединение через unknown net; BBOX overlap без контакта; положительный малый зазор; общая граница; точечное касание; узкая перемычка; островок внутри отверстия; malformed outer/holes. В тестах заданы ожидаемые области/связи, а не только snapshot сегодняшнего вывода.
3. **Слои и сверление:** through, blind и buried spans на четырёх слоях; NPTH; plated pad; offset/rotated slot; различающиеся layer shapes; неполные сведения independent plated drill. Via не касается слоёв за span; drill не оставляет ложного контакта через пустой центр.
4. **Преобразования:** bottom pad без повторного mirror, 90° и произвольный поворот, перенос всей постановки и перестановка входных объектов. Состав физических связей и площади сохраняются в обоснованном допуске; provenance остаётся корректным. IDs результата не должны зависеть от недетерминированного порядка обхода hash map.
5. **Зоны:** Pour/Fill, несколько islands/holes, empty Available, missing/unsupported, unknown/stale freshness, overlap fixed+editable. Ни один source boundary не подставляется как медь. Keepout не вырезает существующий проводник.
6. **Корпус:** все восемь запусков завершаются с явным статусом и артефактами; отсутствуют crash/hang/скрытые пропуски. Таблица покрытия перечисляет использованные/неподдержанные источники, counts, площади, islands, shorts, время и объём результата. Для `partial`/`invalid` указать конкретную причину. Не требовать заведомо ложного `complete` на всех платах.
7. **Независимая проверка реальных участков:** минимум на двух разных платах выбрать участки pad/track/via и native fill с holes/островками, если они есть; сравнить с сохранёнными native/evidence данными. Зафиксировать IDs, ожидания, координаты/связи и способ получения эталона. SVG полезен для просмотра, но сам по себе не доказывает правильность. Если корпус не содержит нужного случая, использовать явно синтетический купон, не выдумывать CAD-подтверждение.
8. **Ресурсы:** один измеренный прогон корпуса и купонов с ростом числа объектов; показать отсутствие обязательного all-pairs поведения на разнесённых объектах, контролируемую точность и лимиты генерации. Не вводить обещание универсальной линейной сложности или произвольные абсолютные benchmark-пороги без baseline.
9. **Интеграция:** Rust unit/integration tests анализатора, native rebuild, typecheck, build, focused native/runtime tests, launcher и installed-package smoke проходят. Старые import-отчёты на восьми платах не изменились. Новые проверки реально исполняются, не skip из-за отсутствующего addon. Поскольку меняется host dependency graph, подтвердить сохранность прежних экспортов/numeric contracts и короткого CPU placement smoke; дорогую полную серию benchmarks не повторять без причины.

## Не входит в этап

FEM/mesh, DC/thermal/PI/SI/EM solver, сопротивления/токи/потери, материалы и DSL builders, fallback-refill, оптимизация компонентов, полноценный DRC, новые CAD exports, изменение RoutingBoardV2, GPU, F32, кеш, sessions или новый формат основной платы. Refill, mesh и физические свойства остаются обязательными частями дальнейшего плана, а не исключаются из проекта.

Если обнаружен недостаток V2, зафиксировать конкретный пример и невозможность вывода. Не расширять транспорт и не додумывать данные автоматически в этой задаче.

## Что вернуть на проверку

Схему модулей, выбранную библиотеку/версию и численную политику; список поддержанных примитивов и ограничений; ожидаемые результаты купонов; таблицу восьми плат и пути к артефактам; независимые проверки участков; команды тестов и resource measurements. Не коммитить и не начинать meshing/DC до приёмки валидатором.
