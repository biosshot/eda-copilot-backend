# P7: аудит разбиения меди и дорогих близких взаимодействий

Пользователь одобрил этот этап вместо дальнейшего ускорения far action. Исполнитель p7_medium, worktree analyze-p7-extraction. Цель — установить причину стоимости и предложить проверяемое изменение; не внедрять очередной большой solver вслепую.

## Входы и аудит

Использовать сохранённые области STM32G0_CAN_RS485, TPS63060DSCR и BandAmpV5, их исходную медь и уже построенные near/far plans. Зафиксировать hashes. Не экспортировать платы заново и не менять оригиналы.

1. Проследить происхождение supports от CAD/нормализованных polygons через Boolean operations, triangulation и формирование базиса токов. Для известных STM668/556 установить точную стадию появления пикометровых размеров. Различать реальную особенность исходной геометрии, Boolean/roundoff artifact и избыточную фрагментацию. Не объявлять причину по одному размеру без трассировки.
2. Для каждой области вывести число исходных объектов/контуров/вершин, triangles/supports/current DOFs, распределение площадей/объёмов/отношений сторон, совпадающих границ и размеров относительно координатной точности. Сохранить source IDs и координаты worst cases; показать overlays исходной меди и расчётного разбиения с масштабами.
3. Разложить near pairs: self, общая грань/ребро/вершина, близкие несоприкасающиеся, ложное укрупнение near из-за bounding balls и вытянутых supports. Для каждой категории — counts, fixed quadrature orders, доля positive fallback, измеренная/оценочная стоимость. Не переносить среднюю стоимость одного pathological pair на все пары без стратификации.
4. Выбрать небольшую детерминированную выборку категорий ДО измерения. Переиспользовать прежние timings; новые kernel измерения максимум один bounded batch <=120s/512MiB, только после освобождения Thermal heavy slot. Full ROI solve запрещён.

## Сравнение вариантов

Сравнить минимум: сохранение геометрии с более качественной triangulation; объединение только доказанно избыточных внутренних разбиений/изменение current basis; специализированные close-pair формулы/адаптивная квадратура; более точная классификация near. Описать отдельно влияние на physical domain, current approximation, near count, интегральную ошибку и ресурсы.

Разрешён изолированный маленький prototype на saved coupon для проверки причины и эффективности одного варианта. Не менять production mesher/принятый kernel или публичный DSL. Нельзя удалять маленькую медь по площади, схлопывать зазор/перемычку, snap координаты без error contract, обнулять неудобную связь или ослаблять gates. Геометрическое равенство и точность представления токов — разные проверки.

## Приёмка

Итог — конкретная диагностика bottleneck с source witnesses, table counts/costs по3областям и рекомендация ОДНОГО следующего изменения. Для prototype: сохранение nets/connectivity/holes/ports/material boundaries; исходные и новые токовые пространства объяснены, full magnetic energy/reciprocity/PSD и near integral gates сохранены. Для изменений аппроксимации нужны независимый reference и сходимость; один хороший probe недостаточен.

Показать верхнюю/нижнюю рабочую оценку экономии и что остаётся непроверенным. Если число элементов нельзя уменьшить без существенной ошибки — явно сказать, не рисовать speedup. Графики geometry/near categories/cost, сырые данные и hashes в ignored evidence; воспроизводимые fixtures/scripts и отчёт в репозитории.

Изменения ограничить audit/prototype/tests/docs, без коммита, новых агентов, новых зависимостей и большого addon rebuild. CPU F64. Thermal имеет первый heavy slot; read-only audit можно вести параллельно. После отчёта STOP, дальнейшее внедрение только после родительского review.
