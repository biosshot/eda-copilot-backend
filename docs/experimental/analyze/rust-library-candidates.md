# Численные библиотеки Rust: кандидаты

Дата: **2026-10-21**. **Набор библиотек и их назначение согласованы пользователем:** faer + rayon как начальная основа, spade с проверкой на реальной меди, rustfft по мере появления соответствующих задач. Точные версии/features ещё не зафиксированы. Библиотеки не устанавливались, сборки и бенчмарки не выполнялись. Основание исследования — первичная документация. [Структура реализации и численная политика](implementation-structure.md) согласованы отдельно.

## Shortlist

| Кандидат | Задача | Предложение |
| --- | --- | --- |
| faer | Плотная/разреженная линейная алгебра | Основной кандидат numerics |
| rayon | CPU-параллелизм | Кандидат ограниченного пула анализатора |

Готовая линейная алгебра не заменяет физическую постановку, сборку, модели, оценку ошибки и валидацию.

## faer

Документация 0.24.4 описывает плотные LU/QR/Cholesky/SVD/eigen-разложения, комплексные типы и разреженные решатели. Ориентация на средние/крупные матрицы соответствует задачам анализатора. [API](https://docs.rs/faer/0.24.4/faer/).

Sparse-структуры отдельно хранят структуру и значения; большинство sparse-алгоритмов используют CSC. Можно переиспользовать подходящую подготовку неизменной структуры, но изменившиеся коэффициенты обычно требуют обновления численной факторизации. [Sparse](https://docs.rs/faer/0.24.4/faer/sparse/index.html).

Matrix-free документирует CG, BiCGSTAB, LSMR и Krylov–Schur. Готовые GMRES и полноценный AMG этим списком не подтверждены; нельзя обещать, что faer закрывает все предобуславливатели. [Matrix-free](https://docs.rs/faer/0.24.4/faer/matrix_free/index.html).

Обычные опубликованные зависимости не требуют BLAS/LAPACK runtime; их наличие в dev-зависимостях не означает включение в наш addon. Конкретный target/features-граф ещё проверяется. Для кандидата рассматриваются std, rayon, sparse-linalg; npy/rand/nightly не нужны автоматически. [Зависимости](https://docs.rs/crate/faer/0.24.4), [features](https://docs.rs/crate/faer/0.24.4/features).

Начальные применения: sparse Cholesky для подходящей закреплённой SPD-системы DC/thermal; sparse LU для общей электрической системы; плотные разложения для небольших портовых моделей/fitting. Прямое разложение может сильно увеличивать число ненулевых элементов и расход памяти. Большие системы требуют отдельного выбора итерационного метода и предобуславливания.

## rayon

Есть собственный ThreadPool с ограниченным числом потоков и install для вложенных Rayon-операций. Предлагается долгоживущий пул анализа на worker, не пул на каждую частоту. [Builder](https://docs.rs/rayon/latest/rayon/struct.ThreadPoolBuilder.html), [ThreadPool](https://docs.rs/rayon/latest/rayon/struct.ThreadPool.html).

faer имеет Seq/Rayon-исполнение. Его фактическую работу в пользовательском пуле вместе с транзитивными средствами исполнения нужно проверить. Не менять глобальный параллелизм между конкурирующими заданиями. [faer::Par](https://docs.rs/faer/0.24.4/faer/enum.Par.html). Rayon не заменяет лимиты RAM, отмену и бюджет всего backend.

## rustfft

FFT на Rust с планировщиком и SIMD. Нужен для спектров и быстрых линейных свёрток. Планы и рабочие буферы переиспользуются; нормировка, окна, временная сетка и физическая полоса остаются нашей ответственностью. [Документация](https://docs.rs/rustfft/6.4.1/rustfft/).

SIMD не является GPU или автоматической многопоточностью одной FFT. Независимые преобразования можно распределять на уровне анализа. AVX-путь документирован с FMA: это требует проверки числовой политики.

## spade

CDT сохраняет заданные рёбра; refinement поддерживает параметры площади/углов и исключение внешних областей/отверстий из уточнения. Завершённость refinement нужно проверять. [CDT](https://docs.rs/spade/2.15.1/spade/struct.ConstrainedDelaunayTriangulation.html), [refinement](https://docs.rs/spade/2.15.1/spade/struct.RefinementParameters.html).

Это строительный блок, не готовый PCB mesher. Наш код отвечает за объединение меди, пересечения, материалы, слои, контакты и уточнение по физической ошибке. Constraints могут разделяться при уточнении; связь с исходными границами сохраняется отдельно. Числовая реализация предикатов проверяется: f32-вход не гарантирует исключительно f32-арифметику внутри.

## Альтернативы

- **nalgebra:** pure-Rust разложения и удобные небольшие матрицы. Альтернатива или дополнение при конкретной потребности, не второй обязательный формат матриц. [Документация](https://www.nalgebra.rs/docs/user_guide/decompositions_and_lapack/).
- **sprs:** CSR/CSC, сборка и sparse-операции, отдельный sprs-ldl. Добавлять при конкретном пробеле faer, не ради постоянного преобразования между экосистемами. [Документация](https://docs.rs/sprs/0.11.6/sprs/).
- **ndarray-linalg:** использует LAPACK; не первый кандидат для простой автономной поставки. Сам ndarray этим не объявляется обязательно зависимым от BLAS. [Документация](https://docs.rs/ndarray-linalg/0.18.1/ndarray_linalg/).

## Проверки перед подключением

Проверить нужные операции, версии/features/лицензии, toolchain и целевые сборки; реальную RAM/потоки; точность на физических эталонах, сингулярные и плохо обусловленные системы. Микробенчмарк плотного умножения не заменяет проверку наших sparse-систем.

Для анализатора согласован F64 по умолчанию без раннего сравнения с F32; детали и критерии описаны в [структуре реализации](implementation-structure.md). Поддержка f32 библиотекой не доказывает соблюдение строгих правил F32/FTZ/FMA packer. Эти правила placement сохраняются; его вычисления не должны незаметно наследовать семантику анализатора. SIMD/FMA и порядок редукций анализатора проверяются отдельно, не запрещаются автоматически по правилам packer.

Для будущего GPU типы матричных библиотек остаются внутренними деталями numerics, не попадают в DSL/транспорт. Достаточна небольшая граница подготовки/решения; универсальная обёртка над каждым методом матричной библиотеки не требуется. faer не объявляется готовым GPU-backend.
