# RoutingBoardV2: достаточность для согласованных анализов

Проверка **2026-10-21**. Основание: актуальный локальный контракт router, рабочая TypeScript-форма V2, пути экспорта/импорта EasyEDA, RawPcb и три сохранённых autoroute JSON. Это статический аудит и чтение сохранённых данных; новый экспорт из CAD, сбор 20 плат и численные расчёты **не выполнялись**.

## Вывод

**Текущий черновик RoutingBoardV2 нельзя объявить достаточным для всех согласованных анализов без дополнений и проверки экспорта.** Он подходит как основа сменного транспортного формата. Для обычной плоской многослойной PCB значительная часть геометрии уже выражается существующими полями, но есть пробелы метаданных, геометрической семантики и фактического заполнения. Для advanced padstacks/маски/неоднородных структур текущих полей недостаточно.

Проверяется сочетание **RoutingBoardV2 + физические модели/материалы + сценарий DSL**, а не автономная достаточность файла платы. Внешние источники, мощности, охлаждение, стимулы, параметры драйверов и пространственные модели внешних объектов не должны становиться обязательными полями платы. Входной адаптер преобразует внешний DTO во внутренние данные; новые физические возможности иногда требуют расширять и внутреннюю модель.

Этот аудит не меняет базовый DSL и не утверждает новый расширенный Board-тип. Перечисленные ниже исправления становятся задачами [плана реализации](implementation-plan.md); рабочая [форма V2](routing-board-v2-shape.md) остаётся предварительной до этапов P0–P2.

**Уточнение после обсуждения G1–G7:** предложенная [TypeScript-редакция](routing-board-v2-shape.md) добавляет optional partUuid/value, уточняет via/type/span/послойные формы и optional окна маски. Номиналы всех R/C не требуются каждому анализу: параметры разрешаются только для участвующих элементов, из библиотеки/снимка либо ручного DSL. Без UUID импорт допустим; отсутствие необходимой электрической модели обнаруживается в prepare. Наличие новых optional полей не означает, что экспорт уже исправлен.

RawPcb Fill жёстко задаёт fill=true и lineWidth=0; API-ошибки нескольких списков заменяются пустыми массивами, orphan Poured получает TOP |

У записей компонентов есть name/footprint/nets/pinName, но нет отдельного value; name не следует безусловно считать нормализованным номиналом.

«Условно» означает: поля могут выразить поддерживаемую модель после корректного экспорта, но полнота ещё не доказана на корпусе. Отсутствие решателя и отсутствие входных данных — разные статусы.

Net и routing keepout не заменяют физическую связность |

| Планарный full-wave, печатная антенна, излучение платы | Проводники, диэлектрические слои, границы PCB, feed/return | Частоты, возбуждение, пространство, свойства материалов, наблюдения | Условно **только для подтверждённой области собственного метода**. Конечные диэлектрики/вырезы и переходы должны поддерживаться решателем; слоистый Green function не гарантирует их учёт автоматически |

Механика, BER, CFD, корпус устройства/кабели, разряд аккумулятора, универсальный SPICE, автоподбор/размещение decaps — вне согласованного текущего охвата. Нельзя увеличивать board-контракт ради них в этом плане.

## 3. Конкретные пробелы и минимальные действия

| ID | Пробел | Где исправлять / минимальное действие | Когда блокирует |
| --- | --- | --- | --- |
| G1 | В исходной форме нет пути к библиотечным параметрам и значению экземпляра | Предложены optional `components.partUuid` с существующим PartUuid и `value`. Разрешать только нужные параметры, ручной DSL имеет приоритет. Без UUID не блокировать импорт, неизвестный обязательный параметр показать в prepare; ManufacturerId не считать номиналом | Автоматические passives в PI/SI/RF; проверить контракт до P3, resolver в P6 |
| G2 | Cutouts, holes, standalone pads, netless и copper graphics могут теряться; консервативные pad-аппроксимации router и preview stroke не равны физической меди | Исправить экспорт/нормализацию; обычные объекты выразимы существующими points/polygons/pads/holes. Нестандартную постоянную медь можно нормализовать как Fill с реальными полигонами и исходными ID. Фиксировать cap/join, координатные соглашения и допуски. Не добавлять arc-тип | Любой расчёт по реальной меди, уже DC |
| G3 | Via span/type плохо заполняется, сложный padstack не выражен полностью | Сохранены fromLayer/toLayer и обязательный through/blind-buried; разрешение blind-via rule ещё проверить. Via shapesByLayer, локальная platingThicknessUm, micro и null для pad shapes отложены. Неподдержанное не заменяется дефолтами | Сложные PCB DC/thermal и подробные via-модели SI/PI/EM; до соответствующего извлечения |
| G4 | Stackup не задаёт все материалы; solderMask не описывает openings/полный loss | Материалы — ресурсы/DSL. solderMaskOpenings удалён из текущего DTO и сохранён как будущее расширение после проверки источника. До этого применимость явного приближения маски проверяется для каждого анализа | Thermal, точные impedance/RF; проверка до P7/P9 |
| G5 | Package/bodySize не определяют body anchor, тепловые пути, die и источник потерь | Использовать bodyOutline/проверенный offset к anchor; неоднозначное размещение тела явно дополняется моделью. Thermal contacts/power/cooling — DSL/models. Идентичность pad → component terminal должна учитывать несколько pads одного номера | Thermal, package/SMD EM и привязка сложных моделей |
| G6 | Полнота refill rules и CAD snapshots не доказана | Общая таблица rules.refill и неподтверждённые поля отложены; разрешённые clearance/padConnection хранятся inline в zone.refillRules. Per-pad zoneConnection удалён; текущий статус partial/unknown. Точная реконструкция требует будущего расширения. Ошибки API не превращать в пустую геометрию; orphan Poured не присваивать TOP | Refill и доверие любому board-based результату |
| G7 | V2 имеет один внешний outline и глобальный stackup | Первая подтверждённая область — одна плоская PCB с вырезами и глобальным стеком. Панели из нескольких тел, rigid-flex/cavities/local stackups нельзя молча сплющивать; обнаружить и вынести в явные ограничения/будущее расширение | Заявления о произвольной геометрии и полноте всего корпуса |

Связь fixed/editable относится к разрешению редактирования. При анализе учитывается физическая медь **обеих** групп. Source definitions Pour не суммируются с их filledPolygons как две независимые медные области; исходный и fallback fill не учитываются одновременно. Это корректность подготовки геометрии, а не отдельный отклонённый механизм контроля перекрытия электрических моделей.

## 4. Решения, которые нужны до замораживания транспорта

На P0 оформить конкретный минимальный diff TypeScript/JSON для G1–G7, таблицу происхождения каждого поля и правила координат/единиц/ID. На P1 проверить заполнение из CAD, на P2 — достаточность на корпусе. Текущий документ не выдаёт optional поле за реально экспортируемое и не предлагает сохранять всю CAD-документацию внутри board.

Для каждого анализа preflight проверяет только нужные ему входы. Отсутствие тепловой модели не блокирует геометрию; неизвестная медь в анализируемой области не позволяет объявить достоверный DC. Формат и реальная заполненность проверяются отдельно от доступности численного метода.

**Положительное заключение возможно после корпуса:** каждый значимый CAD-объект либо корректно представлен, либо явно признан неподдержанным; необходимые параметры модели доступны из известного источника; отсутствуют молчаливые пропуски; пройдены независимые проверки контактов/геометрии и первых физических эталонов. Двадцать плат дают проверенное покрытие выбранных случаев, а не доказательство поддержки любой PCB.
