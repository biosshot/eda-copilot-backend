## M1 — `check` с `equals` допускает несовместимую единицу

Место: `src/analyze/analysis-dsl/data.ts`, `ReportStore.check`, ветка сравнения `equals` для обёрнутого результата.

Проверка единицы сначала записывает сообщение об ошибке, но не запрещает последующее сравнение. Для результата с `unit: "1"` ветка `equals` вычисляет `pass`, после чего перезаписывает сообщение. Поэтому следующий обычный JS-сценарий по текущему коду записывает **pass**, хотя должен записать **unknown**:

```js
const a = analysis();
a.check({
  name: "Несовместимые единицы",
  actual: {
    kind: "scalar",
    unit: "1",
    value: 1,
    validity: { status: "valid" },
    diagnostics: [],
  },
  equals: 1,
  unit: "V",
});
a.log({ level: "info", message: "После проверки исполнение продолжается" });
```

Это вывод по коду, **не результат выполненного здесь теста**. Нельзя выдавать успешную проверку при явно несовместимой единице, в том числе для счётчиков/логических результатов. Исправление: единая проверка совместимости единицы до выбора предиката; сохранить разрешённое dimensionless-сравнение через `equals` без `unit` или с `unit: "1"`. Не добавлять автоматическое преобразование единиц и не превращать ошибочную проверку в исключение.

Приёмка исправления:

- Обёрнутый scalar `1`, `equals: 1`, `unit: "V"` даёт `unknown`, объясняет несовпадение единиц; следующая строка исполняется.
- Та же проверка без `unit` и с `unit: "1"` проходит; несовпадающее значение даёт `fail`.
- `unavailable` остаётся `unknown`; существующие диапазонные проверки не меняют поведения.
- Регрессия проходит через production `runAnalysisDsl`, без тестового физического исполнителя; достаточно расширить существующий focused DSL-тест.
