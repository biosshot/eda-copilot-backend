# План реализации анализаторов

**2026-10-21. Только документация.** План подготовлен по запросу пользователя; исходники, манифесты и зависимости не изменяются, проекты плат не скачиваются, этапы не объявляются выполненными. Это детализация [архитектуры](implementation-structure.md), [математических методов](numerical-architecture.md), [DSL](dsl-reference.md) и [стратегии тестирования](validation-corpus.md).

## 1. Зафиксированные границы

- Репозиторий ядра — eda-copilot-backend: `native/analyze` и `src/analyze`; packer и analyze — библиотеки, отдельная N-API оболочка собирает один `.node`. Для получения данных понадобятся изменения экспортёра в существующем EasyEDA Copilot, без нового репозитория контрактов. Места интеграции перечислены ниже.
- RoutingBoardV2 — входной транспорт. Адаптер преобразует его во внутренние данные; решатели не зависят от EasyEDA DTO. Плата неизменяема, варианты расчёта не применяются автоматически в CAD.
- Математика на F64, многопоточный CPU, ограничение потоков и памяти. Обязательных F32-путей/сравнений сейчас нет. GPU — будущая возможность; прежние F32/GPU правила placement сохраняются.
- Собственная физическая реализация; faer/rayon, spade после проверки на меди, rustfft по потребности. Внешние солверы — источники методов/сохранённых эталонов, не программы, необходимые пользователю для запуска.
- Самодостаточная проблема → worker → Rust → результат, с прогрессом/отменой по концепции packer. Кеш — оптимизация, не обязательное пользовательское состояние. `compute-runtime` заранее не создаётся.
- Сохраняется полный согласованный состав: geometry, DC, thermal, electrothermal, impedance/TDR, SI/crosstalk/eye/timing, AC/transient PI, EMI, planar full-wave/антенны, S-параметры, sweep/solve/optimize, standalone-расчёты.
- BER, механика, CFD, корпус/кабели, универсальный SPICE/IBIS-AMI и автоматическое проектирование decap-развязки не входят. Нет нового converters/battery subsystem и `.solver("openems")`.

**Результат проверки входов:** текущая форма V2 ещё недостаточна для безусловного охвата. [Аудит достаточности](routing-board-v2-sufficiency.md) содержит подтверждения кода, матрицу анализов и пробелы G1–G7. Их закрытие или явное ограничение — часть P0–P2, а не предположение плана.

[Текущая редакция TypeScript V2](routing-board-v2-shape.md) сокращена до базовых данных и подтверждённых расширений. Геометрия окон маски, специальные via padstacks/micro и полные refill rules отложены до проверки источников на P0–P2. Состав анализов и fallback-refill из плана не отменяется: соответствующие этапы требуют доказать источники и расширить DTO перед реализацией зависимых возможностей. UUID/номиналы всех R/C не обязательны для импорта; нужные модели задаются доступными данными либо DSL. Существующий код не изменён.

## 2. Зависимости и порядок

**Готовность к старту:** пользователь принял рабочую TypeScript-структуру V2 с inline-правилами в Pour и без pad.zoneConnection. Для P0–P2 не требуется ещё один раунд проектирования DSL/архитектуры. На P0 остаются инженерные соглашения: единицы/координаты/слои/IDs, точность геометрии, разрешение правил и диагностика неполного чтения. Их уточняем по данным CAD. На пилотных 3–5 разнообразных трассированных платах проверяем экспорт и формат тестового случая, затем расширяем корпус до согласованных ≥20. Число пилотных плат не заменяет критерии P2. Реализация solver начинается по зависимостям ниже; достаточность V2 и точность методов доказываются разными проверками.

| Этап | Результат | Обязательные зависимости |
| --- | --- | --- |
| P0 | Уточнённые источники данных, транспорт и критерии корпуса | Текущие решения и статический аудит |
| P1 | Экспорт EasyEDA → V2 и сохранённый корпус ≥20 плат | P0; экспорт и сбор итеративно |
| P2 | Аудит корпуса, зафиксированные ограничения и тестовые эталоны | P1; первые проверки начинаются на пилотных экспортах |
| P3 | Общий addon, анализатор, DSL runtime и исполнение problem → result | P2 для стабилизации границы входа |
| P4 | Внутренний board, физическая геометрия, контакты, mesh, geometry/refill | P3 и проверенные входы P2 |
| P5 | Сквозной DC по реальной меди | P4 |
| P6 | Электрические сети, модели компонентов, AC/transient, multiport/FFT | P3; использует численную основу P5, standalone тесты независимы от CAD |
| P7 | Извлечение связанных линий/via/PDN и сокращённые модели | P4–P6 |
| P8 | AC/transient PI по плате | P5–P7 |
| P9 | Стационарный/transient thermal и радиаторы | P4; P5 нужен для источников потерь из DC |
| P10 | Электротепловая связь | P5, P9; P6/P8 при использовании динамических электрических потерь |
| P11 | Impedance/TDR, SI/crosstalk, eye/timing и RF-каналы | P6–P7 |
| P12 | EMI: риски, conducted, coupling, внешние возбуждения | P4, P6–P7; сравнения со связанными SI/PI — P8/P11 |
| P13 | Собственный планарный full-wave, антенны и излучение | P4, P6–P7 и положительная проверка применимости метода |
| P14 | Полная интеграция sweep/solve/optimize и вариантов | P3 и готовые анализаторы P5–P13 по сценариям |
| P15 | Полная регрессия, документация и поставка | Все согласованные возможности P0–P14 либо явно согласованные изменения объёма |

Основной маршрут: экспорт/корпус → DC → электрическое ядро/извлечение → PI → thermal/electrothermal → SI → EMI → full-wave → итоговая интеграция. P9 допускает независимую работу после P5; P11 — после P7. Это зависимости задач, не поручение запускать параллельных агентов. Минимальный sweep появляется уже с P5; P14 не откладывает всю исследовательскую функциональность до конца.

Риск применимости планарного EM исследуется заранее на P2/P3: ограничения конечных диэлектриков, вырезов, via, портов и поддерживаемых SMD-моделей. Малый проверочный прототип относится к будущей реализации и не считается готовым P13. Отрицательный результат требует пересмотра метода/границ с пользователем, а не молчаливой замены full-wave эвристикой.

## 3. Подготовка входов и тестирования

### P0. Спецификация экспорта и закрытие известных пробелов

- [ ] Инвентаризировать autoroute JSON, native primitives/PourFills, DRC и свойства компонентов. Для каждого поля V2 указать источник, единицы, преобразование и способ проверки.
- [ ] Разобрать G1–G7: минимальные метаданные R/C/L, физическая медь/holes, spans/padstacks, материалы/маска, тела/terminal mapping, refill и область поддержанных плат. Оформить конкретный diff документа TypeScript/JSON; не добавлять второй список компонентов и не возвращать importInfo/schemaVersion.
- [ ] Определить координатные соглашения, порядок слоёв, локальные/абсолютные shapes, bottom transforms, slot offsets/rotation, допуск аппроксимации и поведение на лимите сегментов.
- [ ] Определить проверку согласованности чтений CAD. Если атомарный снимок недоступен, ограничение видно в диагностике; timestamps не объявляются доказательством атомарности.
- [ ] Утвердить манифест тестового случая и критерии отбора ≥20 плат. Набор сценариев, ожидаемых величин и допусков хранится отдельно от транспорта.

**Тесты/проверки:** ручная трассировка каждого обязательного поля до источника, разбор трёх существующих JSON как стартовых примеров; ни один не засчитывается автоматически как полноценная трассированная плата. Отдельная таблица «поле существует / источник доступен / значение проверено».

**Выход:** рабочая спецификация экспортёра, минимальные изменения контракта, перечень неподдержанных структур и критерии пилотного аудита. Неведомые значения не заменены дефолтами.

### P1. Экспорт EasyEDA и сбор корпуса

- [ ] Реализовать обогащённый экспорт через существующие пути EasyEDA Copilot. Кандидаты: `extension/src/eda/pcb.ts`, `extension/src/mcp-client.ts`, `shared/types/pcb/*`, `mcp/src/routing/easyeda-autoroute-adapter.ts`; конкретное разделение определить перед изменением. V1 router продолжает работать, V2 — отдельный маршрут совместимости.
- [ ] Считать реальные Pour/Poured/Fill и правила; сохранить source IDs/слои, корректно преобразовать fill/stroke и вложенные контуры. Реализовать строгую диагностику ошибок API вместо пустых массивов.
- [ ] Заполнить pad holes/slots/plating, standalone pads/holes, контур/cutouts, via span/type, netless copper и метаданные компонентов. Сначала native-медь, без обязательного запуска собственного refill.
- [ ] Сделать корректную аппроксимацию дуг и нормализацию физической меди. Не переносить консервативные препятствия router или упрощения Preview как фактическую геометрию.
- [ ] Собрать несколько пилотных плат, затем минимум 20 различных трассированных EasyEDA-проектов по [распределению корпуса](validation-corpus.md). Сохранять исходник, происхождение/условия использования, ревизию, native-экспорт, V2 и диагностику. Искать больше кандидатов, чем нужно для итогового покрытия; непригодный проект не подменять фиктивной платой.

**Тесты:** round/oval/round-rect/polygon pads, bottom side, holes/slots, разные widths, дуги/окружности, вложенные заливки/островки/thermals, missing/orphan Poured, пустая реальная заливка, unknown net, native ошибки. Проверка старого routing-экспорта и его потребителей на отсутствие регрессий.

**Выход:** воспроизводимый экспорт и ≥20 сохранённых исходных плат; статус каждой — экспортировано/ограничение/ошибка. Число скачанных файлов не выдаётся за число проверенных проектов.

### P2. Аудит корпуса, эталоны и критерии точности

- [ ] Сравнить CAD → V2 на каждой плате: слои, медь, площади/границы, holes, контакты, shorts/opens и нетипичные объекты. Проводить визуальное наложение вместе с независимыми численными проверками; Preview с тем же декодером не является независимым эталоном.
- [ ] Для каждого анализа заполнить требования к stackup/materials/models/scenario и известные пробелы. Не требовать thermal-параметры от случая, проверяющего только импорт.
- [ ] Подготовить малые аналитические задачи DC/RLC/thermal и геометрические купоны, будущие SI/EM-эталоны. Записать постановку, происхождение, полосу/режим, погрешность и единицы каждого ожидаемого результата.
- [ ] Назначить несколько сценариев каждой подходящей плате: нагрузки, температура, сигналы, измерительные порты; известные плохие варианты сохранять отдельно от исходника. Намеренно неуспешный check — полноценный тест.
- [ ] Выбрать ранние рискованные случаи planar EM/извлечения и процедуру проверки; подготовить конечный набор геометрий, которые обязан выдержать выбранный метод.
- [ ] Определить быстрый набор, расширенный корпус и дорогие эталоны; манифест связывает случай с обязательными для него этапами.

**Тесты:** все экспортные свойства P1 на корпусе, чистый повтор импорта из сохранённого снимка, выявление неизвестных данных. Численные решатели ещё не обязаны существовать: здесь готовятся входы и независимые ожидаемые результаты, не самоподтверждающие golden outputs.

**Выход:** аудит ≥20 плат и закрытые блокирующие дефекты экспорта для первой поддержанной области; подтверждённый транспорт для P3/P4; готовые DC-эталоны и план проверок остальных методов. Неподдержанные сложные случаи сохраняются в корпусе с явным статусом, не считаются поддержанными. Риски full-wave не скрыты до последнего этапа.

## 4. Исполнение и общая физическая основа

### P3. Native-оболочка, runtime DSL и воспроизводимая проблема

- [ ] Выделить packer в Rust-библиотеку и создать библиотеку analyze с общей оболочкой N-API. Адаптировать сборку/упаковку/загрузку, Cargo profiles/lockfile и exports, сохранив placement F32/GPU-поведение. Новую общую compute-библиотеку не создавать.
- [ ] Подключить согласованные библиотеки с нужными features после проверки лицензий/toolchain/целевых сборок. Закрепить версии и проверить отсутствие незапланированного внешнего runtime.
- [ ] Реализовать минимальный JS/TS runtime и builders принятого DSL, разрешение globals/resources, неизменяемые snapshots, builder.prepare/run, единицы/селекторы/ports. prepare остаётся необязательной диагностикой, не пользовательской сессией памяти.
- [ ] Сформировать внутреннюю задачу с входной платой/моделями/сценарием, адаптер RoutingBoardV2 → внутренние данные в Rust и воспроизводимый capture. Callback evaluate исполняется в TS; поддерживаемые функции времени преобразуются в согласованное описание/выборки с контролем точности, произвольные JS-функции не сериализуются в Rust.
- [ ] Адаптировать process workerpool: очередь, ограничение CPU/RAM, progress, отмена/timeout/ошибки. Проверить реальные границы остановки native-вызова; прекращённый расчёт не выдаёт успешный частичный результат.
- [ ] Базовые результаты: скаляры/серии/карты, complex/units, исходные IDs, diagnostics, check/plot/log/report. Fail/unknown check продолжают DSL, невалидный запуск отклоняет Promise согласно контракту. Кеш ограничен и выключаем; большие массивы не копируются без необходимости.

**Тесты:** V2 → internal (вторая независимая граница аудита), immutable builder, отсутствие неявного наследования, ручные overrides, работа без board, сериализация/ошибки/повтор запуска, отмена и сбой worker, пустой/заполненный кеш. Прежние native exports и focused placement replay после изменения упаковки.

**Выход:** рабочая инфраструктура и контракт результатов без обещания готовности физики; один addon, сохранённая совместимость packer. Поддержка всех имён DSL без решателей не выдаётся за выполненный анализ.

### P4. Физическая геометрия, связность, материалы, сетки и fallback-refill

- [ ] Нормализовать фактическую медь fixed+editable, геометрию отверстий/вырезов, контакты pad/via и межслойные связи; не соединять всё по имени net. Source outline Pour не считается заполненной медью.
- [ ] Подключить stackup/materials из DSL и проверять соответствие слоям, толщины, необходимые свойства и единицы. Не вводить универсальные молчаливые FR4/проводимость/plating значения.
- [ ] Реализовать geometry-проверки и измерения с привязкой к объектам; spatial index, области и экспорт карт для существующего отображения. Малые зазоры/отверстия не удаляются ради красоты.
- [ ] Построить сетки для слоистого conduction и соответствие исходной геометрии. Проверить spade на отверстиях/constraints; ограничения mesher видны. Сетки для разных задач не принуждаются к единому разрешению.
- [ ] Реализовать собственный fallback-refill поддержанных режимов: препятствия, приоритеты, эффективные правила, thermals/hatch/islands по спецификации. При неполных/неподдержанных правилах — диагностика, не угадывание. Использовать пригодную CAD-заливку по умолчанию; физический дефект меди не «лечится» импортом.
- [ ] Результат refill — производные данные анализа с provenance/cache dependencies, не перезапись native fill или CAD. Не суммировать CAD и fallback геометрию. Неподдержанный Fill нельзя заменять Pour.

**Тесты:** аналитические площади, topology/contacts, отверстия/узкие шейки, shorts между разными nets, разрыв одной net; повороты/сдвиги целой постановки; проверка требований mesh и границ; CAD-vs-fallback на известных режимах; невозможный refill. Для невосстановимых случаев DC допускается только на достоверной нужной геометрии.

**Выход:** geometry и подготовка DC работают на корпусе в объявленной области, правила происхождения фактической меди однозначны. Отсутствие покрытия всех CAD-refill режимов не скрывается.

## 5. Последовательная реализация анализаторов

### P5. DC по реальной меди — первый сквозной анализ

- [ ] Реализовать сборку слоистой проводимости, площадки/металлизированные переходы, источники/нагрузки и выбранные граничные условия. Для подходящих систем — sparse Cholesky, для иных — подходящий общий путь; сингулярность диагностируется.
- [ ] Распределять заданную нагрузку по контактам выбранной сети и возвраты по GND согласно DSL: равномерный остаток и отдельные ручные токи. Отчёт перечисляет допущения и неполные назначения.
- [ ] Получить напряжения, токи/плотности, потери, карты и измерения портов; выполнить board DC и standalone conductor. Заданный circuit использует общее ядро P6. Температурная зависимость материалов в фиксированном температурном состоянии.
- [ ] Подключить минимальный sweep заданных нагрузок через evaluate и проверку повторного использования подготовки.

**Тесты:** однородная полоса R=rho L/A, сети с известным решением, две ветви/несколько GND, manual remainder, ограниченный источник по принятой модели, missing ground/обрыв/короткое, via-chain, реальная заливка. Баланс токов и мощности, уточнение сетки, локальный ток через узкую перемычку. Корпус: простая/силовая/многослойная/плотная плата, нормальный и перегрузочный режим.

**Выход:** DSL → экспортированная PCB → DC → карта потерь → check/report; подтверждённые физические результаты F64. Нет скрытого бесконечного/нулевого решения при плохой постановке.

### P6. Общая электрическая сеть и компонентные модели

- [ ] Реализовать MNA для заданных RLC/управляемых поддержанных источников, circuit DC/рабочую точку, AC и transient, начальные условия/переключения, контроль ошибки и независимость output sampleStep от внутреннего шага.
- [ ] Простые a.model, модели supply/load/driver/receiver и R/C/L. Для участвующих компонентов разрешать параметры по optional PartUuid, значению экземпляра или явному DSL; не требовать весь BOM. Использовать существующий TS device resolver по возможности, сохранять разрешённые ресурсы для воспроизведения, не выполнять сетевой поиск из Rust. Автоматический номинал не означает автоматически достоверные ESR/ESL/частотный диапазон. Поддерживаемые форматы ресурсов и pin/port mapping документируются.
- [ ] Подключить multiport, S/Z/Y и a.connect, загрузку проверяемого поднабора Touchstone, reference impedances и комплексные серии. Проверять полосу/устойчивость/причинность по используемым операциям; не создавать отдельный ранее отклонённый механизм границ моделей.
- [ ] FFT/свёртки, нормировка/окна, временные отклики частотных моделей, vector fitting по потребности. Пассивность проверять/сохранять для пассивных объектов, не принудительно для RF-усилителя.

**Тесты:** RC/RLC-отклики, резонанс/ступень, согласованность AC и transient в допустимых режимах, разрывные stimuli, отрицательные номиналы/невалидные порты, заведомые S-матрицы thru/аттенюатор и заданная активная модель, преобразования S/Z/Y с известным ответом. Неподдержанный ресурс даёт диагностируемый отказ.

**Выход:** standalone circuit/network считается без платы; единое электрическое ядро пригодно для PI/SI/EMI. Полный SPICE и произвольный IBIS-AMI не обещаются.

### P7. Извлечение линий, переходов и PDN

- [ ] Реализовать численное сечение связанных линий и RLGC(f) для поддержанных материалов/структур; несколько проводников и слоёв, опорная медь, потери. Простые формулы использовать в проверенной области.
- [ ] Добавить локальные quasi-static модели переходов/неоднородностей, выбранные PEEC/BEM-подходы; проверить pad/antipad/span/возвраты, включая пробелы G3. Отсутствующую структуру не заменять идеальным via.
- [ ] Извлекать PDN с переходами, связями и частотными потерями/распределённым поведением в заявленной полосе. Статический DC-граф не выдаётся за достаточную широкополосную модель.
- [ ] Сокращать подробные пассивные модели с сохранением нужных откликов/пассивности (направление PRIMA), восстанавливать внутренние токи/потери, если они нужны. Проверить fitting и границы интерполяции.

**Тесты:** стандартные сечения с независимым решением, симметричная/асимметричная пара, проводники на разных слоях, одиночный via и возвратные via, PDN-купон, mesh/frequency convergence. Проверка полной и сокращённой моделей на выбранных портах и внутренних величинах; нельзя валидировать только S21, если выдаются локальные потери.

**Выход:** частотные модели линий/via/PDN с подтверждёнными границами геометрии/полосы и измеренными затратами. Конкретный iterative solver/preconditioner выбирается по полученным системам, не по общему обещанию библиотеки.

### P8. AC и переходный PI по плате

- [ ] Объединить извлечённый PDN с источниками/нагрузками/decap-моделями и измерительными портами. DC-DC задаётся согласованными независимыми входной нагрузкой и выходным источником; энергетическая обратная связь не выдумывается.
- [ ] Реализовать Z(f), переходный отклик, просадку, резонансы и распределение токов/потерь там, где поддержано моделью; начальные условия согласовать с электрическим ядром.
- [ ] Проверять заданные варианты развязки и sweep. Автоматический подбор количества/расположения decaps не добавлять.

**Тесты:** RLC PDN с известным ответом, сравнение простого случая с P5 при DC-пределе, шаг нагрузки с конечным фронтом, несколько rails/returns, резонанс/антирезонанс, влияние ESR/ESL и положения заданного decap. Корпус — buck/MCU/многослойная PDN; отсутствие модели не считается идеальной развязкой.

**Выход:** AC/transient PI на реальной плате и standalone circuit, ожидаемые отрицательные checks и явные допущения, проверенная полоса извлечённой модели.

### P9. Thermal и охлаждение

- [ ] Слоистая теплопроводность по меди/диэлектрику/vias, компактные package thermal paths, стационарная и неявная адаптивная временная задача.
- [ ] Заданные мощности и карты DC-потерь, температуры среды/профили, initial state; radiator/TIM/контакты/теплоёмкость и заданные характеристики пассивного/активного охлаждения без CFD.
- [ ] Корректно разделить junction/case/board/ambient; body по package — приближение геометрии, не источник скрытых thermal parameters. Поддержать thermalNetwork без платы.

**Тесты:** тепловое сопротивление однородного тела, экспонента lumped RC, баланс энергии и теплоёмкости, стационарный предел transient, ступень мощности/температуры среды, включение заданного обдува, сеточная/временная сходимость. Корпус — MOSFET/радиатор/MCU, сравнение с независимыми данными при известных условиях.

**Выход:** проверенный нагрев и охлаждение во времени; отсутствие enclosure/CFD не маскируется обещанием температуры произвольной сборки.

### P10. Электротепловой координатор

- [ ] Связать conductivity(T) → электрические потери → thermal → обновление материалов, с согласованными разными временами и остановкой по сходимости.
- [ ] Переносить потери между сетками с сохранением мощности; детализировать/усреднять динамические потери только в допустимом масштабе времени.
- [ ] Выдавать совместные результаты и причину несходимости, не бесконечный цикл. Не создавать третий дублирующий решатель.

**Тесты:** аналитическая/независимая модель резистора с rho(T), разные сетки с одинаковой полной мощностью, влияние шага связи, постоянные коэффициенты дают согласованный несвязанный результат, заданный режим теплового разгона/несходимости. Корпус — силовые paths и MOSFET.

**Выход:** количественно проверенная двусторонняя связь, различены физическое превышение температуры и численная несходимость.

### P11. Impedance/TDR, SI, crosstalk, eye/timing и RF

- [ ] Impedance/frequency характеристики одиночных и совместных линий; a.differential — описание пары. Разбивать неоднородную трассу на подходящие связанные модели, переходы и ветви; не выдавать одно число за полную характеристику сложной линии.
- [ ] SI через channels([...]), drivers/receivers со stimulus; измерения порта/нескольких портов. CAN/параллельная шина/DDR используют тот же электрический интерфейс.
- [ ] TDR, eye и result.timing(sampling/propagation), заданные пороги/фронты и правило обработки звона/отсутствующих событий. Число периодов/полоса/шаг вывода согласованы с наблюдением.
- [ ] RF-сценарий: извлечённые линии + заданные S-параметры усилителя, S/Z/Y и отклик; тип активной модели сохраняется.

**Тесты:** согласованная/несогласованная линия с известной задержкой/отражением, crosstalk на паре линий, смена слоя/проводники на разных слоях, CAN stub, несколько data channels с контролируемым skew, DDR sampling относительно строба, ringing/missing edge, известный RF multiport. BER/протокол не имитировать.

**Выход:** связные сценарии USB/CAN/display/DDR/RF работают через единый DSL с результатами и проверками; геометрическая длина не подменяет временную задержку.

### P12. EMI-риски, conducted и coupling

- [ ] Геометрические риски возвратов/петель/соседства с явными правилами; без амплитуд нельзя выдавать уровни излучения.
- [ ] Excitations на портах, заданные пространственные источники/поля, их placement/ориентация и фазы в поддержанной модели. Параметры SW — волна с амплитудой/фронтом/возвратным путём, не только частота.
- [ ] Conducted по общей сети; coupling на чувствительных портах с нагрузкой/измерительной моделью, временной/частотный результат и выбранный detector. Внешний двигатель — явно заданная модель возмущения, не автоматическая физика мотора.
- [ ] Реализовать поддержанные quasi-static near-field связи с соответствующей областью применимости. Полноволновой путь при необходимости использует P13, не объявляется готовым этим этапом.

**Тесты:** известная взаимная индуктивная/ёмкостная связь, нулевой источник/смена фазы, изменение расстояния и ориентации в допустимом аналитическом случае, влияние реальной reference copper, SW рядом с ADC, внешнее поле на приёмную структуру, измерительный спектр известного сигнала. Проверка полосы и отсутствия двойного добавления одного возбуждения.

**Выход:** численно проверенные наведённые напряжения/кондуктивные помехи и отдельно объяснимые риски. Compliance устройства и полное излучение без P13 не заявляются.

### P13. Планарный full-wave, печатные/SMD-антенны и излучение

- [ ] Реализовать собственный MoM в подтверждённой ранним исследованием области: базис/интегралы, layered media, порты/return, потери, существенная геометрия переходов и границы.
- [ ] Определить обработку конечного диэлектрика, cutouts и неоднородностей; если выбранный метод не покрывает нужный класс корпуса, согласовать доработку/ограничение, не молча считать бесконечную подложку точной моделью.
- [ ] Получать S-параметры, fields и radiation; нормировка возбуждения/мощности, диаграмма, проверка применимости near/far field. Поддержать standalone scene.
- [ ] Согласованные пространственные EM-модели SMD/внешних антенн взаимодействуют с платой только в пределах реализованного представления. S11/название корпуса не заменяют геометрию/поле.
- [ ] Проверить ресурсы плотных систем, частотный sweep и сокращение; ускоренные операторы добавлять по измеренному узкому месту, без обещания произвольного размера задачи.

**Тесты:** независимые эталоны линии/перехода и печатной антенны, сеточная/частотная сходимость, баланс входной/излучённой/рассеянной мощности, взаимность для взаимных структур, нормировка S. RF/antenna случаи корпуса, известная пространственная модель SMD и отрицательный случай только с S11.

**Выход:** full-wave и излучение в документированной области со ссылками на эталоны; полный объём согласованного EM не закрывается одной картинкой поля. Кабели/корпус/CFD не добавляются.

### P14. Исследования, подбор и варианты

- [ ] Завершить sweep/solve/optimize: evaluate, несколько параметров, scalar/метрики, cartesian/zip, критерии остановки, ограничения и ошибки отдельных оценок по DSL. Без обещания глобального оптимума произвольной задачи.
- [ ] Варианты геометрии/материалов неизменяемы относительно CAD; инвалидировать зависимые заливки, mesh, extraction, factors и reduced models. Если обновить fill нельзя, вариант не получает ложный достоверный результат.
- [ ] Реализовать ограниченный параллелизм оценок; функции пользователя остаются в JS/TS. Повторные варианты используют кеш только при совпадении значимых данных.

**Тесты:** sweep мощности/температуры, поиск ширины для заданного импеданса в поддержанной модели, ограниченная оптимизация с известным решением, невозможная цель, отмена/ошибка evaluate, холодный/тёплый кеш, вариант меняет нужный результат и не исходную плату. Сценарии на разных анализаторах, включая standalone.

**Выход:** согласованные исследовательские операции работают поверх всех готовых методов. Автопроектировщик decap-развязки не возникает из общего optimize автоматически.

## 6. Сквозная проверка и поставка

### P15. Интеграция и приёмка

- [ ] Пройти [матрицу DSL](dsl-data-matrix.md), [справочник](dsl-reference.md) и реальные сценарии: каждому согласованному вызову сопоставлены реализация, проверки входов, результат и тест. Не скрывать отсутствие возможности общей ошибкой «unsupported» и одновременно объявлять этап выполненным.
- [ ] Проверить весь корпус ≥20 плат по назначенным сценариям, все малые эталоны и регрессии. Не требовать дорогое EM на каждой плате, но для каждого заявленного метода иметь независимое численное подтверждение и реальные интеграционные случаи.
- [ ] Проверить геометрические overlays/maps, единицы/масштабы/направления, связь с CAD-объектами, отчёт допущений, отрицательные и unknown checks; отсутствие ложных зелёных результатов при частичном входе.
- [ ] Повторить целевые сборки/пакетирование одного addon, загрузку без GPU для анализа, placement-регрессию, ошибки/отмену/лимиты, кеш и воспроизводимый problem capture. Измерить размер бинарника и runtime-зависимости, не обещать прежний размер packer после добавления математики.
- [ ] Сопоставить новый экспорт с потребителями router/Preview. Удаление RawPcb и перевод router на V2 не являются предпосылками первых анализов; возможны отдельной миграцией только после паритета потребителей и их тестов.
- [ ] Обновить примеры/инструкции и таблицу поддержанных геометрий/моделей/полос; зафиксировать известные ограничения. Изменение согласованного охвата обсуждается явно.

**Выход:** согласованный набор функций подтверждён тестами и документацией. Наличие этапа в этом плане не является обязательством по календарному сроку или заявлением о готовности.

## 7. Общие правила приёмки каждого этапа

1. **Точность входа:** для поддержанного случая нет молчаливых пропусков. Неизвестные данные обнаруживаются до зависимого расчёта; точность аппроксимации связана с геометрией/зазорами, а не только с лимитом точек.
2. **Численная точность:** перед реализацией конкретного эталона записать наблюдаемую величину, абсолютный/относительный допуск, область применимости и происхождение ответа. Универсального «1% для всего» нет; около нуля нужен абсолютный допуск. Измерительный эталон учитывает неопределённость измерения.
3. **Сходимость:** mesh/time/frequency refinement меняет целевые величины в пределах принятого бюджета; малая невязка не заменяет проверку физического результата. F64 — рабочая точность, не независимый эталон.
4. **Физические инварианты:** ток/мощность/энергия и применимые симметрия/взаимность/пассивность. Проверять отдельно отрицательные случаи; физический предел и численная ошибка имеют разную диагностику.
5. **Регрессии:** собственный сохранённый вывод доказывает неизменность поведения, а не правильность физики. Эталоны не перезаписываются автоматически при обновлении solver/адаптера.
6. **Ресурсы:** записывать оборудование, threads, размер сетки/системы, подготовку/solve/полное wall time, пиковую RAM и холодный/повторный запуск. Лимиты назначать по классу задачи и измерениям; сравнивать одинаковые входы/точность. Никаких обязательных F32-бенчмарков сейчас.
7. **Самостоятельность поставки:** обычные тесты используют сохранённые источники/эталоны; живой CAD проверяется отдельно. Внешний solver не становится зависимостью штатного запуска или обычного CI.

## 8. Что сознательно уточняется внутри задач

Версии/features crates, точные внутренние Rust-типы, схемы интегрирования/предобуславливатели, размеры пакетов IPC/кеша и численные пороги выбираются в соответствующем этапе с проверками. Это не повод заново открывать весь DSL. Если проверка выявляет невозможность согласованного метода или нехватку новых физических данных, обновляется аудит и обсуждается конкретное изменение; интерфейс не расширяется «на всякий случай».

Для каждой задачи плана будущая карточка исполнения должна содержать затрагиваемые файлы, зависимости, тестовые случаи и критерий завершения. Сейчас ни одна реализационная задача не помечена выполненной.
