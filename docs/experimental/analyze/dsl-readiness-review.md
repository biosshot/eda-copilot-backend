# Аудит DSL: открытые решения и покрытие сценариев

Дата: **2026-10-20**. Проверка проекта API и документации, без реализации, численного тестирования и утверждения точности. [Принятые решения](dsl-scenario-decisions.md), [справочник](dsl-reference.md).

**Итог после обсуждения:** базовый DSL согласован. Пользователь подтвердил drivers/receivers, привязки, timing, a.model и измерения в [рабочем контракте](dsl-working-contract.md). Отдельный механизм контроля границ/двойного учёта моделей отклонён. Этот аудит сохраняет историю вопросов, а не список незакрытых блокеров DSL.

## Итог

Набор видов анализа достаточен для постановки обсуждавшихся задач. Это не завершённая спецификация всех аргументов и не доказательство, что любой пример уже можно исполнить. Новые отдельные языки/анализаторы для CAN, DDR, аккумулятора и наведённого напряжения не нужны.

Приняты channels([...]), drivers/receivers и timing(options) у результата. Конструктор a.channel сохраняется; network остаётся альтернативой channels для заданной сети. Прежние setters активности удалены из актуальных примеров.

## Вопросы аудита и их решения

| Вопрос | Основание уточнения | Итог |
| --- | --- | --- |
| Единая запись активности SI | Закрыто пользователем: прежние setters исключены | drivers с stimulus и receivers; соседние активные линии включаются в общую сеть |
| Привязка моделей | Нужна понятная запись нескольких контактов | Приняты port/ports из рабочего контракта |
| Временные измерения | Требовалось определить options/метрики | Приняты sampling/propagation, пороги, события и правила пригодности |
| Объекты данных и проверки | Требовались единые операции и работа с пропусками | Приняты abs, подписанный at, единицы, validity и проверки без остановки |
| Ресурсы моделей и источники значений | Нужны простые модели без файла | Принят a.model с параметрическими видами; ресурсы для сложных моделей |
| Возбуждения и наблюдение EMI | excitations/coupling/measurement/voltage(port) приняты, но нет полного контракта спектров/размещения/нескольких наблюдений | Явные комплексные спектры и временная привязка, система координат/поворотов, единая запись измерений без неявной нагрузки |
| Контроль границ моделей | Обсуждался редкий случай повторного учёта содержимого моделей | Отдельный механизм отклонён пользователем; не является требованием или открытым блокером DSL |

Базовые пользовательские правила приняты. Формальные transport-типы, способы сериализации и алгоритмы относятся к реализации; дальнейшие изменения DSL допускаются по конкретным обнаруженным ограничениям.

## Покрытие обсуждавшихся сценариев

| Сценарий | Есть способ общей постановки | Условие содержательного результата |
| --- | --- | --- |
| USB-пара | differential + impedance/TDR/SI/eye | Связанная геометрия, драйвер/приёмник, режим, согласованные порты |
| CAN | network/connect + SI | Терминации, трансиверы, заданная внешняя линия либо эквивалент на границе PCB |
| RP2040, питание от аккумулятора/USB, DC-DC | sources/loads + DC/PI/thermal | Явные режимы, потребление и потери; без автоматического зарядного алгоритма и связи преобразователя |
| RF-усилитель около 2 GHz | Извлечение PCB + многопортовая модель + networkParameters | S-параметры при заданной рабочей точке; малосигнальный режим, без автоматического насыщения/гармоник |
| DDR | Общий многолинейный SI + timing | Модели выводов/корпусов, терминация, DQS, раздельные сценарии чтения/записи; без протокола и обучения |
| Цифровая шина/дисплей | channels + drivers/receivers + timing | Согласованные переключения, электрические нагрузки и требования выборки |
| EMI сложной платы | excitations + coupling/conducted/EM | Заданные источники, возвратные пути и поддержанная физика; не автоматическая оценка всего изделия |
| Внешние помехи | Пространственный источник + измерение напряжения/поля | Предоставленная модель источника, положение/ориентация; для вывода о сбоях — критерии чувствительности |
| MOSFET и охлаждение | thermal/electrothermal + cooling | Потери, тепловой путь/инерция, характеристика охлаждения; без CFD |
| Печатная/внешняя антенна | antenna/scene + EM | Геометрия или подходящая EM-модель; одного S11 недостаточно для диаграммы |

Во всех десяти группах есть архитектурное место для постановки. Это **не 100% полноты DSL**, не 100% плат рынка и не доказанная численная поддержка. Некоторые группы требуют закрытия вопросов выше и значительной реализации. Под «симуляцией платы» надо отдельно понимать проверку выбранного аспекта и исчерпывающее моделирование изделия: второй цели текущий набор не обещает.

## Сложность платы и процент покрытия

Универсальный процент поддержанных плат нельзя вывести из списка методов: нет определённого множества плат, обязательного набора проверок, эталонов точности и бюджета расчёта. Значения вроде 80%/95% без этого были бы выдуманной статистикой. Исполняемая поддержка текущим экспериментальным Analysis DSL пока отсутствует, поскольку реализация не начата; это не характеристика возможностей существующих других инструментов проекта.

DSL не ограничивает постановку простыми или средними платами: сложная плата описывается несколькими сценариями и выбранными подсистемами с корректными граничными условиями. Число компонентов само по себе не определяет трудность: небольшая высокочастотная структура может требовать более глубокой модели, чем большая плата с медленными сигналами. Расчёт всей сложной платы full-wave, одновременной активности, пакетов, кабелей и корпуса не обещается.

Практическую оценку следует получать на согласованном наборе плат/сценариев: отдельно считать долю полностью описанных задач, успешно подготовленных моделей и результатов, прошедших критерии точности и ресурсов. Эти показатели не подменяют друг друга.

## Вопросы реализации после закрытия пользовательского контракта

1. Полнота экспорта RoutingBoardV2, связность/заливки/переходы, физические единицы, stackup и доступность данных.
2. Поддержанные классы геометрии, материалов и моделей, диапазоны применимости каждого метода.
3. Извлечение электрических и тепловых моделей и соединение с компонентами; без отдельного отклонённого механизма контроля перекрытия внешних моделей.
4. Частотные/временные решатели и электротепловая связь; устойчивость, сходимость и обработка ошибок.
5. Валидация на аналитических задачах, независимых решателях и измерениях с критериями точности.
6. Масштабирование: выбор области с сохранением возвратов, редукция моделей, кэширование, время и память.
7. Runtime JS/TS и граница Rust/Node: отмена, прогресс, лимиты, перенос результатов и воспроизводимость.

Контракт платы важен, но не является единственной или автоматически самой трудной задачей. Опубликованный метод ещё требует устойчивой реализации и доказанной применимости к фактической геометрии.
