# Thermal: согласованный критерий температурной сходимости

Решение пользователя от2026-10-24. Для двух сопоставимых решений ordinary и refined, в каждой проверяемой физической точке и моменте:

    abs(T_refined - T_ordinary) <= max(0.1 K, 0.01 * abs(T_refined - T_initial))

T_initial — исходная температура соответствующего физического узла/области. Для текущих TPS/Band сценариев это25°C. Используется абсолютная величина изменения, поэтому охлаждение также определено. Не подставлять текущую меняющуюся ambient вместо исходной температуры. Разница1K равна разнице1°C; это не1% абсолютной температуры по Цельсию или Кельвину.

Это критерий изменения температур при уточнении, НЕ гарантия ошибки относительно реальной платы или точного решения. Проверяется полное поддержанное поле, компактные узлы и обязательные временные наблюдения; отсутствующее покрытие не считается нулевой ошибкой. Временную и пространственную проверку вести отдельно. Ошибки материалов/мощностей/охлаждения отдельно от численной сходимости.

Прежние проверки энергии, невязки, связности, геометрии, устойчивости, finite values и ресурсные ограничения не ослабляются. Внутренний local-error controller не получает автоматически1% tolerance: это другой критерий. Пространственный2% guard пока сохраняется дополнительно; не заменять его механически на1% и не менять mesh settings ради PASS.

Исторический temporal0.1% FAIL TPS сохраняется как результат прежнего требования. По новому критерию сохранённая пара должна пройти (max absolute change0.010969778K<0.1K); подтвердить полной переоценкой массивов без повторного solve. Новое правило применять одинаково к будущим сценариям, не только к неудачной точке20s.
