# Следующее задание: численные сечения и однородные линии — P7a

База: [принятый P6b](../../evidence/frequency-networks-acceptance-2026-10-23.md), текущий общий addon и Analysis DSL. Реализовать первый законченный блок P7 из [плана](../../plans/implementation-plan.md), затем передать на ревью. Не переходить самостоятельно к произвольным PCB-каналам, via/PDN extraction, SI или TDR.

## 1. Пользовательский результат и границы

Пользователь задаёт геометрию однородной одиночной линии или симметричной пары через существующий `a.line()`, рассчитывает численное поперечное сечение через `a.impedance().method("cross-section")` и получает:

1. Ёмкость и внешнюю индуктивность на единицу длины; для пары — матрицы с взаимными связями.
2. Характеристический импеданс и задержку; для симметричной пары — even/odd и явно определённые differential/common значения.
3. При заданной длине — двухпортовую или четырёхпортовую частотную модель, пригодную для `a.networkParameters()` и `a.connect()` из P6b.
4. Визуальное сечение с проводниками/материалами, сетку, поле потенциала и сравнение сходимости; графики частотных характеристик и проверки в отчёте.

Это существенный численный этап: собственный field solver, модель распространения и законченный production DSL-путь. **Первый режим — lossless quasi-TEM с идеальными проводниками (PEC), немагнитными изотропными диэлектриками и идеальными опорными плоскостями.** Он нужен для проверки геометрии, импеданса и связи, но не предсказывает реальные потери в меди или FR-4. R=0/G=0 допустимы лишь как явно подписанные допущения этой идеальной модели; неизвестные потери реальной платы не становятся вычисленными нулями.

Обязательные публичные геометрии уже есть в LineInput: `microstrip`, `stripline`, `coupled-microstrip`, `coupled-stripline`. У пары одинаковые ширины, один сигнальный уровень, постоянный gap. Stripline допускает разные верхнюю/нижнюю толщины и проницаемости. Учитывать конечную толщину сигнальной меди геометрически. Маску в этом этапе можно явно отклонять; не принимать и затем игнорировать её. Отсутствующая маска означает модель без маски.

`channel`, `differential` по PCB, `method("layered")`, неподдержанный Resource и прочие будущие targets должны давать точный unsupported. Имя метода не разрешает подменить сечение одной эмпирической формулой. Полный P7, P6 и P11 этим этапом не закрываются.

## 2. Переиспользование и архитектура

Прочитать AGENTS/CHANGELOG, `numerical-architecture.md`, `implementation-structure.md`, DSL types/schema/context/prepare/executor, conduction geometry/mesh, P6b math/results, direct fixtures и audits.

- Rust CPU/F64, существующие faer/spade/rayon по реальной необходимости. Одна библиотека анализатора и один общий `.node`, прежние task/process/cancel/budget. GPU и общую compute-runtime не вводить.
- Внутреннее сечение: проводники с явными ролями/именами, диэлектрические области, reference, граничные условия и координаты в SI. Геометрия вне solver отделена от FEM-сборки; ядро оперирует набором проводников, а не отдельными формулами под каждый `kind`.
- Переиспользовать геометрические/матричные утилиты только при совпадении смысла. Электростатическая сетка заполняет диэлектрик, поэтому готовая DC-сетка только внутри меди не является сеткой сечения. Не рефакторить рабочий DC ради общего абстрактного solver.
- Подготовка геометрии/сетки, факторизация с несколькими RHS, извлечение C/C0 и распространение по длине — отдельные операции. Геометрия без дисперсии не решается заново для каждой частоты. При sweep длины можно повторно использовать неизменное сечение. Cache необязателен; при его наличии ключ включает все материалы/размеры/границы/численные настройки, cache ограничен и не влияет на ответ.
- Сохранять прямое соответствие полей/проводников/портов исходному описанию. Результаты и прежние handles неизменяемы.

## 3. Математическая постановка

### Электростатика

Основной метод: 2D FEM первого порядка на согласованной треугольной сетке для `div(epsilon * grad(phi)) = 0`. Границы материалов и металлические контуры — реальные constraints. На reference phi=0; для каждого сигнального проводника отдельная базисная задача 1 V при 0 V на остальных. Нулевой reference не объединяет произвольные реальные земли: это явно идеальная плоскость данного сечения.

Получить Maxwell capacitance matrix на единицу длины из интегралов энергии/реакций Dirichlet, с указанными знаками зарядов. Вычислить C с заданными диэлектриками и C0 на той же геометрии с вакуумной проницаемостью. Для внешней индуктивности идеальных немагнитных проводников использовать `L = mu0 * epsilon0 * inverse(C0)` через линейные решения. Внутреннюю индуктивность реальной меди эта формула не даёт.

Проверять симметрию, положительность энергии, остаток системы, зарядовый баланс с reference/внешней границей. Не исправлять ошибочный знак взаимной ёмкости через abs. Не обнулять связи малой величины без указанного допуска и оценки влияния.

В microstrip внешняя воздушная область конечна только численно: отдельно проверять увеличение области и уточнение сетки. Боковые границы stripline также должны быть достаточно удалены. Искусственная стенка не должна незаметно стать физическим экраном. Сохранять размеры области, тип границ и результаты обеих проверок сходимости. Сгущать сетку около кромок и малых gaps, контролировать качество/лимиты.

### Импеданс и распространение

Для одиночной линии `Z0 = sqrt(L/C)`, погонная задержка `sqrt(L*C)`. У симметричной пары использовать собственные even/odd параметры полной матрицы. Соглашения: differential voltage V+−V−, differential current (I+−I−)/2; common voltage (V++V−)/2, common current I++I−. Тогда `Zdiff=2*Zodd`, `Zcommon=Zeven/2`. Не смешивать эти величины с диагональю Z-матрицы или referenceOhm.

По L/C и длине построить lossless multi-conductor transmission line. Использовать проверенное модальное решение/эквивалентный устойчивый метод, не цепочку произвольно выбранных lumped L/C без оценки ошибки. Согласовать направления токов: порты на обоих концах направлены внутрь сети. Для `exp(+j*omega*t)` передача согласованной линии содержит `exp(-j*beta*length)`.

Порядок портов одиночной линии `input, output`; пары — существующий `positiveInput, negativeInput, positiveOutput, negativeOutput`. Получить полный 4×4 S, включая crosstalk, а не два независимых S21. Внутренняя нормировка может использовать P6b 50 Ohm; она не является вычисленным Z0 или добавленной нагрузкой.

Не строить результат обязательно через Z/Y: у идеальной линии на отдельных длинах/частотах эти представления сингулярны при корректной S. Lossless reciprocity/unitarity и конечность ответа проверяются, параметры не «ремонтируются» проекцией. P6b сохраняет собственные passivity/conditioning guards.

### Область применимости

Диэлектрики требуют явно заданных положительных relativePermittivity и `lossTangent: 0` для данного идеального этапа. Ненулевой lossTangent/проводимость диэлектрика, попытка задать частотную дисперсию или неподдержанные материалы дают явный отказ, а не игнорирование поля. PEC, отсутствие conductor loss/internal L/roughness и бесконечные идеальные опорные плоскости записываются в assumptions и provenance.

Указать проверенную quasi-TEM область в терминах поперечных размеров, материалов и частоты. Консервативный геометрический screening допускается только как эвристика, не как доказательство full-wave точности. Численная сходимость FEM не доказывает применимость quasi-TEM. Длинная однородная линия может быть электрически длинной: не применять ограничение lumped length<<wavelength к модели распределённой линии.

## 4. DSL и результаты

Сохранить существующие factories/builders. Пример целевого сценария:

```js
const a = analysis();
const line = a.line({
  kind: "microstrip",
  widthMm: 0.30,
  copperThicknessMm: 0.035,
  dielectricHeightMm: 0.18,
  lengthMm: 20,
  material: {
    relativePermittivity: 4.2,
    lossTangent: 0,
    state: "Explicit ideal dielectric hypothesis; PEC conductors, no mask",
  },
});
const z = await a.impedance()
  .target(line)
  .method("cross-section")
  .frequency({ startHz: 1e6, stopHz: 1e9, points: 101, scale: "log" })
  .run();
a.plot({ title: "Характеристический импеданс идеальной линии", data: z.characteristicImpedance });
a.plot({ title: "Параметры сечения", data: z.rlgc });
const r = await a.networkParameters()
  .network(z.network)
  .frequency({ startHz: 1e6, stopHz: 1e9, points: 101, scale: "log" })
  .representation("S").referenceOhm(50).run();
a.plot({ title: "Отражение линии при нормировке 50 Ом", data: r.parameter({ out: "input", in: "input" }).magnitude() });
a.plot({ title: "Передача линии", data: r.parameter({ out: "output", in: "input" }).phaseDeg() });
```

Это геометрический пример, не эталон 50 Ohm; не подгонять размеры/проверки под желаемый результат. Добавить аналогичный прямой пример пары и каскада извлечённой линии с Attenuator Pad.

- Без длины возвращать погонные параметры/Z0, а `delay` полной линии и `network` должны быть unavailable с объяснением; не подставлять условный метр. Семантику нулевой длины определить явно (предпочтительно отклонить), не делить на ноль.
- `characteristicImpedance`: для одиночной линии скаляр/серия Ohm; для пары таблица с именами even/odd/differential/common и единицами. `delay`: полная задержка в s, для пары по модам. Не усреднять разные моды в одно число.
- `rlgc`: таблица/structured data с порядком проводников, C в F/m и L в H/m; R/G помечены assumed zero для PEC/lossless, а не measured/extracted copper losses. Не присваивать всей смешанной таблице физическую единицу одного столбца. `segments` описывает один однородный участок и его происхождение.
- Численные поля, сетка, energy/charge/convergence diagnostics и фактическая область применимости сохраняются в solution; не добавлять отдельный публичный solver только для renderer. Структуру таблиц документировать и проверить audit.
- `network` использует тот же NetworkResource P6b с ровно рассчитанной частотной сеткой, портами и validity/provenance; последующая интерполяция по правилам P6b. Не выдавать coarse interpolated phase за точное повторное решение длинной линии: явно показывать сетку и conditional. За полосу не выходить.
- Для board-derived hypotheses результаты остаются conditional. Неуспех сетки/сходимости/применимости даёт unavailable/rejected, а не successful Z0=0. `a.check` сохраняет fail→continue.
- Прямой `a.connect({networks:[line,...]})` может оставаться unsupported: обязательный путь этого этапа через рассчитанный `z.network`. Не вводить скрытые параметры извлечения при подключении raw Line.

## 5. Независимые тесты и допуски

Обязательные группы:

1. Электростатический внутренний купон с аналитическим ответом (параллельные пластины с корректными боковыми BC либо коаксиальная область): C/энергия/заряд, единицы mm→m. Воздушное сечение: `L*C0=mu0*epsilon0` в скалярном случае и матричный аналог. Последнее — инвариант, не единственный oracle.
2. Microstrip/stripline: независимые опубликованные формулы/таблицы в их области применимости. Отдельно thin-conductor limit и конечная толщина; не сравнивать разные определения высот/толщин. Несколько width/height/epsilon, неоднородный диэлектрик stripline.
3. Пара: независимый опубликованный even/odd эталон, symmetry/reciprocity, перестановка проводников, изменение gap, слабая/сильная связь. Проверить знаки взаимных C/L, предел двух далёких одиночных линий. Численная связь не обнуляется по названию разных nets.
4. Раздельная сходимость mesh и truncation domain, сохранение C/L/Z0 и modal delay. Для принятого результата изменение Z0 и значимых C/L между двумя последними уровнями <=1%; для почти нулевых mutual entries нужен объявленный абсолютный floor относительно self terms. Если лимит не достигнут — явный отказ/непригодность, без повышения допуска постфактум.
5. На аналитическом field coupon целевая ошибка <=1%; сравнение инженерных формул microstrip/coupled в подтверждённой области <=3% с отдельным учётом точности эталона. Остаток линейной системы <=1e-8; энергия/заряд и symmetry проверяются с явными нормировками и допусками. Не объявлять эти числа универсальной точностью анализа реальных плат.
6. Модель распространения на заданных тестовых L/C: matched line S11≈0, S21 phase=−omega*delay, отражения на несогласованной линии, четверть/половина волны, изменение длины, полный 4-port независимый even/odd oracle. Точность algebraic complex S: 1e-8 relative + 1e-10 absolute; фазовые сравнения учитывать modulo 2*pi. Отдельно ошибка field extraction и propagation.
7. Reciprocity/unitarity, связь порта/знака/стороны, перестановка/каскад через P6b. Изменение referenceOhm не меняет C/L/Z0 и не добавляет сопротивление. Старый `result.network` не меняется при новой длине/геометрии; cache не возвращает устаревший ответ.
8. Негативные inputs: отсутствие epsilon/явного lossless описания, отрицательные размеры, касание проводников, маска/ненулевые потери, неподдержанный board target, неизвестные методы, выход за область, невозможная сетка, бюджеты/отмена/timeout и следующий успешный запуск.

Сравнение solver с самим собой или только ручным калькулятором по той же production-формуле не является независимым эталоном. Сохранить исходные опубликованные значения/геометрию/единицы, ссылку и пояснение воспроизведения versioned; сторонний solver не становится runtime-зависимостью.

## 6. Реальные платы и визуальные отчёты

Минимум три прямых named `impedance.js` + тонкие `.ts` launchers в существующем корпусе, например BandAmpV5, STM32G0_CAN_RS485 и ThunderF722 (допустима другая имеющаяся плата с более подходящим участком). Для каждого выбрать реальные track IDs/координаты/net/layer, проверить ширину и длину выбранного прямого участка по сохранённому V2. Для сценария пары нужны два реально существующих параллельных участка и проверенный зазор; имя USB/DDR не доказывает пару.

Параметры `a.line()` явно записываются в прямом DSL; versioned audit сверяет их геометрическое происхождение с V2. Helper не генерирует сценарий и не содержит field solver. Stackup/epsilon, если их нет в достоверном CAD-входе, задаются явно как гипотеза, а не «измерены по плате». Такой пример — анализ идеализированного участка по размерам платы, не автоматическая модель всего канала. Полный экспорт не менять ради прохождения эталона.

Отчёт должен показывать:

- обзор реальной платы с выделенными проводниками/участком и ID; исходные размеры против принятых моделью;
- поперечное сечение с масштабом, материалами, reference, граничными условиями; различать physical geometry и artificial outer boundary;
- сетку и phi/E для независимых возбуждений, energy/charge и таблицу сходимости;
- C/L, Z0 либо even/odd/diff/common и задержку с единицами;
- S11/S21, а для пары также cross-channel коэффициенты и фазы на общих частотных осях; явные PEC/lossless/stackup assumptions;
- versioned checks, один expected fail и следующий выполненный check/plot.

Audit проверяет текущие массивы полей/графиков, идентичности/порядок портов и проводников, единицы, происхождение геометрии, допущения, эталоны и сходимость. Negative audit tests: поменять ширину/gap, conductor IDs/order, epsilon, фазу/знак связи, удалить поле/plot/convergence, подменить conditional на достоверный результат реальной платы. Все такие ошибки должны выявляться.

Сохранить exact scripts/inputs/board hash/source-native hashes, JSON/audit, wall time/peak RSS, HTML и screenshots в ignored debugging; открыть отчёты и выполнить визуальную проверку. Не сохранять только красивые картинки без соответствующих numerical arrays.

## 7. Порядок работы, ресурсы и приёмка

Порядок: контракт внутреннего сечения/порты/границы → field coupons и FEM C/C0 → L/Z0/modes → finite line network → production DSL → независимые и отрицательные проверки → три board-derived сценария/audit/визуальная проверка. Не добавлять сначала публичные заглушки всех будущих геометрий.

До крупных выделений ограничить число узлов/элементов/проводников/RHS/итераций уточнения, размер внешней области, частоты/выходные матрицы и поля отчёта. Соблюдать budget/maxSeconds/maxMemoryMiB, ограничивать retained state и рабочую параллельность, не запускать неограниченный fan-out frequency×mesh. Прерывание native считать через имеющийся process lifecycle. Публиковать фактические caps и peak RSS; лимиты нельзя объявлять строгим OS memory cap без реализации.

Перед приёмкой исполнитель выполняет focused Rust/Node tests, релевантные регрессии P6a/P6b/DC, native build/typecheck/build/package и один итоговый прогон новых named fixtures. Старые тяжёлые корпуса повторять при влияющем изменении, иначе сохранить evidence/source parity. Записать команды/exit codes, hashes, допуски и честные границы в `line-cross-sections-verification.md`; обновить публичные типы, DSL reference, READMEs, architecture map и CHANGELOG.

Критерий готовности: все четыре вида LineInput рассчитываются собственным численным сечением; связь пары реальная матричная; соблюдены независимые эталоны и обе сходимости; `z.network` работает в P6b, включая каскад; три board-derived прямых сценария имеют проверенные визуальные отчёты и происхождение; неподдержанные входы/потери не игнорируются. Передать на ревью, новый этап/автоматический коммит не делать.

За пределами: skin/proximity/roughness/conductor losses, lossy/dispersive dielectric, via/antipad/plane gaps, автоматическое извлечение полного PCB path/PDN, finite-ground radiation, произвольные 3D/full-wave, fitting/FFT/TDR/time SI/eye/BER, компоненты/IBIS, placement/route changes, F32/GPU. Они остаются в плане, а не удаляются из согласованного состава.

## 8. Источники методов и сравнений

Использовать как научные/технические источники и эталоны, не подключать готовый simulator:

- [TU Hamburg CONMTL manual](https://www.tet.tuhh.de/wordpress/wp-content/uploads/2024/07/Manual-CONMTL-March-2020.pdf): связь внешней L с вакуумной C0 и представление многопроводной линии как multiport. При переносе выводов сохранять ограничения модели проводников.
- [Musa/Sadiku, FEM multilayer/multiconductor capacitance](https://www.comsol.com/paper/capacitance-computation-of-multilayered-and-multiconductor-interconnects-using-finite-element-method-5178): пример самостоятельного извлечения матриц сечения и сравнения с опубликованными данными.
- [Qucs technical: single microstrip](https://qucs.github.io/tech/node75.html) и [coupled microstrip](https://qucs.github.io/tech/node77.html): независимые инженерные формулы с указанной областью, не замена production FEM и не доказательство произвольной геометрии.
- [deal.II step-6](https://dealii.org/9.3.3/doxygen/deal.II/step_6.html): организация адаптивного FEM для эллиптической задачи. Оценка ошибки сетки не заменяет проверку открытой границы и применимости quasi-TEM.
