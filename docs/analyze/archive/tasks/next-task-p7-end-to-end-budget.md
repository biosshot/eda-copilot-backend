# P7: проверяемый сквозной бюджет и решение о закрытии

Утверждено пользователем 2026-10-30. Продолжение a51c8f0. Сначала доказательство выигрыша, затем положительный DSL-проход, затем очистка. Нельзя объявлять P7 завершённым по одному символическому прогнозу памяти.

## Ограничения

CPU/F64, текущая физика и direct sparse FEM. Без out-of-core, GPU, нового iterative solver, молчаливого обнуления L. Сохранить исходную медь/отверстия/контакты. Разрешено до8% итогового физического расхождения с независимыми эталонами; не складывать отдельные8% ошибок и не ослаблять residual/KCL/KVL/reciprocity/passivity. Геометрическая сегментация и HF-пробелы остаются частью честной матрицы закрытия.

## Работа

1. Реализовать компактный детерминированный nested-dissection порядок для текущего разреженного графа, предпочтительно используя координаты и фактические рёбра для построения корректных разделителей. Математическая матрица не меняется. Сначала доказать, что перестановка полная, а разделённые области не связаны ребром вне разделителя; проверить численный результат против прежнего порядка на малых SPD/FEM задачах. Не вводить большую новую зависимость без необходимости.
2. Сначала только символически сравнить текущий private-first AMD и новый порядок на сохранённом реальном STM32 запросе. Измерить fill, factor values, scratch, stage bound и время; остановить невыгодный вариант до большого numeric allocation. Не собирать несколько production альтернатив без выигрыша.
3. Если порядок даёт существенный выигрыш, выполнить реальный холодный DSL-проход, включая geometry/field/training/reduction/assembly/результат. Общее время и peak process-tree RAM фиксировать, не подменять временем kernel. Определить главную оставшуюся стадию. Сокращать избыточную детализацию только локально с проверкой нужных физических наблюдаемых. Не повторять уже отвергнутые trace3 и fullAMD эксперименты.
4. Проверить cold/warm/restart и cache invalidation; подготовка общих частей не повторяется без причины. Факторы/поля, не нужные для результата или восстановления, не удерживаются сверх нужной стадии.
5. Приёмочный ориентир пользователя: cold<=120s, peak<=4GiB (цель2GiB), warm<=5s, restart<=10s на согласованных сценариях. Режим OS paging разрешён для диагностики, но не заменяет доказательство штатного рабочего набора памяти. Если хостовая конкуренция портит время, обозначить это, не заявлять ускорение по несравнимым запускам.
6. Итоговая точность собранного канала <=8% проверяется целиком, включая задержку/порты/coupling/потери; старые7.79% и профиль5.63% сами по себе не подтверждают суммарный результат. Реальный STM32 должен завершиться положительно. Остальные обязательные RF/PDN/time/геометрические классы из next-task-p7-complete-channel.md нельзя молча исключать. Если они не реализованы/проверены, весьP7 остаётся открытым даже при удачной оптимизации.

## Очистка и сдача

Удалять только ставшие ненужными собственные экспериментальные ветки после принятия рабочего пути. Не удалять независимые физические эталоны и доказательства неудач, пользовательский native/analyze/debugging, исходные fixtures. Без git reset/clean/push. Документировать один выбранный путь и границы; сохранить исторические измерения как отчёт, не параллельные runtime реализации.

Прочитать AGENTS/CHANGELOG. Focused Rust tests, обычный native build, TS typecheck/build/cache/DSL tests. Одновременно только одна native сборка/тяжёлый расчёт. Результат: commit-ready изменения, runnable прямой DSL и визуализация, единый отчёт с исходной/новой памятью и временем, физической ошибкой и чётким статусом каждого незакрытого требования. Коммит после ревью родителя.
