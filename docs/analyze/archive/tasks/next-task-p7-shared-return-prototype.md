# P7: проверяемый прототип общих возвратных проводников

Статус: задание на ограниченный прототип, 2026-10-31. Не обещание закрытия P7.

## Цель

Проверить одну конкретную физически согласованную схему: связанные линии + общие конечные опорные проводники + локальные переходы. Выяснить, сохраняет ли она обход разрывов земли, распределение возврата между слоями и взаимные наводки при меньшей памяти, чем существующий объёмный путь. Промышленное применение гибридных методов подтверждает направление, но не точность нашей будущей реализации.

Прочитать AGENTS.md, CHANGELOG.md, implementation-plan.md, p7-memory-architecture-audit.md, p7-route-partition-results.md, p7-oriented-boundaries-results.md и действующий DSL. Изучить текущие section RLGC, local extraction и P6 composition до добавления кода. Использовать существующие библиотеки и физические примитивы.

## Границы и владение файлами

Агент formulation владеет новым native/analyze/examples/shared_return_prototype.rs, его подпапкой shared_return_prototype/ и отчётом docs/experimental/analyze/p7-shared-return-prototype-results.md. Это исполняемый Rust-прототип с повторяемыми проверками, не новая производственная ветка solver. Не менять src/, рабочие native/analyze/src/, зависимости, текущие DSL/контракты, общий CHANGELOG и implementation-plan. Если существующий публичный API не позволяет прототип, сначала описать точное препятствие; не начинать незапланированный перенос ядра.

Соседний агент независимо готовит benchmark manifest, эталоны и harness. Согласовать с ним машинный формат входа/выхода сообщением. Прототип не должен самостоятельно вычислять себе единственный эталон той же формулой.

## Последовательность

1. Сначала в отчёте зафиксировать выбранную формулировку: неизвестные, оператор, физические единицы, граничные условия, источники/контакты, частотную применимость и получение R/L/C/G либо портового оператора. Различать DC, квазистатику и распространение. Не применять CG к произвольной комплексной/неопределённой системе без доказанной структуры.
2. Явно описать связь линии с общей плоскостью и локальным multiport: потенциал/ток, сохранение заряда/мощности, опорные степени свободы, отсутствие двойного счёта self/mutual L/C. Не создавать независимую идеальную землю на каждый отрезок. Геометрическое продолжение широкой земли за бок коридора само по себе не основание отказа, но её разрывы/перемычки нельзя игнорировать.
3. Выбрать ОДНУ минимальную формулировку по первичным источникам и существующему коду. Не перебирать несколько solver, F32, порядков FEM и перестановок. Если согласованную формулировку в этих границах получить нельзя, завершить конкретным no-go с недостающим механизмом и обоснованием, а не фиктивным расчётом.
4. Реализовать прототип и пройти шесть семейств: широкая земля; край конечной земли; разрыв; несколько опорных плоскостей; переход с близким/удалённым возвратным via; две линии с общей землёй (в том числе узкой перемычкой). Для каждого фиксировать поддержанные/неподдержанные эффекты, диапазон и незамкнутые возвраты.
5. Проверить независимость от искусственного разреза/разбиения, физическую связность, взаимность/пассивность где применимо, сходимость и независимые эталоны агента benchmarks. Получить off-diagonal результат, не только собственный импеданс.
6. Только после малых контролей — ограниченные проверки на реальных 2/4/6-слойных fixtures, без изменения исходной меди/DSL. Если экспорт/геометрия мешает, сохранить конкретное свидетельство; не маскировать отказ как быстрый успех. Не объявлять полноценный DSL реализованным, пока проверяется лишь прототип.

## Измерения и приёмка

Сравнивать одинаковые геометрию, порты, материалы, полосу и наблюдаемые величины. Цель основного результата <=8% на объявленных метриках; приближённого <=15% только там, где есть независимая проверка. Это не разрешение ослаблять нынешние numerical guards. Для S возле нуля/слабых наводок/нулевой задержки заранее задать физически осмысленные абсолютные floors совместно с benchmarks. Не переносить low-band успех на GHz.

Отдельно: ошибка относительно эталона, неопределённость эталона, численная невязка, изменение при уточнении. Показывать полный и сокращённый размер системы, nnz, stored factor entries (если есть), оценку байтов и измеренные process-tree RSS/private commit, wall time по фазам. Для старого пути использовать сопоставимые сохранённые данные; несопоставимые сравнения явно помечать. Не обещать сокращение памяти по одному числу неизвестных.

CPU/F64. Прототип должен иметь пределы исполнения: предварительная оценка/host headroom, максимум 8 GiB на один процесс-tree и 600 s на попытку, либо меньший безопасный лимит по доступной памяти. Одна тяжёлая задача одновременно с benchmark-агентом; согласовать сообщением. Не увеличивать бюджеты и не повторять идентичные неудачные расчёты. Это предел эксперимента, не продуктовый SLA. При timeout сохранять стадию/измерения/ошибку. Не запускать многочасовые циклы.

Итог: схема с источниками, код, команды, JSON измерения и графики (геометрия/возврат/передача/наводки), таблица по всем случаям, go/no-go для интеграции и честные пробелы. Ни P7, ни P8/P11 readiness автоматически не закрывать. Не коммитить: сначала ревью родителя. Не удалять накопленные пользовательские изменения, native/analyze/debugging или исторические эталоны. Не запускать субагентов.
