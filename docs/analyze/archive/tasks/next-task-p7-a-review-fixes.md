# P7-A: две правки после ревью

2026-10-31. Пользователь разрешил выполнение. Это завершение проверок A, не новый solver, не закрытие P7 и не начало обработки широких возвратных проводников. Прочитать AGENTS.md, CHANGELOG.md и свой предыдущий отчёт. Сохранить все накопленные и пользовательские изменения.

## Агент p7_a_em_accuracy: R1 — физическая применимость эталона

Владение: `scripts/verify-p7-closure-baseline.ts`, `tests/analyze-p7-closure-accuracy.test.ts`, дополнение `docs/experimental/analyze/p7-a-em-accuracy-results.md`.

Воспроизведение: взять supplementalControls coupled-stripline из manifest, заменить topDielectricHeightMm на 0.1 и bottomDielectricHeightMm на 0.5. validatePhysicalReference ошибочно возвращает validated для исходного симметричного эталона 0.3/0.3 mm.

Исправить сопоставление физической геометрии: сравнивать положение и толщину проводников относительно обеих опор, а не только суммарный зазор. Проверить полноту необходимых полей, конечность и физически допустимые значения. Сохранить проверки ширины, зазора, толщины меди, материалов и неопределённости. Использовать явно определённую координатную конвенцию эталона; не расширять задачу до универсального нового формата моделей. При сравнении чисел учитывать только обоснованный допуск представления, не физический допуск 8%.

Приёмка:
- исходный finite35um reference принимается;
- 0.1/0.5 против 0.3/0.3 отвергается;
- смещение conductorYMm, неверная опорная геометрия, отсутствующие/nonfinite необходимые данные отвергаются понятной диагностикой;
- прежние negative tests проходят;
- сохранённое положительное сравнение повторно проверено без нового численного решения, с проверкой исходных hashes. Обозначить replay, не cold run.

Не менять эталон или физические входы ради прохождения. Новый FEM/FD прогон не нужен, если меняется только валидатор. Отчёт: что исправлено, команды, результаты, границы принятого малого контроля.

## Агент p7_a_dsl_validation: R2 — тест настоящего превышения допуска

Владение: `tests/analyze-p7-closure-execution.test.ts`; минимально необходимый test seam в `scripts/verify-p7-closure-stripline.ts`; дополнение `docs/experimental/analyze/p7-a-dsl-validation-results.md`. Другие файлы только после согласования с родителем.

Воспроизведение: первая итерация теста threshold excess возвращает validation-failure/INVALID_VALUE. Базовая S-матрица нулевая, поэтому ABCD-преобразование делит на ноль. Этот тест не доказывает, что превышение допуска само приводит к nonzero exit.

Создать минимальный полноценный, конечный вход для subprocess comparator: ненулевая передача, корректные metadata/field/modes. Сначала подтвердить, что неизменённый контроль проходит реальный comparator с exit 0. Затем изменить ровно один сравниваемый показатель так, чтобы превысить допуск, и проверить exit != 0, status fail и конкретную метрику/error сверх порога. Это тест механизма проверки, не независимый физический эталон. Не привязывать unit tests к ignored debugging-файлам и не запускать solver для каждого negative.

Приёмка:
- положительный subprocess control действительно pass;
- threshold negative возвращает именно comparison fail, без INVALID_VALUE/NaN/ошибки схемы;
- остальные malformed cases проверяют ожидаемую причину, а не только произвольный nonzero;
- прежние supervisor negatives и focused tests проходят;
- production/native/физика сохранённого DSL не меняются.

## Общие ограничения и проверки

Не менять production, native, зависимости, manifest, чужие отчёты, общий roadmap/CHANGELOG. Не пересобирать addon, не запускать большие STM32/магнитные расчёты. Никаких субагентов, коммитов, очистки чужих файлов или новых этапов. Каждый запускает свои focused tests; DSL-агент один выполняет typecheck/build после изменений и сообщает результат соседу. Если появится реальная необходимость нового numerical run — сначала объяснить родителю причину, не повторять сохранённые удачные измерения автоматически. Завершить собственный отчёт и остановиться для ревью.
