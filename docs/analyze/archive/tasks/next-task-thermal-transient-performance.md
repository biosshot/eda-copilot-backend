# Thermal: измерить и устранить узкое место transient

Исполнитель thermal_medium, worktree analyze-thermal. Оба tighter запроса предыдущей задачи завершились THERMAL_DEADLINE600s; временная сходимость не подтверждена. Новый этап — производительность, а не повышение лимита или ослабление физики.

## Сначала измерение

- По сохранённым ordinary отчётам и исходникам установить работу каждого из 7 solve stages. Имеющиеся общие phase wall times не считать временем factor/CG.
- Добавить внутреннюю ограниченную диагностическую инструментализацию: mesh/assembly, symbolic/numeric factorization, preconditioner application, CG iterations, accepted/rejected time steps, repeated matrices, output/comparison. Диагностика не должна превращать неуспешный результат в complete. Не менять DSL или гарантии partial fields.
- Снять одно bounded измерение TPS tighter: до 120s, сохранив counters при отмене/таймауте без больших массивов. Разрешается меньший диагностический coupon для разделения факторов; такой coupon не является приёмкой реальной платы. Сохранённые источники/физические параметры обязательны.

## Исправление по измерению

Реализовать только обоснованное устранение крупнейшего повторения/затраты: безопасное переиспользование структуры или факторов при точном равенстве матрицы, улучшение preconditioner/assembly либо другое измеренное узкое место. Уже отвергнутый single-slot cache не возвращать без новых данных. Не удалять spatial solves или обязательные события, не менять физику, tolerances, сетку, output coverage и resource accounting. Cache key должен охватывать все параметры матрицы; отдельные проверки invalidation и memory ownership.

Если измерение не даёт безопасного улучшения — выдать конкретный proposal с цифрами, без нового большого запуска. Не принимать заранее 3600s/1536MiB controller candidate.

## Приёмка и ограничение запусков

- Малые аналитические/событийные/отрицательные tests; counters имеют понятные единицы, не меняют числа. Сравнить baseline/candidate на одном заранее выбранном малом случае с идентичными настройками; не ухудшать физические guards и memory peak.
- Только после измеренного выигрыша и preflight <=600s разрешены по одному TPS tighter и Band tighter на прежних 384MiB/50k/2M/128MiB, без повторов. Сравнить с сохранёнными ordinary полными полями: прежняя temporal gate <=0.1%, spatial <=2%, missing=0 и прежние nodal/energy guards. Если меняется numerical result ordinary, доказать неизменность или остановиться с необходимостью новой пары; не смешивать несопоставимые данные.
- Полные real runs максимум два; controller/curve не запускать. Не увеличивать deadline ради зелёного результата. Сохранить ошибки, наблюдаемое wall/RAM, исходные hashes, локальные графики времени/полей и отчёт.
- Тяжёлые операции согласовать с P6/P7; изолированный target, jobs=1. Общие TS API, электрические модули и placement не менять. Без коммита/новых агентов. После отчёта остановиться, весь P9 не закрывать.
