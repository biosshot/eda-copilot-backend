## 1. Зафиксировать сравнения до запуска

Переиспользовать field_observable_check, saved-real-field-basis-v1.json и field-refinement-request-v1.json. Уточнённый вариант считать кандидатом, не истинным решением. Исходный грубый результат сохранить.

В небольшом JSON заранее записать ровно два дополнительных сравнения:

- **Сетка:** граница остаётся 8 мм; maxVerticalStepM 0,5→0,25 мм, interfaceStepM 25→12,5 мкм, прежний growth. Сохранить исходную медь, контакты и XY-представление. Это проверка вертикального уточнения; не выдавать её за проверку всех направлений сетки.
- **Граница:** отодвинуть внешнюю границу 8→16 мм при неизменных узлах/разрешении в ближней области кандидата. Проверить, что генератор не перетриангулировал ближнюю область существенно. Если такое сохранение технически недоступно, явно пометить сравнение как смешанное, не приписывать весь эффект границе.

Все 17 исходных частот, все четыре элемента Z; общая нормировка с прежним абсолютным floor. Сравнить также матрицу ёмкостей связных проводников и энергию независимых возбуждений. Отдельно показать общий ёмкостный вклад и ограничения оценки сквозного режима по разности огромных Z. Не объявлять такую разность точным сквозным измерением.

Не переобучать магнитный базис: это проверка электрического оператора в сохранённом подпространстве, а не независимое доказательство точности полной модели. Записать это в результатах. Каждое диагностическое выполнение ограничить 300 с и 2 ГиБ, включая процесс; сборку учитывать отдельно. При отказе бюджета/геометрии не начинать поисковую кампанию.

## 2. Независимый эталон электрического оператора

Сначала найти уже существующие аналитические/эталонные тесты и переиспользовать их. Нужен хотя бы один проверяемый эталон, который проходит через тот же production FEM/charge-energy путь, а не отдельную игрушечную формулу в обход решателя.

Предпочтительный простой эталон: однородный коаксиальный конденсатор с C/L = 2*pi*epsilon/ln(b/a). Для конечного 3D участка условия на торцах должны точно реализовывать z-инвариантную задачу (нулевой нормальный поток), внешний цилиндр — физический grounded conductor. Не сравнивать открытый конечный цилиндр с бесконечной формулой без учёта торцевого поля. Радиусы, длина, epsilon, аппроксимация окружности и условия записать явно. Если текущие утилиты не позволяют такой пример без нового инфраструктурного проекта, взять существующий аналитический тест с точно совпадающими граничными условиями и объяснить выбор.

Нужны аналитическое C, численное C из заряда и энергии, ошибка, charge balance, две заранее выбранные сетки. Допуск физической величины <=5%; численные guards не ослаблять. Тест должен проверять ненулевое неоднородное поле, по возможности и межслойный диэлектрик отдельным уже существующим тестом. Успех простого эталона не означает автоматическую приёмку STM32.

Пользователь также предложил опубликованный лабораторный эталон. Выполнить короткий поиск первичных источников (максимум 3 поисковых запроса), записать пригодность: полная геометрия, epsilon/материалы, частота, контакты/guards, измеренное значение и неопределённость. Пример настоящей метрологии — конденсатор Томпсона–Лампарда NIST:
https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication250-76.pdf
https://pmc.ncbi.nlm.nih.gov/articles/PMC4865284/
Не объявлять воспроизведением лабораторного измерения сравнение только с аналитической формулой. Не строить сложный NIST эталон в этой задаче. Если воспроизводимого простого измерительного набора нет, прямо сказать; аналитическая проверка обязательна и достаточна для этой части задания, лабораторная валидация остаётся отдельной.

## 3. Сдача и решения

Обновить checkpoint отдельным текущим разделом, не переписывать историю. Таблица: грубый, кандидат, уточнение сетки, удаление границы; C, Z, ошибки/различия, время/RSS. Визуализации: геометрия/граница и сравнение C/частотного Z; подписать, что это проверка сходимости, а не истинная ошибка 88,8%.

- Если оба новых сравнения дают <=5%, назвать кандидата стабильным по выполненным проверкам, но не объявлять полную погрешность <=5% автоматически: направления уточнения, фиксированный базис и независимая валидация ограничивают вывод.
- Если эталон не проходит, локализовать расхождение до сборки/границ/заряда/энергии. Допустимо одно небольшое доказанное исправление с регрессией; после изменения повторить затронутые сравнения. Никакой смены семейства метода.
- Если эталон проходит, а STM32 нет — сообщить конкретную чувствительность и остановиться. Не делать вывод «виноваты порты» без свидетельств, не расширять задание самостоятельно.

Focused тесты по изменениям, стандартные требования AGENTS к native changes. Не запускать полный дорогой магнитный sweep. Можно сделать тематические Conventional Commits только проверенных изменений, без push, перечислить точные команды/хеши/оставшийся git status. Не объявлять P7 закрытым и не выдавать следующие задания. Итог родителю: верен ли кандидат по доступным свидетельствам, что проверено независимо, какой ровно пробел остался.
