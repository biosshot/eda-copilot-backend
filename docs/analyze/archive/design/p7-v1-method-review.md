# P7: историческое ревью вариантов перед очисткой c9312e1

Исторический снимок до удаления альтернатив. Действующее состояние: [single-method checkpoint](../../evidence/p7-single-method-checkpoint.md); текущий лимит300s/2GiB/5%. Указанные ниже120s измерения и архитектура относятся к тому снимку.

## Решение пользователя

Память до 2 ГиБ, холодный сквозной запуск до 120 секунд, физические наблюдаемые до 5% (цель 1%). Это заменяет старые 512 МиБ и обязательную высокую точность всех внутренних координат при приёмке v1. Исторические численные результаты и отказы не переписываются.

## Архитектурное ревью

Рабочая база остаётся c3b436e; новые volume-модули и изменения P6 ещё не приняты. Это целевое ревью архитектуры и критериев, не доказательство корректности каждого нового kernel.

1. `volume_magnetic` содержит P1, higher-degree, interior bubbles, entity patches и iterative patch варианты. `volume_tensor`/`tensor_potential` — самостоятельный альтернативный магнитный путь. `volume_integral`/`volume_surface`/compensated/cache — третье семейство. Все ещё подключены к local module и диагностическому dispatch. Несколько независимых методов нужны эталонам, но не production dispatch.
2. `board_volume` смешивает mesh construction, экспериментальные конфигурации, cache transport, обучение редукции, P6 и печать результатов. Runtime board→worker→DSL отсутствует; добавление `viaId` и слоёв контактов само по себе его не реализует.
3. `volume_field::DenseField` обязательно строит полный Schur по исходным координатам. Полная матрица полезна как эталон, но принудительная материализация каждого столбца для каждого пользовательского сценария — лишнее требование. Эквивалентный apply/Gram для нужного подпространства предпочтителен при независимой проверке наблюдаемых и recovery.
4. `board_volume` печатает maxCurrentCoordinateError/maxCellLossError с масштабом почти нулевых координат 1e-12 от максимума. Такая диагностика не должна определять пользовательскую точность v1. Сам `fullChecks.push` не является приёмкой физических ошибок; нулевой exit code диагностического example также не означает физический PASS.
5. Изменён общий `coupled::System`: charge-coordinate fallback при residual/power failure и cache invalidation после нагрузки. Это изменение принятого P6, а не локальная оптимизация P7. Перед объединением требуется отдельный focused regression набор.
6. Сетки и sparse/factor accounting содержат полезную общую работу. Раннее удаление файлов без dependency inventory опасно; сначала выбрать единственный runtime dispatch, затем убрать неиспользуемые experiment ветви, сохранив reference tests.

## Ограниченное сравнение

Одинаковый original STM32 JSON и `STM32-rs485-three-terminal-air2-request.json`, реальные finite контакты. Это небольшой three-terminal via+return-conductor ROI, не исходный двухпереходный канал и не доказательство масштабирования. Холодный запуск включает mesh/C/magnetic/training. Оба кандидата используют одну и ту же грубую C-модель, которая пока не имеет физической приёмки; сравнение проверяет вычислительную жизнеспособность, а не утверждает 5% точность.

Команды: `board_volume <board> <request> entity:6:8:16:3 train` и `... tensor:6:8:16 train`. Параметры фиксированы до запуска, не подбирались под результат. Первые diagnostic launches с недопустимым exterior order9 сохранены отдельно как ошибочная конфигурация, не performance evidence. Повтор v1 использует допустимый order16.

Сборка отдельно: single-job release с существующим package opt-level=1, 15.65s. Это не стандартная итоговая addon-сборка. В диагностическом example изменён только byte budget на 2 ГиБ, прежние max_nodes/tetra counts сохранены. Никакие физические или numerical guards не ослаблены.

Факты и hashes: `debugging/p7-board-integration/review-2gib-comparison-v1/{direct-fem,tensor}/run.json`, stdout/stderr. Supervisor запускает последовательно, ограничивает живой RSS family до 2 ГиБ и wall до120s; sampling .02s. Планируемые allocations дополнительно проверяет Rust.

Прямой FEM: timeout120.079s, peak RSS1025654784 bytes (~978.14MiB), factor plan1606358337 bytes. Обе training port задачи успели пройти KCL/KVL/power, но полного выхода/holdout результата нет. Метод не принят по времени или физической точности. Увеличение памяти разрешило прежний factor refusal, но не весь сквозной сценарий.

Тензорный:111.484s, peak RSS94924800 bytes (~90.53MiB), exit1: `tensor lifetime deadline`. Начальные training решения прошли KCL/KVL/power, но полный train/holdout не завершился. Это внутренний deadline, а не успешное завершение за120s; 5% физической точности этим запуском не доказаны. Оба кандидата имеют нечисловую итоговую ошибку: сравнивать скорость получения принятого результата невозможно, потому что принятого результата нет. Два запуска не являются exhaustive tuning; дальнейший перебор степеней/звёзд запрещён текущим решением.

## Ограничения выбора

Проход frozen3-current контроля не доказывает точность реальной платы. Совпадение native/SciPy на одной сетке не заменяет пространственную/доменную сходимость. Исторический coherent-source-subset148 witness отвергал tensor10x10 (в том числе self-energy16.7864%); это не переносится численно на новую конфигурацию, но запрещает объявлять тензорный метод точным по скорости primitive test.

Физически приемлемый победитель может быть объявлен только после реальных наблюдаемых проверок <=5% и времени<=120s. Если оба новых запуска не проходят, честный итог — победителя нет. Приоритет ограниченной дальнейшей работы: existing direct FEM как кандидат с уже наблюдавшимся решением физических training equations. Это направление интеграции, не приёмка и не обещание скорости. Новые методы не исследовать; задание next-task-p7-single-method-v1.md задаёт предел доработок и остановки.
