## Структура

```
docs/analyze/
  README.md                  этот индекс
  plans/                     живые планы и handoff
  reference/                 справочники и семантика
    dsl/                     контракт, справочник, матрица реализации, сценарии
    input/                   RoutingBoardV2, аудит входа
    p4-geometry/             геометрия, экспорт, валидация
    p5-p6-electrical/        электрическое ядро и частотные многопорты
    p7-extraction/           сечения, потери, HF-оператор, paging
    p9-thermal/              тепловая политика
    architecture/            численная архитектура, структура, корпус, библиотеки
    scope/                   каталог анализов, глубина, границы
  evidence/                  приёмки, результаты, ревью, контрольные точки (датированные)
  archive/tasks/             выполненные задания next-task-*
  archive/design/            черновики периода 2026-10-19…10-23, заменённые решения
  archive/handoffs/          предыдущий handoff
```

Правила:

- **Живой документ один на тему.** Остальное — датированный evidence, он не переписывается.
- `plans/` обновляется по статусу; `evidence/` — только добавляется.
- У живого документа в шапке должны быть: статус, дата обновления, что он заменяет.
- `reference/dsl/dsl-reference.md` — спецификация, а не статус. Фактическая реализация — только в
  `reference/dsl/dsl-implementation-status.md`.

## Статус документации на 2026-11-05

Заменяет сводку статусов 2026-11-04; исторические evidence сохраняются.
**P7 v1 закрыт 2026-11-11 в суженном определении ([план закрытия](plans/p7-v1-closure-plan.md), раздел 5); физическая приёмка по эталонам (P7-R) и вся case-matrix остаются открытыми.**
**P7-R (высокая полоса): работа остановлена на шаге 4.2.1 (2026-11-14). Режимы за переключателями `P7_*`; с 2026-11-14 рабочий набор включён по умолчанию (явный `0` возвращает прежнее поведение, `P7_BAND_SCREEN` по-прежнему выключен); физика `unverified`, внешнего эталона нет; канал BandAmp RF_IN отказан планировщиком, каскад в DSL не подключён (P11). Итог и ограничения — [записка закрытия](evidence/p7-r-closure-2026-11-14.md).**
**P7-completion закрыт 2026-11-21 ([итог](evidence/p7-completion-summary-2026-11-21.md), матрица `tests/pcb-analyze/p7-matrix.json`): каскад каналов в DSL включён по умолчанию (`P7_CHANNEL_CASCADE=0` выключает) (BandAmp RF_IN/RF_OUT до 1 ГГц `complete`), TPS pi() по всей сетке `complete`, DC→тепло на плате через `idleNets`; STM32G0/BandAmp pi() на полной сетке и каналы M8/M9 — названные отказы. Физика `unverified`.**
Нормативный контракт — [план P7](plans/p7-plan.md), актуальные ограничения —
[матрица случаев](reference/p7-extraction/p7-case-matrix.md).

Реализованы 2D-сечения и локальные 3D-блоки с композицией, N-port planner,
`.si().channels([...])`, mixed foil/volume, конечные контакты и независимые острова,
компоненты, автоматическое проводящее разбиение и exact-grid кэш. Эти механизмы
не означают готового и принятого автоматического маршрута для каждого случая.
Гибридная сборка применяется к допустимым коридорам; общий auto-foil/mixed путь
сохраняет совместные поля и проверки исходных объёмных координат. Проводящее
разбиение не заменяет их независимыми локальными EM-задачами.

Полная геометрия STM32 проходит подготовку. Адаптивный магнитный оператор
реализован и проходит малый эталон, но действие на двух физических распределениях
токов полной платы не завершилось за **1800.047 с**. Пик private памяти native
поддерева незавершённого прогона — **1 328 381 952 Б (~1,24 ГиБ)**. Это не пик
завершённого действия и не оценка полного экстрактора. Сертификат ошибки действия
и полный AC-ответ канала не получены; требование по времени **не выполнено**.
[Подробности и проверки](evidence/p7-adaptive-magnetic-2026-11-05.md).

Физическая приёмка case-matrix, общая подтверждённая полоса section/local,
реальные каналы/PDN и пять обязательных плат остаются открытыми. Частные приёмки
сечений и coupon-контролей действуют только в собственных условиях; корректный
отказ или присутствие геометрии в сетке положительный случай не закрывают.

CPU/F64 и экономия памяти сохраняются. Необходимый иерархический/адаптивный
магнитный оператор был отдельно разрешён для устранения ресурсного блокера;
поэтому прежнее откладывание глубокой оптимизации не означает, что время уже
приемлемо. Переход via на 2.5D отложен, P8/P11 и fast/F32 не начаты в этой работе.
После фиксации результатов численные прогоны остановлены по согласованному объёму.

## Как добавить документ

1. План или задание — `plans/`; задание обязательно парой с будущим `*-results.md`.
2. Результат, приёмка, ревью — `evidence/`, имя с датой.
3. Справочник или спецификация — `reference/`; статус реализации туда не писать.
4. Завершённое задание и заменённый черновик — `archive/`.
5. Обновить этот README, если изменился статус или точка входа.
