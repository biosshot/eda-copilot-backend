# P7-R: рабочий план до 1 ГГц без full-wave

Статус: черновик 2026-11-12, на решение пользователя. Это пошаговая инструкция для исполнителя. Обоснование и проверенные факты — в [плане высокой полосы](p7-r-highband-plan.md), диагноз по прогонам — в [плане полосы](p7-r-band-plan.md).

Цель: каналы до 1 ГГц каскадом, плата целиком до границы квазистатики. Запаздывание в ядре, полноволновой расчёт и 10 ГГц в этот план не входят.

## 1. Правила работы

1. Перед правкой прочитать `CHANGELOG.md` и корневой `AGENTS.md`. Править только файлы, названные в шаге.
2. Каждое новое поведение включается переменной окружения и по умолчанию выключено, как `P7_FOIL_SHEET`. Значения по умолчанию меняет только пользователь после проверки этапа.
3. Шаги идут по порядку. Следующий этап начинается после пройденной проверки предыдущего.
4. Физическая точность остаётся `unverified`. Слова «подтверждено» и «accepted» в отчётах не использовать.
5. Итог каждого этапа: строка в `CHANGELOG.md` (`Unreleased`) и файл `docs/analyze/evidence/p7-r-highband-<этап>-<дата>.md` с командами, числами и путём к логам. Логи лежат в `debugging/p7-r/h/`.
6. Коммит — только если пользователь разрешил коммиты в этой сессии.

### Когда остановиться и спросить

- Шаг требует править файл вне списка или менять критерий приёмки.
- Проверка этапа не прошла после двух попыток правки.
- Средний прогон идёт дольше 15 минут или просит больше 4 ГБ.
- Разбор кода расходится с тем, что написано в шаге.

## 3а. Этап 0.5. Иглы в стенках via (добавлен 2026-11-12 по итогам этапа 0)

[Итог этапа 0](../evidence/p7-r-highband-stage0-2026-11-12.md): со 2-й по 16-ю итерацию худшая строка KVL — одна и та же ячейка ствола 2141 с сопротивлением 32,9 кОм. Она же задаёт общий масштаб, поэтому KVL держится около 1 независимо от решателя. До её устранения этап 1 оценивать нельзя.

Причина по коду: `barrel_segments` в `mixed_conductor.rs:370` принимает любой столбец стенки с площадью треугольника больше нуля. Для листов правило «шум» есть (`mixed_conductor.rs:708-718`), для столбцов стенки его нет. Столбец-игла электрически параллелен соседним столбцам той же стенки, его проводимость ничтожна.

Файл: `mixed_conductor.rs`.

| Шаг | Работа | Готово, когда |

| 0.5.1 | Проба без правки поведения: для каждого ствола вывести число столбцов, наименьшую и медианную площадь треугольника, длину отрезка; посчитать столбцы с проводимостью меньше 1e-6 от суммарной проводимости своего ствола | в evidence: сколько игл на плате и подтверждена ли площадь ствола 2141 |
| 0.5.2 | Переключатель `P7_BARREL_NOISE=1`: столбец стенки с долей проводимости меньше 1e-6 своего ствола не получает токовой моды и идёт по существующему пути игл (`sliver_cells`), с учётом в `dropped_volume` и `quality.sliverPolicy`. | 0.5.3 | Один средний прогон 700 кГц (кэш H-матрицы: сетка та же, если ключ кэша не изменился — проверить по логу) | в evidence: новая худшая строка и история KVL |

## 4. Этап 1. Устойчивое решение

Файл: `foil_reduced.rs`. Образец малого итерационного решателя: `compact_cg.rs`.

Сейчас в `grow_phases` кандидат равен `−R⁻¹·невязка` для каждой фазы отдельно. Это работает только при ωL/R ≲ 1.

| Шаг | Работа | Готово, когда |
|---|---|---|
| 1.1 | Переключатель `P7_ENRICH_INDUCTIVE=1`. Вместо `drop = kvl / R` приближённо решить `(R + jωL)·d = r` для пары фаз невязки: GMRES на существующем магнитном действии (`magnetic`), не более 30 действий, останов при падении невязки в 100 раз. Дальше без изменений: DC-поправка `dc.solve`, `candidate = conductive(bubble) − d` для вещественной и мнимой части | купон: история KVL не хуже прежней; 700 кГц: KVL падает от итерации к итерации |
| 1.2 | Только если развилка 0.4 показала медь без тока в базисе: добавить в стартовый базис по одному вектору на каждый такой остров — решение 1.1 для начальной невязки | худшая строка уходит с этого острова |
| 1.3 | Переключатель `P7_ENRICH_MAX=<число>`: предел итераций вместо 16 и согласованные пределы числа векторов (`growth`, `voltage_cap`, `current_cap` в `solve_compact_adaptive`). Останов по правилу `enrichment_continues` | прогон с пределом 64 не падает по `MEMORY_LIMIT` |
| 1.4 | Убрать квадратичный рост времени `grow` (26 с за 16 итераций): в `append_current_mode` не пересчитывать `resistive_action` всего базиса на каждый вектор, хранить рядом с базисом | `grow` растёт линейно |

Запасной вариант, если 1.1 не даёт падения за два захода: остановиться и спросить. Не начинать GMRES на полной системе без решения пользователя.

Критерий KVL (максимум по ячейкам) в этом этапе не менять.

Проверка этапа (дорогая, один раз): band-step на 100 кГц и 700 кГц с `P7_FOIL_SHEET=1`. Оба выдают модель с KVL ≤ 1e-3; 100 кГц не более 19 итераций. 1 МГц запустить и записать результат, провал на 1 МГц этап не блокирует (его чинит этап 2).

### Поправки к этапу 1 по итогам шага 1.1 (2026-11-12)

Итог шага 1.1: с `P7_ENRICH_INDUCTIVE=1` на 3 МГц KVL падает втрое быстрее (7,4e-3 против 2,2e-2 на 17-й итерации), но модель не выдаётся. Внутренний GMRES с предобуславливателем `R⁻¹` за 30 действий снижает невязку только в 2,4–3,2 раза.

Причина в самом шаге 1.1 этого плана: в нём не был задан предобуславливатель. `R⁻¹` слаб именно там, где нужен: при ωL ≫ R оператор близок к `jωL`, и `R⁻¹` его не выравнивает. Откладывать 3 МГц до этапа 3 бессмысленно: этап 3 меняет модель меди по толщине, а не сходимость, и с ростом частоты до 40 МГц сходимость будет только хуже.

Дальше идти по лестнице (согласовано пользователем 2026-11-12). Каждая ступень — одна правка, одна пересборка, один прогон 3 МГц (около 3 минут). Следующая ступень — только если предыдущая не дала модель на 3 МГц за 30 внешних итераций. Режим `=2` больше не развивать.

| Ступень | Файлы | Работа |
|---|---|---|
| A | `foil_reduced.rs` | `P7_ENRICH_GMRES_MAX` (по умолчанию 30): прогон с 120. В evidence записать падение невязки GMRES на 30, 60, 90, 120 действиях |
| B | `foil_reduced.rs`, чтение `mixed_conductor.rs` | Диагональный предобуславливатель `(R_j + jω·L_jj)⁻¹` вместо `R⁻¹` (режим `P7_ENRICH_INDUCTIVE=3`). `L_jj` — собственный член ячейки: по опорам ячейки из `planar_current_supports`, `barrel_current_supports`, `local_current_supports` сумма `|v|²·L_опоры`, где `L_опоры` — собственный элемент ядра (`Kernel::entry(s,s)` или существующий точный собственный интеграл). Комплексное деление выполнять как блок 2×2 на пару фаз |
| C | `foil_reduced.rs`, `planar_hmatrix.rs` | Блочный предобуславливатель (режим `=4`): для каждого диагонального плотного листа H-матрицы (до 16 опор) собрать `R + jωL_лист` в пространстве токов ячеек и разложить один раз на частоту; применять поблочно. Ячейки вне плоской H-матрицы (локальные тетраэдры) — по ступени B. Из `planar_hmatrix.rs` открыть только чтение диагональных плотных блоков и порядка опор |

Критерий ступени: 3 МГц выдаёт модель с KVL ≤ 1e-3 не более чем за 30 внешних итераций. Критерий купона смягчён: число итераций на 100 кГц и 1 МГц не больше прежнего плюс 2, замер на итоговой версии кода.

После первой прошедшей ступени: band-step на 100 кГц, 700 кГц, 1 МГц, 3 МГц и 10 МГц с выбранным режимом (10 МГц — только запись результата, при `t/δ > 1` идёт послойная сетка и отказ допустим). Затем пять плат один раз, с итоговым набором переключателей.

Если не прошла и ступень C — остановиться и спросить; пять плат в этом случае запускаются с потолком 1 МГц.

### Итог лестницы и шаг 1.1д (2026-11-12, проба согласована пользователем 2026-11-12)

Ступени A, B, C не прошли: KVL на 3 МГц останавливается на 1,55e-2…1,69e-2 при любом качестве внутреннего решения. Evidence: `docs/analyze/evidence/p7-r-highband-ladder-2026-11-12.md`.

Что видно в логах (проверено по `P7_COMPACT_GRID_STEP`):

- Лучший результат (7,4e-3) дал не «индуктивный кандидат везде», а смесь: в попытке 1 шага 1.1 было всего 5 индуктивных решений (итерации 0–4), дальше шло прежнее правило `−R⁻¹·r`. Ступень A применяла индуктивный кандидат на всех итерациях и вышла хуже. Странности здесь нет: это разные алгоритмы.
- Оценка неопределённости магнитного оператора (`maxKvlUncertaintyRelative`) на 3 МГц равна 6,1e-3 и растёт с частотой (1,7e-3 на 700 кГц, 2,4e-3 на 1 МГц). Плато 1,6e-2 лежит в 2,6 раза выше неё, цель 1e-3 — в 6 раз ниже.
- На плато худшие строки — одни и те же треугольники на TOP и BOTTOM (5351, 5336, 5339, 5363). В них `gradientTerm` и `omegaLTerm` почти гасят друг друга, `resistanceTerm` на три порядка меньше.

Три возможные причины, не разделённые:

1. Оператор не линеен на уровне своей неопределённости (точность ближних пар подбирается по столбцу). Тогда решение GMRES верно для своих векторов, но после добавления в базис даёт другой результат, и ниже неопределённости индуктивный кандидат не работает.
2. GMRES снижает сумму квадратов по всем ячейкам, а критерий — максимум по ячейке. Невязка в нескольких треугольниках остаётся.
3. Поправка `bubble` (решение на постоянном токе) после GMRES нарушает индуктивный баланс кандидата.

Шаг 1.1д — проба, одна правка, одна пересборка, один прогон 3 МГц с `P7_ENRICH_INDUCTIVE=4`. Файл `foil_reduced.rs`, только под `P7_ENRICH_PROBE=1`, поведение не менять. На каждое решение GMRES напечатать строку `P7_ENRICH_PROBE` (цена — два лишних магнитных действия на решение):

- `claimed`: падение невязки по GMRES (уже есть);
- `true2`, `trueMax`: `‖r − Z·x‖ / ‖r‖` в норме суммы квадратов и в максимуме, где `Z·x` посчитано одним новым действием над готовым `x`;
- `cand2`, `candMax`: то же для итогового кандидата после `bubble`, с учётом градиента потенциала `bubble`.

Как читать:

| Результат | Причина | Следующий шаг |
|---|---|---|
| `true2` заметно хуже `claimed` (в разы) | 1 | Проба классов несошедшихся пар из поправок к этапу 2, затем шаг 2.4. До него 3 МГц не дожимать |
| `true2 ≈ claimed`, но `trueMax` почти не падает | 2 | Смешанное правило: индуктивный кандидат, пока он даёт падение KVL больше 1,3 раза за итерацию, затем `−R⁻¹·r`. Это воспроизводит попытку 1 шага 1.1 |
| `true2`, `trueMax` падают, `cand*` — нет | 3 | Остановиться и спросить: нужен совместный решатель тока и потенциала |

Перед пробой прогнать на итоговом коде то, что не было прогнано после лестницы: `cargo test --lib foil_reduced` (два известных падения не чинить), тест GMRES, купон `diag_compact_kvl_100k_vs_1m` с выключенными переключателями (история должна совпасть со `stage2-coupon-off.log` до напечатанных цифр).

### Итог пробы и шаг 1.1е (2026-11-12, шаг согласован пользователем 2026-11-12)

Проба (evidence `docs/analyze/evidence/p7-r-highband-step11d-2026-11-12.md`): GMRES честен (`true2 = claimed`, около 1e-2), причина 1 исключена. Кандидат после `bubble` невязку не снижает (`cand2` 0,8–1,4 с первой итерации) — причина 3. Вариант без слагаемого потенциала отличается меньше чем на 5%, так что вывод от знака не зависит.

Почему так (сверено с `grow_phases`): кандидат равен `−d + R⁻¹·G·b`, где `b` — решение на постоянном токе, возвращающее KCL. После него в KVL остаётся `jωL·R⁻¹·G·b`. При ωL ≪ R это мало, при ωL ≫ R оно того же порядка, что исходная невязка. То есть KCL восстанавливается в метрике R, а на 3 МГц ток распределяет L.

Шаг 1.1е: решать GMRES сразу в пространстве токов, не нарушающих KCL, тогда `bubble` после решения не нужен. Режим `P7_ENRICH_INDUCTIVE=5`, файл `foil_reduced.rs`, по умолчанию выключен. Все кирпичи уже есть: `divergence`, `conductive`, `dc.solve` (готовое разложение Холецкого, решение дешёвое), магнитное действие.

- Проектор: `P·x = x − conductive(dc.solve(divergence(x)))`.
- Частное решение для KCL: `i_p = −conductive(dc.solve(kcl))` (это нынешний кандидат при `drop = 0`).
- Неизвестное `w` (на обе фазы, как сейчас). Оператор действия: `w → P·R⁻¹·Z·P·w`, правая часть `−P·R⁻¹·(r + Z·i_p)`. Предобуславливатель справа — блоки ступени C, затем `P`.
- Кандидат тока: `i_p + P·w`, без `bubble`. Мода потенциала: `ψ = −dc.solve(divergence(R⁻¹·(Z·δi + r)))` вместо `bubble`; знак проверить пробой.
- Цена действия: одно магнитное действие и два решения Холецкого на фазу. Замерить и записать.

Проверка шага — та же проба `P7_ENRICH_PROBE=1`: `cand2` должен совпасть с `claimed` (с точностью до процентов). Если не совпал — ошибка в знаке или в проекторе, прогон 3 МГц не засчитывать.

Критерии. Одна правка, одна пересборка, один прогон 3 МГц; печатать падение невязки GMRES на 30, 60, 120 действиях (`P7_ENRICH_GMRES_MAX=120`).

### Итог шагов 3.1–3.2 и шаг 3.3а (2026-11-13, шаг 3.3а согласован пользователем 2026-11-13)
