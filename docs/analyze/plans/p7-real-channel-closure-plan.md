## 1. Результат и границы

Из реальной RoutingBoardV2 и заданных stackup/materials получать модели выбранных каналов, связанных групп и PDN с физическими контактами, возвратными путями, собственными/взаимными R/L/C/G, потерями и подтверждённой частотной применимостью. Обычный DSL не требует ручного прямоугольника/разрезов. Сохранять исходную геометрию и source mapping для recovery и следующих анализаторов.

P7 не заменяет весь DSL: P8 строит PI, P11 — SI/TDR/eye/timing; излучение, антенны и электрически большие/многомодовые неоднородности остаются P13. Текущий объёмный квазистатический расчёт не является full-wave. Частота сама по себе не доказывает применимость. «Любая плата» и «15% при любом отказе» не являются критериями, которые можно подтвердить.

## 2. Проверенный исходный статус

Источники: [route results](../evidence/p7-route-partition-results.md), [oriented contacts](../evidence/p7-oriented-boundaries-results.md), [memory audit](../evidence/p7-memory-architecture-audit.md), [integration/cache](../evidence/p6-p7-integration-acceptance.md), [HF prerequisite](../reference/p7-hf-operator-design.md), [последний прототип](../evidence/p7-shared-return-prototype-results.md).

- Уже есть импорт/геометрия/связность, DSL без обязательного scope, маршрутный граф, произвольные polygon sections, ориентированные контакты, Node addon/worker, P6-композиция и дисковый кэш. Не создавать их заново.
- Сечения совместно рассчитывают проводники; внешняя L получается из вакуумной C0 в квазитемовом приближении. Земля уже учтена. Polygon API требует один reference polygon; остальные проводники независимы. Универсальная обработка нескольких соединённых/плавающих опор ещё не завершена.
- Joint-volume уже включает сохранённую медь области, электрические/магнитные взаимодействия. Дополнительная глобальная «земля» поверх этой модели не нужна.
- P6 соединяет переданные модели, но не извлекает отсутствующую межблочную EM-связь. Непересечение меди не доказывает отсутствие взаимной энергии полей.
- STM32: отказ planner на боковом продолжении опорной меди. Независимый whole-source reference: отдельный отказ по точности annulus/координатному диапазону. Это разные препятствия.
- Straight/bend имеют положительные low-band результаты; rotated45 и via не прошли прежние2% sensitivity gates (2.174198% и2.763860%). Sensitivity не равна ошибке относительно независимого эталона.
- Автоканал сейчас ограничен1–10kHz; отдельный local — условной1–100kHz полосой с обучением10/100kHz. Частотно-зависимые section coefficients отвергаются sectionDescriptor. Частные HF sections не подтверждают RF-канал.
- Исторический большой magnetic:1,411,442 unknowns,784,635,174 factor values,6,277,081,392B только F64 values. Это промежуточная факторизация, не конечная модель.
- Последний эксперимент:8 resistor-graph DC controls,24 EM comparisons unavailable. Не подтверждает EM-разбиение/экономию памяти; не развивать его как новый extractor.

## 3. Переиспользование и архитектурные изменения

| Часть | Сохраняем | Меняем |
|---|---|---|
| Вход/исполнение | V2→internal board, DSL, addon, workers, cancellation/budgets | Только необходимые внутренние adapters |
| Геометрия | Физические источники, connectivity, clipping, oriented contacts | Координатная согласованность и чрезмерные запреты planner |
| Быстрые линии | FEM сечений, C/C0/L, propagation, loss kernels, cache | Несколько опор/связей, coplanar, применимость, common band |
| Неоднородности | Joint-volume R/C/L, current space, reduction/recovery | Компактные достаточные области и измеренное уменьшение magnetic DOFs/памяти |
| Сборка | P6, физические контакты, заряд/энергия | Полнота интерфейсов и взаимодействий; не weld по имени сети |
| Повторы | Model/section cache | Проверенное переиспользование одинаковых локальных окружений |
| Приёмка | Corpus, references, supervisor, plots | Единая матрица точности/полосы/ресурсов |

CPU/F64. Без GPU, новых F32-кампаний, внешнего обязательного solver, собственного out-of-core и нового DSL. Два вида блоков section/local; повторяемая ячейка — источник компактной модели, не третий публичный solver.

AGND/DGND/GND/VCC — имена, а не соединения. Выбор математического reference не равен физическому объединению проводников. Даже связанная медь имеет распределённое напряжение. Соединение через компонент задаётся отдельной моделью на физических контактах; его параметры нельзя получить из формы площадок.

## 4. Последовательность работ

### A. Зафиксировать cases, эталоны и baseline

Один manifest: board/source hashes, порты, нагрузки, материалы, полоса, наблюдаемые, допуски, происхождение/неопределённость reference, hardware/threads и ресурсные цели. Реальные2/4/6layer включить с начала. Выбрать полноценные каналы NanoScope/ThunderF722; короткий fragment не подменяет канал. Для RF проверить геометрию BandAmp либо обоснованно выбрать другую реальную плату.

Разделить независимые аналитические/измеренные references, уточнённый существующий volume как перекрёстный численный reference и regression goldens. Согласие двух путей одного кода не доказывает физическую точность. Неполные публикации не превращать в fixtures с выдуманными размерами. Пригодные сохранённые данные не перезапускать без причины.

Выход: runnable manifest и baseline; не очередной полноразмерный прогон при известном неустранённом prerequisite.

### B. Геометрия и выбор численной области

1. Исправить whole-source STM32 annulus/coordinate-range отказ в общем конформном пути геометрии. Проверить перенос/поворот, большой контур и тонкую металлизацию, отверстия, gaps/bridges. Не исправлять площадь только в отчёте и не ослаблять guards скрыто. Ранее принятый дефект аппроксимации отверстий у границы допуска остаётся отдельно документированной ограниченностью; не обещать его устранение этой правкой.
2. Сохранять исходную медь целиком как данные; численная область может содержать часть с явными граничными условиями. Не включать весь polygon только потому, что он пересёк коридор: ответ не должен зависеть от CAD-разбиения одной меди на объекты.
3. Широкая однородная опора за боковой границей не запрещает section автоматически. Обоснованно выбирать протяжённую опору или ограниченную область; проверять влияние ширины/границ, сохранять значимые щели, ветви, соединения и соседей. Не превращать широкую землю в узкую резистивную ленту без проверки.
4. Через разрыв сохранять физический обход и соединения опор. Если они требуют большой области, объяснить стоимость, не заменять путь идеальной связью.

Выход: положительные геометрические проверки и complete STM32 geometry/reference preparation. Это ещё не электрическая приёмка.

### C. Дешёвые совместные модели однородных участков

Обобщить существующие section conditions: несколько сигналов, физически соединённые опоры, независимые опоры и floating conditions. Равенство потенциалов задаётся только обоснованным условием. Via/феррит/конденсатор между опорами нельзя заменить reference label.

Обязательны microstrip, asymmetric stripline, coplanar/GCPW approximation, конечный край, связанные линии на одном/разных слоях. Сохранять self/mutual matrices. Независимые single-line модели не являются crosstalk extraction.

Начать с широкой однородной опоры. Для регулярного via fence сначала проверить эквивалентное сечение в заданной полосе. Если оно недостаточно для заявленного эффекта, проверить одну совместную повторяемую ячейку с корректными интерфейсами; отдельно её края/нарушения регулярности. Простое каскадирование не должно терять значимую межъячеечную связь. Успех Z0 не подтверждает NEXT/FEXT или экранирование. Кэшировать контекст линии/переходов/опор, не один диаметр via.

Выход: совместные coefficients и измеренное преимущество на сопоставимых малых случаях. Длинная однородная трасса не тетраэдризируется целиком.

### D. Доказать сборку на EM-задаче, затем расширять

Первый integration case: две связанные линии, общий возврат, разрыв/обход и фиксированные порты. Сопоставить joint-volume и section+local: передача/отражение, delay, наводки и возвратный ток. Resistor graph и изображение разрезов этого не заменяют.

До реализации определить неизвестные и граничные условия: какие токи/потенциалы несёт интерфейс; какие R/C/L уже содержатся в блоках; как учитывается либо ограничивается остаточная взаимная связь. P6 не извлекает её сам. Не добавлять новую глобальную plane-модель поверх уже посчитанных энергий.

Неразделимую неоднородность считать совместно с влияющими сигналами/возвратами. Сдвигать разрезы в однородные участки и проверять инвариантность результата к положению разреза. Дополнительные интерфейсные степени свободы/компенсация допустимы при явной математической постановке и независимой проверке. Если схема не проходит, конкретно назвать недостающий механизм, а не подменять задачу DC.

После первого успеха: rotated/bend/via, branch/meander, смена слоя с близким/удалённым return via, несколько опор и каналов, AGND→DGND через медь. Отдельно component bridge: сначала извлечённый multiport+заданная R/C/ferrite-модель через P6, затем adapter существующего DSL. Нынешний запрет components в local executor — незавершённая интеграция.

Выход: один проверенный путь сборки и устранённые rotated/via sensitivity failures. Не заменять2% численный критерий15% физическим допуском.

### E. Память и стоимость оставшегося magnetic

Измерения идут с A; оптимизировать после B–D реально нужные области.

Порядок: (1) уменьшить объём через C/D; (2) один heavy block одновременно, общий immutable mesh/factor, ограниченные RHS buffers и немедленная проекция в малую модель; (3) reuse неизменных операторов; (4) уменьшать доказанно избыточные магнитные DOFs в текущей постановке по ошибке нужных откликов. Не повторять blanket near-copper order reduction, уже провалившее controls. Часть буферных улучшений уже есть — сначала профиль, потом изменения.

По одному кандидату с сопоставимым before/after. Записывать current/potential/magnetic DOFs, input nnz, factor entries/bytes, basis/recovery, shared/private scratch, OS peak и фазу максимума. Не выдавать reduction размера результата за снижение peak подготовки.

Если факторизация неизбежной совместной области всё ещё не укладывается в принятую ресурсную цель, P7 не закрыт. Тогда требуется отдельное конкретное решение о низкопамятном алгоритме по структуре оставшейся матрицы; CG/FMM/AMG этим планом не считаются выбранными или реализованными. Не начинать свободный перебор методов. OS paging не экономит private commit и не гарантирует скорость; pagefile не менять.

Выход: успешные сопоставимые end-to-end измерения. Failure latency не сравнивается с полным solve. Объёмный путь сохраняется для оправданных областей, не как fallback всей платы.

### F. Полоса, потери и представление для P8/P11

Низкочастотная ветвь: DC→1kHz с holdouts и DC-сопоставлением с P5, finite-return multiports, L/C и recovery. Не экстраполировать нынешнюю1–100kHz модель молча вниз. Transient допускается только для проверенного спектра источника;1kHz недостаточно для произвольно быстрого фронта.

Широкополосная ветвь: общая полоса section/local задаётся запросом и физической применимостью. Удаление hardcoded constants не является реализацией. Нужны DC/skin-transition/HF overlap, conductor/dielectric losses, frequency-dependent coefficients и сопряжение с P6. Поверхностное описание thick good conductors применять только в проверенном режиме. Local surface-current basis и согласование внешней L/C ещё требуют реализации: [HF design prerequisite](../reference/p7-hf-operator-design.md). Это существенная работа, не готовый helper.

Частоты: небольшая стартовая сетка, дополнительные точки по изменению отклика/резонансам и независимые holdouts; не каждый герц. Для SI/transient учитывать фронты/спектральный хвост, не только bit rate. Проверить пассивное, устойчивое, причинное представление и time response; таблица S сама по себе его не гарантирует.

Benchmark цели: DC..1kHz для минимального PI handoff; transition-band coupons; coupled SI и реальный RF channel с целевой точкой2GHz при применимой геометрии/материалах. Существующий10GHz section control остаётся отдельным контролем. Точные оси/области A фиксирует до результатов; невозможность RF case не засчитывать low-band успехом.

Выход: положительная common-band сборка и временные проверки извлечённой модели. P8 и P11 readiness отмечать раздельно.

### G. Реальные DSL, кэш и отчёт

Обязательные: STM32G0_CAN_RS485 полный U5→J5 канал с ветвями/слоями; NanoScope4-layer полный канал и PDN multiport; ThunderF7226-layer полный канал/связанная группа; TPS PDN; реальная RF-плата из A. Прямые JS/TS DSL как в pcb-layout, без SavedScenario вместо DSL и без обязательного scope. P6 temporal controls здесь проверяют модель, не требуют закончить продуктовые P8/P11.

Cold: пустой выделенный cache, время от начала DSL до результата. Warm: тот же процесс/модель. Restart: новый процесс+disk cache. Проверить invalidation geometry/ports/materials/temperature/core/потерь/проверенной полосы. Кэш локального окружения вводить после доказательства эквивалентности и source mapping; одинаковый диаметр via недостаточен. Широкополосную модель можно переиспользовать только в подтверждённом диапазоне.

В отчёте: исходная плата, выбранная медь, физические/численные границы, mapping, fast/local причины, overlay вариантов; S/Z/delay/crosstalk/loss/error curves и holdouts; карты токов/потерь при проверенном recovery; timeline, OS peaks, factor counts, cache evidence. Отказ сохраняет конкретную причину/стадию, не «pending».

### H. Очистка и приёмка

После прохождения replacement tests удалить заменённые production branches/flags/helpers. Независимые test references не являются legacy. DC graph prototype не принимать за P7 improvement; его уникальные полезные проверки перенести в действующие network tests либо признать избыточными перед удалением. Сохранить пользовательский native/analyze/debugging, исходные платы и raw evidence.

При Rust-изменениях обычная native build; focused Rust/TS/worker/cache tests, typecheck/build; реальные DSL должны работать на измеренном release addon с hash/version. Conventional Commits после ревью законченных изменений. Сейчас код/коммиты не выполняются.

## 5. Единая точность

| Проверка | Критерий |
|---|---|
| Топология | Сохранены gaps/bridges/spans/branches; нет weld по net name, потерянной/дважды учтённой меди |
| Численная корректность | KCL/KVL/энергия/взаимность/пассивность в применимых режимах; существующие guards не ослаблять ради pass |
| Физический результат | Основной ориентир <=8%; явно приближённые cases <=15% только с независимым подтверждением метрик/полосы |
| Сходимость | Отдельные mesh/domain/interface/width/frequency checks;2% sensitivity не равно8% physical error |
| Слабые величины | Absolute floors для complex S, наводок, отражений, токов/потерь заранее; не проценты от нуля и не phase возле исчезнувшей амплитуды |
| Reference | Достаточная точность и отдельная оценка неопределённости; полный набор исходных условий |
| Recovery | Total/regional loss и возвратные токи проверяются, если выдаются; S21 alone недостаточно |

Нельзя дать каждому блоку8% и обещать8% каналу. Coarse/fine agreement не доказывает физическую точность.15% не назначается по невязке. Допустим ранее завершённый coarse result с честной применимостью; недопустимы зануление L/взаимных связей, искусственный возврат или failed factor как approximate answer. Unverified/partial не проходит обязательную accuracy gate.

Семейства: straight0/45/90; asymmetric/multilayer sections; finite edge; split/remote bridge; several references; AGND/DGND copper и component bridges; near/far return via; regular/broken fence; branch/meander; two-line/небольшая bus group; PDN и DC/AC/time overlap. Для каждого фиксировать нужные observables; не требовать field map от модели, которая её не выдаёт.

| Обычный полный STM32 channel | <=300s;120s stretch goal | <=2GiB цель | warm<=5s; restart<=10s |
| Согласованный сложный multilayer/RF | <=300s цель, превышение явно отражать | <=4GiB цель, не гарантия любой платы | Те же цели при ограниченном output |
| Reference/диагностика | До600s на заранее выбранную попытку | До8GiB при host headroom | Только после изменения/нового вопроса |

Более тяжёлый reference требует отдельного bounded плана, не автоматической многочасовой серии. Developer limits этим документом не меняются. Для прежнего отказа нет old/new successful speed ratio. В wall включены geometry, factorization, training, reduction, validation, serialization/cache. Warm не скрывает cold.

Один тяжёлый запуск одновременно. Внутри — существующие bounded jobs с shared factors/private RHS;1/2/4 сравнить на репрезентативном изменённом пути, избегать вложенных pools и factor copies. Выбор jobs зависит от запаса памяти. Записывать peak RSS/private commit и, где доступно, признаки paging/I/O. Software byte estimate не заменяет OS measurement.

## 7. Зависимости и закрытие

Порядок: A → B → C → D → E → F → G → H. Измерения A/E идут с начала. Независимые references и low-band F можно готовить параллельно после стабилизации контактов; совместные core/geometry изменения не отдавать несогласованным исполнителям. Это порядок плана, не запуск агентов сейчас.

- **P8 handoff:** положительный реальный PDN multiport, DC..1kHz либо необходимая более широкая полоса, source/component/return mapping, проверенное P6 temporal представление/recovery. Быстрый фронт с неподтверждённым спектром не допускается.
- **P11 handoff:** положительный полный связанный канал с переходами/опорами, loss/delay/common band, off-diagonal coupling и подтверждённое представление для time response. Идеальная отдельная линия не закрывает gate.
- **Полный P7:** оба handoff, обязательные реальные2/4/6layer/RF cases, topology/refinement/interface gates, точность раздела5, принятые на A ресурсные цели, cache cold/warm/restart, очистка/документация. Остаток public P6 FFT/convolution/fitting проверять отдельно, если на него опирается потребитель; одна матрица S не закрывает весь P6.

Риски остаются явными: межблочная EM-связь; local HF surface basis/causal realization; память неизбежных больших совместных областей. План задаёт путь и точки проверки, но не гарантирует, что нынешний direct-FEM закроет их без существенного изменения. Исправление широкой земли не заменяет эту общую матрицу.
