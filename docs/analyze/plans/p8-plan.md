# P8: AC и переходный PI по реальной плате

Статус: **черновик, 2026-11-15**, ждёт решений пользователя (раздел 7). Ничего не заменяет; исходный объём P8 — [общий план](implementation-plan.md), раздел P8.

## 1. Цель

`a.pi()` на реальной плате без явного `circuit`: из платы, источников, нагрузок и моделей компонентов
автоматически извлекается PDN-многопорт (P7), собирается с моделями (P6/P6b) и считается:

- частотный режим: Z(f) в точке нагрузки, передача между портами, резонансы и антирезонансы;
- временной режим: просадка при ступени нагрузки с конечным фронтом от установившегося DC-состояния;
- распределение токов и потерь там, где P7 даёт recovery.

Сейчас `pi()` работает только с явным `circuit` (`prepare.ts:209`), на плате — `ANALYZER_NOT_IMPLEMENTED`.

## 2. Основание для старта

- По [плану P7 v1](p7-v1-closure-plan.md) P8/P11 стартуют на моделях с пометкой `unverified`. P7 v1 закрыт 2026-11-11, P7-R — 2026-11-14 ([записка](../evidence/p7-r-closure-2026-11-14.md)).
- Результаты P8 наследуют `unverified` и уровень «приближение»; `accepted` P8 не присваивает.

## 4. Пробелы, которые закрывает P8

1. **Сборка задачи из DSL.** sources/loads/components → порты на rail/return (VRM, каждая нагрузка, каждый decap, пробы); модели компонентов из библиотеки или DSL; отсутствие модели — явный отказ, не идеальная развязка.
2. **N-портовый DC-конец** и непрерывность DC..1 кГц (групповой маршрут начинается с 1 кГц, `[0,1000]` пишется как непокрытое).
3. **Частотный план.** Свип на 201 точку нельзя извлекать по точке (минуты на частоту). Извлечение в опорных частотах по полосам + сокращённая модель/интерполяция с проверкой на контрольных точках.
4. **Временная модель.** Пассивное представление извлечённого многопорта для P6 BE (прямо сокращённая RLC-модель P7 либо `passive-resonant-y` по таблице Y). Спектр фронта сверяется с проверенной полосой: вне её — «приближение» или отказ по трём уровням.
5. **Ресурсный предохранитель.** Гибридный путь сейчас без ограничений памяти/времени (`usize::MAX`, `Duration::MAX`). Для продуктового `pi()` нужен честный отказ по `.budget()`, иначе STM32G0 (5,5–6,3 ГБ) и ThunderF722 (>9 ГБ) уводят машину в своп.

## 5. Этапы

| Этап | Работа | Готово, когда |
|---|---|---|
| 0 | Базовая линия: разобрать 5 падающих Rust-тестов и 6 TS-файлов (починить или записать причину); прогнать `pdn-multiport` 10 кГц на TPS с новыми умолчаниями (один прогон, 4 ядра) | зелёный или объяснённый набор тестов; PDN-многопорт с умолчаниями даёт модель |
| 1 | Семантика `pi()` на плате: порты, модели, опорная точка, полоса применимости; документ `reference/p8-pi/` | контракт записан до кода |
| 2 | Сборка задачи и N-портовый DC-конец; предохранитель по `.budget()` в гибридном пути | DC-предел `pi()` совпадает с P5 `dc()` на той же плате |
| 3 | Частотный PI: опорные частоты, сокращённая модель, Z(f)/transfer/резонансы | аналитический RLC PDN; ESR/ESL и положение decap меняют Z предсказуемо; TPS 1 кГц–40 МГц |
| 4 | Временной PI: пассивная модель, `initial("steady")`, ступень с фронтом, проверка спектра | RLC-ступень с известным ответом; установившийся предел = DC; TPS с шагом нагрузки |
| 5 | Recovery токов и потерь, несколько rails/returns | баланс мощности; два rail на одной плате |
| 6 | Реальные платы прямым DSL: TPS63060DSCR (buck), STM32G0 (MCU), BandAmpV5; NanoScope/ThunderF722 — ожидаемые отказы/приближение с причиной | каждый сценарий — результат или понятный отказ со стадией; время и память записаны |
| 7 | DSL-статус, CHANGELOG, evidence | `pi()` в `dsl-implementation-status.md` обновлён |

Тяжёлые прогоны: по одному, ограничение ядер, без повторов без причины.

## 6. Вне P8

Автоматический подбор decaps; PDN до 1 ГГц (нужна отдельная 2D-модель пары плоскостей); энергетическая обратная связь DC-DC (VRM — заданные вход/выход); `accepted` по внешним эталонам; channels/TDR (P11).

## 7. Решения (2026-11-15)

1. Полоса P8 v1 — до 40 МГц, с пометкой «приближение».
2. Платы приёмки: TPS63060DSCR, STM32G0, BandAmpV5. NanoScope — ожидаемое приближение/отказ. ThunderF722 пока не трогаем (отказ по памяти; позже можно попробовать с подкачкой на диск).
3. Временная модель: сначала сокращённая RLC-модель P7 напрямую в P6 BE (пассивна по построению, путь уже работает в developer-гипотезе). Её R/L взяты на одной частоте полосы, поэтому отчёт сверяет Y(f) этой модели с извлечёнными опорными точками и пишет расхождение. Подгонка `passive-resonant-y` по таблице Y из нескольких опорных частот — второй шаг, если расхождение (скин-эффект на широком фронте) выше порога «приближения».
4. Внешний эталон: искать дешёвый (аналитика резонатора пары плоскостей, опубликованные измерения PDN); если найден — один результат P8 сверяется с ним.
