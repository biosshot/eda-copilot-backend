# Thermal: сокращение уточнений при согласованной точности

Исполнитель thermal_medium, прежний worktree. Прочитать thermal-convergence-policy.md из MAIN. Пользователь разрешил реализацию экономной стратегии уточнения; rejected supernodal/cache варианты не возвращать.

## 1. Сохранённые данные до реализации

Переоценить ordinary/extended TPS по новому max(0.1K,1% нагрева) правилу на полном поле: отдельный новый audit, старый FAIL не перезаписывать. Сохранить witnesses/coverage/normalization и negative substitutions.

По сохранённым stage histories TPS/Band выяснить, на каком проходе решение стабилизируется. Разделить временную и пространственную ошибки. Установить минимальные реально доступные поля/mesh для сравнения: отсутствующие intermediate данные не восстанавливать догадками. Таблица stage cost/change/coverage и выбранная stopping policy ДО нового запуска.

## 2. Реализация

Вместо обязательного исчерпания всех локальных проходов разрешить ранний переход к независимому контрольному уточнению при подтверждённой стабилизации. Контроль НЕ убирать. Если независимый контроль не проходит — продолжить в рамках исходных caps либо вернуть честный unconverged/refusal; нельзя считать любой маленький local indicator доказательством точности.

Решение должно зависеть от физического поля/критерия, не от имени платы, номера шага или заранее сохранённого ответа. Сохранить события, источники, stopS60, initial conditions, площадь/контакты и полное покрытие. Не менять временной integrator, local tolerances, spatial2% guard, рабочие memory/output/node caps или production defaults. Не переносить сохранённую геометрию/температуру в пользовательский DSL как обязательный replay.

Повторное использование неизменившихся данных допускается только с корректной зависимостью и учётом памяти; не добавлять отдельную cache subsystem. Публичный DSL остаётся совместимым. Ограничить изменения Thermal refinement policy, её тестами/аудитами/документацией.

## 3. Приёмка и лимит запусков

Сначала малые manufactured/event/hotspot cases: ранняя остановка, заведомо обманчивый local indicator, контроль не прошёл, missing coverage, лимит памяти/времени. Убедиться, что итоговая контрольная сетка действительно уточняет независимым способом, а не повторяет ту же ошибку.

Затем максимум ДВА full-board запроса: один TPS и один Band, каждый <=600s shared deadline и прежние384MiB/50k nodes/2M numeric/128MiB output. Перед ними preflight и один согласованный normal addon build, jobs1. TPS сравнить с сохранённым extended reference, Band с сохранённым ordinary и независимым spatial control; Band temporal acceptance этим не закрывается. Одинаковые authored physics обязательны, интерполяция только через проверенный physical-domain helper.

Успех: новый температурный критерий по полному полю, missing0, все прежние физические guards, явная независимая spatial validation, фактическое уменьшение числа solve stages/полного wall без увеличения planned/observed memory. Изменение арифметики/сетки отражать в provenance, не выдавать старый output за новый.

Ни повторов full runs, ни controller/curve, ни нового1800s запуска автоматически. При failure сохранить результат и остановиться. Saved audits/PNG не считаются numerical runs. Итог: отчёт baseline/candidate cost, stages, errors, карты разностей и hashes; без коммита/новых агентов. Heavy слот согласовать с P7. По завершении STOP.
