# P7-completion, этап 7.5: рациональная модель по частоте в DSL с откатом на прямые решения (2026-11-20)

Ветка `feat/analyze`. Физическая точность `unverified`, порог 1e-3 не менялся. Прогоны по одному, `RAYON_NUM_THREADS=4 P7_HMATRIX_THREADS=4 CARGO_BUILD_JOBS=4`. Решение пользователя (обязательное): при провале проверки считать оставшиеся точки напрямую, результат как сегодня.

## Где частоты решаются и куда встроено

- Канал/band-step (`impedance()`, слоистый метод, `analysis-dsl/local-executor.ts` -> `solveHybridBoardChannel` -> `runAutoFoil`): все точки оси идут одним вызовом, каждая точка - прямое решение. Встроено здесь (`src/analyze/rational-sweep.ts`, вызов из `local-executor.ts`).
- `pi()` (`pi-frequency-executor.ts`): уже строит приведённую модель полосы и считает по ней все запрошенные точки. Прямые решения на полосу - это 3 якоря плюс 8 отложенных точек аудита (в M1-SPLIT: `anchorsHz` 3, `trainedAtHz` 11, holdouts 8), одним набором `union` в `runAutoFoil` (`plannedFrequencyAuditAxis`), а выбор и число точек аудита адаптивные (`frequency_audit::run`, `board_prepare.rs`). Рациональной модели здесь заменять нечего: на 3 якорях подгонять нечего, 8 отложенных уже являются проверочными точками. Уменьшение числа решений на M1 требует менять политику аудита (число и выбор отложенных точек, порог 2%/1e-2 в `auditBoardFoilFrequency` и Rust), то есть доказательную часть и общий для каналов `runAutoFoil`. Это инвазивно и рискованно, поэтому `pi()` не тронут, M1 не запускался.

## Правило

Ось канала короче 24 точек, одна частота и DC - без изменений (вызов тот же, записи нет). Иначе:

1. Прямое решение на сетке подгонки из 12 точек (равномерно по индексам оси, оба края) плюс 3 отложенные точки (середины зазоров 2, 5, 8 сетки; всего 15 решений; запрошенный интервал первому вызову не передаётся, поэтому аудит между точками не тратится).
2. Подгонка `fitRationalModel`: S, `poles: auto` до 8, `fitD`, 30 итераций, `enforcePassivity` (только пассивные модели: канал `nature: passive`).
3. Ошибка на отложенных точках, строго: каждый элемент S относительно своего модуля, напряжение и ток порта (как в `boardFoilPortObservations`), последовательный импеданс `2 Z0 (1/S_ij - 1)` каждой пары портов. Порог 1e-3 для каждой величины на каждой точке; модель обязана быть пассивной.
4. Прошла: остальные точки оси из модели, на решённых точках сохранены прямые значения. Не прошла (проверка, не пассивна, подгонка отказала, портов больше 8): оси целиком считается прежним вызовом (результат тот же, что без этапа; цена - 15 решений первого вызова; бюджет времени для отката уменьшен на уже потраченное).

Отчёт: `solution.rationalSweep` (method `rational` / `direct-fallback`, reason, `fitGridHz`, `checkPointsHz`, `checks` с ошибками на каждой точке, `poleCount`, `passive`, сводка подгонки и навязывания, число решений, модель при использовании). При `rational` сеть `network.data` имеет `samplePolicy: 'rational-hybrid'` и `directFrequenciesHz`; `solution.frequenciesHz`/`portObservations` - только решённые точки; запись о пассивности и `evaluatedFrequenciesHz`/`rationalFrequenciesHz` в `validity.domain`. Контракт `physical-port-samples` расширен: `samplePolicy` `exact|rational-hybrid`.
