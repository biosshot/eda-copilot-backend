# P7 v1: этапы 2 и 4, промежуточный результат

2026-11-09, незакоммиченное дерево поверх `49d3187`. План: [P7 v1](../plans/p7-v1-closure-plan.md). Прогоны под supervisor, холодный кэш, исходные DSL без правок, лимит 300 с и 8192 МиБ private. Пики — выборки ОС, нижняя оценка. Локальные артефакты: `debugging/p7-v1-stage2/boards-traced` (до модели стенки), `boards-v3` (после). Первый набор шёл параллельно с компиляцией, поэтому сравнение времени приблизительно. Физическая точность: `unverified`. Цели §1.4 **не достигнуты**.

## Сделано

Вывод слоя контакта из платы; граница площади `h·P`; стенка металлизированного паза; профиль скин-эффекта на низких частотах; трассировка `P7_PHASE_TRACE=1`; тонкостенный ствол (`P7_BARREL_MODEL=volume` возвращает объёмный путь); отказ от правила формы элемента для медных колонок при `δ ≥ 3t`; отбрасывание щепок с записью объёма; допуск пар 1e-6 с приёмкой шума до 2e-3; ограничение плотной таблицы пар 1 ГиБ; индексы bbox в геометрии.

Причины и меры: резерв блоков по числу пар убран; H-матрица на коробках с `min(diam) ≤ η·gap`, η=1, листья 16; блоки меньше 1024 элементов сразу плотные; быстрая тензорная квадратура и дробление игл; цель пары 1e-5, потолок порядка 16; значение выше порога шума считается приближением и попадает в `approximatedPairs` (TPS: 3 699 из 10,3 млн точных пар, наибольшее изменение 0,159).

Остаётся: первое магнитное действие TPS не вышло из иерархии 456 оставшихся тетраэдров за 495 с (метка `P7_COMPACT_ACTION stage=local-start`, `cross-start` не достигнут). Итоговый предел 600 с, цели §1.4 **не достигнуты**, ни одна плата модель ещё не выдала. Сетка BandAmp по-прежнему 75–84 с. Исправление полигона STM32 на плате не проверено. Тест `partitioned_plan_omits_only_unused_global_sparse_assembly` падает (разница 384 000 байт), причина не разобрана.

## Final five-board measurement 2026-11-11

Commit under test: the commit preceding this documentation commit on `feat/analyze` (after `d7de66e`, plus the shrunken-domain foil evidence validator). Build: `npm run native:build` (default release profile, LTO on, 6m25s) and `npm run build`. One sequential run, 1800 s cap, nothing else running (`final1`, `debugging/p7-v1-stage2/final1/`).

| Board | Status | ROI mode, margin | Nodes | Tets | Wall | Peak private |
|---|---|---|---|---|---|---|

| BandAmpV5 | diagnostic-complete | full | 72588 | 131964 | 207.5 s | 1624 MiB |

| ThunderF722 | validation-failure `NETWORK_SINGULAR` | corridor, 1.5 mm (approximation) | 81620 | 140700 | 1742.0 s | 7797 MiB |

- NanoScope: not a hang. The solve completes in about 625 s (training-end, 262 charge and 430 magnetic actions), then the return-boundary flux gate fails at domain scale 1 (maximum relative guard-box flux 5.9% against the 1% gate, unresolved 0.029 A of 0.50 A port current). The return search then re-ran the whole solve at larger domain scales, but the budget-shrunken corridor fallback lands on the identical 2 mm corridor mesh each time (three identical full restarts in the `final1` log), so the 1800 s cap hit inside the third copy. Fix: a failed gate on a solve that carries `roiFallback`/`electricalRoi` evidence now refuses immediately with `CHANNEL_RETURN_UNRESOLVED` (rerun `final2`: 661 s). The refusal is real (5.9% is above the 1e-3 approximation tier): the corridor domain is too small for the return current.
- ThunderF722: after the mesh (481 s), charge actions (881 s) and the 2 magnetic actions (1601 s), the reduced frequency network LU fails structurally at index 178. The reduced system has 88 voltage and 2 current modes, so 178 is the imaginary row of the last current mode in the real-expanded 2n system (n=90 would put it at 179, so the exact mapping is unconfirmed); hypothesis: that current mode has an all-zero column or row (a floating or unreferenced conductor piece left by the corridor cut, or a mode whose magnetic action returned zero). Not fixed.
