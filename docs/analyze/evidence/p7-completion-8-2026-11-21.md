## Метод

- «Остров» — связная медь по `capturedBoardGeometry` (площади и стенки отверстий). Возврат канала — острова возвратных контактов.
- Если возвратные контакты лежат на одном острове, «нескольких тел возврата» нет. Число коридоров в `finite-return-closure` (`board-channel-plan.ts:277–281`) — это число коридоров по сигнальной стороне, а не число тел возврата.
- Тела на слое: компоненты связности меди возврата внутри слоя по `physicalContacts` вида `area` (оценка).
- M6 и M8 — 4-контактные наборы по два канала; `createBoardChannelPlanner` их не принимает (`CHANNEL_TERMINALS_INVALID`: ровно четыре контакта), поэтому для них смотрел только острова.

## 8.2. Записка о широком блоке

Список 8.1 пуст, поэтому записка по существу не писалась. Для решения:

1. Вариант «один широкий блок с эквипотенциальным интерфейсом возврата по всем телам меди на грани» не снял бы ни один отказ матрицы: возврат везде один остров, интерфейс по всем телам совпал бы с нынешним интерфейсом по одному. Условие, на котором планировщик отказывает (`corridors.length !== 1`, `board-channel-plan.ts:278`), считает коридоры сигнала; чтобы его обойти, менять пришлось бы сборку коридоров (`sweptCorridors`, `corridorCells`), а не `returnClosure`, и это отдельная задача — стыки в многокоридорной сигнальной цепи (для M5 — блок D5.2–V2–V1–V0 и стаб JP2, 4.5).
2. Память: расширение области до внешних границ возврата увеличивает число узлов, не уменьшает. ROI_ESTIMATE из журналов: M5 26,7 ГБ (z=30), M9 50,5 ГБ (z=10), M8 5,99 ГБ при бюджете 6,44 ГБ; M10 не оценён. Блок помещается только у M8 (и то на пределе).
3. Что остаётся отказом при любом варианте: M9, M10 (память), M5 (структура сигнала, 4.5), M6 (связанные секции, 4.6).
4. Предложение: этап 8 закрыть как «не требуется», названные отказы оставить.
