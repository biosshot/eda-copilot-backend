- Операторы 1035 с = 31,7 % стены; H-матрица 815 с = 25,0 %.
- Плоская сетка (строка `P7_MESH_QUALITY`, planar = 5148, xyNodes = 278532) одна на все полосы. Число слоёв по толщине различается: полосы 1-2 один слой (t/delta <= 1), полосы 3-4 два полулиста (`P7_FOIL_SHEET=4`, верх полосы 4,47 МГц > t/delta = 1), поэтому между полосами 2 и 3 геометрия призм разная и общая сетка «только с другим множителем» невозможна. Внутри пар (1,2) и (3,4) H-матрица идентична (все счётчики совпадают).
- Дисковый кэш H-матрицы (`P7_HMATRIX_CACHE`) в M1 не работал: Rust берёт каталог только из `P7_HMATRIX_CACHE_DIR` / `PCB_ANALYSIS_CACHE_DIR`, ни `run-one.ts`, ни продуктовый TS-путь их для Rust не задают; в логе `hmatrixCache:""`. При заданном каталоге ключ в парах совпал бы.
- Потенциал: 97,7 + 309,9 = 407,6 с = 12,5 % стены (порог 10 % пройден); из них 310 с в полосе, которая кончается отказом.

## 7.2. Реализация

Сделано в процессе, а не на диске: диск при записи 587 МБ на геометрию без вытеснения и без заданного каталога не решает задачу по умолчанию.

- `native/analyze/src/extraction/local/planar_hmatrix.rs`: `PlanarHMatrix::build_shared` и статический слот `SHARED` (одна запись `Arc`, ключ = `disk_cache::key`: координаты призм, параметры сборки, значимые `P7_*`). Совпадение ключа, числа призм и `stored_bytes <= max_bytes` возвращает тот же объект (`P7_COMPACT_HMATRIX_CACHE mem-hit` в логе); при несовпадении слот сбрасывается до сборки, пик памяти не растёт. Обход при `P7_HMATRIX_PAIR_PROBE=1`. Нового переключателя нет.
- `native/analyze/src/extraction/local/foil_reduced.rs`: поле `hm` теперь `Option<Arc<PlanarHMatrix>>`, вызов через `build_shared`.
- `CHANGELOG.md`, Unreleased.
