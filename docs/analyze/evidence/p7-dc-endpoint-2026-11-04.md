# P7: отдельная точка DC

Дата: 2026-11-04. Ограниченный пакет реализации; универсальная приёмка P7 остаётся открытой.

## Контракт

Существующий `.impedance().method('layered').target(channelOrDifferential).frequencyHz(0)` извлекает матрицу проводимости конечных физических электродов. Нативный `solveLocalDc` использует исходную геометрию `board_mesh` и разреженный `DcFactor`; электрический и магнитный AC-операторы не строятся. Это решение дискретной задачи на 0 Гц, не сертификат пространственной точности.

Результат в `segments` сохраняет порядок ориентированных портов, имена электродов, их гальванические компоненты и `dcConductanceS`. Напряжение между независимыми островами — `null`. Численные gauges не соединяют острова. Если захваченная геометрия подтверждает совместимую пару концов канала, адаптер задаёт контурный пробный ток 1 A и сообщает `loopProbe.resistanceOhm` через суммарную мощность. При обратной полярности выходного порта меняется знак возбуждения. Если совместимый контур не установлен, возвращается матрица электродов с нулевым возбуждением.

Одна проба не является независимой N-port Z-матрицей. Волновое сопротивление и reusable AC network из неё не создаются. Нативный API допускает явно заданные резистивные нагрузки и проверяет совместимость токов после их подключения; DSL-путь их автоматически не добавляет.

DSL отключает искусственную изоляцию обрезанных краёв меди. Неполная область отвергается существующей геометрической проверкой. Скрытого перехода к расчёту всей платы нет. Проверки лимитов учитывают отчёт, восстановление полей, базис контактов и sparse factor; дедлайн проверяется между стадиями и столбцами. Сам вызов факторизации остаётся непрерываемым.

Последующий W5d подключил `.components`: положительные R/DCR используют дополнительные внутренние пары физических контактов и явные native resistive loads. Внешний порядок портов не меняется; полная внутренняя ось сохранена в `nativePortMapping`. Конденсатор остаётся разрывом, обе физические площадки сохраняются. Матрица `dcConductanceS` явно помечена как проводимость меди **до** компонентных stamps. `electrodeGalvanicComponents` относится к меди, `electrodeLoadedComponents` — к системе с конечными резисторами. Для каждого компонента возвращаются DC-эквивалент, ток и потери; суммы сверяются с native. Пробное сопротивление петли включает корпусные потери, если они явно заданы.

## Границы

- Только отдельная точка 0 Гц; диапазон 0..AC не разрешён и непрерывное покрытие не заявляется.
- Материалы и покрытие металлизации проверяются на применимость к DC отдельно от AC-диапазона 1–100 кГц.
- Поддерживаются до восьми явно заданных R/C/L-компонентов с однозначными физическими площадками в автоматической области. Идеальная катушка без положительного DCR, непрозрачная device-модель, температурный закон корпусного R и компонент в ручном scope явно отвергаются. Не добавляются leakage, gmin или приближённое короткое соединение. Существующий `.dc()` сохраняет свой контракт источников/нагрузок.
- Однозначность физических селекторов проверяется для AC и DC; выбор первого из нескольких совпавших контактов больше не допускается.
- Группы SI/DDR, полный PDN, skin/HF, пространственная сходимость и обязательная case-matrix этим пакетом не закрываются.

## Проверки

`cargo test --manifest-path native/analyze/Cargo.toml --lib --test board_dc_endpoint finite_` — PASS: пять выбранных unit tests (один новый DC, четыре существующих) и один новый интеграционный тест, последний за 0.13 s. Контроль использует реальные площадки купона, переставленный порядок электродов, независимые сигнал/возврат, явный встречный ток и аналитическую оценку сопротивления однородных полос.

В первом запуске обнаружен отсутствующий import, исправлен. После компиляции unit-test нагрузки обнаружил ошибку около 1.18e-11 W при ожидаемых 2 W: абсолютный тестовый допуск 1e-12 W не учитывал обусловленность copper/load conductance. Допуск только этого теста теперь равен `32 * epsilon64 * (Gcopper/Gload) * expectedW`; рабочие гейты невязки и мощности 1e-8 не менялись.

11 целевых TypeScript tests (DC adapter, physical terminals, multiport planning) и `npm run typecheck` — PASS. После добавления реальной addon-проверки typecheck повторно прошёл. `npm run build` — PASS (ESM 186 ms, DTS 11.114 s). `npm run native:build` — PASS за 6m00s; SHA-256 addon: `37ea60127fe255af17f55b55613a6cc7269ec9e54a0196acc2859764115c353c`.

После сборки `node --import tsx --test tests/analyze-local-dc-endpoint.test.ts` — 2/2 PASS. Сквозной `.frequencyHz(0)` от DSL до нового native endpoint на реальном купоне занял 0.262 s; подтверждены отдельные острова, плавающие напряжения `null`, положительное сопротивление петли и баланс мощности. AC-подготовка не вызывалась. Это контроль реализации, не полная case-matrix или независимая проверка пространственной сходимости.

W5d: 11 целевых tests (DC endpoint/components и существующие AC component checks) — PASS. Добавленный actual-addon контроль в `tests/analyze-local-dc-components.test.ts` проверил два состояния одной платы: R=2 Ohm + DCR=3 Ohm замыкают путь через три исходных медных острова, C остаётся открытым; без R пробное возбуждение не добавляется, C не создаёт связи. Корпусные потери при токе 1 A равны 5 W в пределах 1e-8, медные положительны и учитываются отдельно; сумма совпадает с мощностью источника. Оба состояния выполнены за 0.340 s; файл tests — 2/2 PASS.
