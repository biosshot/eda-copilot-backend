# PCB layout module

`run-pcb-layout.ts` orchestrates DSL parsing, footprint resolution, graph creation, solving, reporting, and assembly. `placement-input.ts` compiles the solver input; `pcb-auto-place/` owns geometry, validation, rendering, and reports; `pcb-auto-place-v2/` owns block/tree solving, board packing, and post-placement refinement. `pcb-auto-place-v2/native/` contains the TypeScript/Rust contract and encoders. Inspect these existing paths before adding geometry, scoring, or serialization helpers.

Keep diagnostic capture opt-in; it must not alter production candidate order, scores, or cache keys. Use `npm run debug:pcb-layout -- capture <fixture>` for a timestamped run and `npm run debug:pcb-layout -- replay <capture-dir> [repeats]` for an exact native block/board input. See [debug output guide](../../docs/pcb-layout-debugging.md) for the `runs/` and `replays/` layout. A successful process exit does not imply a valid placement, so check `placementOk` and hard violations. Save experiment commands, inputs, before/after quality, wall time, and verdict under `docs/experimental/pcb/<topic>/README.md` when testing a placement change.

The completed [F32 migration](../../docs/experimental/pcb/cubecl-backend/F32_MIGRATION_ROADMAP.md) requires explicit F32 arithmetic for numerical PCB paths in TypeScript as well as native CPU/GPU. Use the shared numeric/rotation helpers; IDs, integer angles/counts and timings retain their existing meaning. Localize absolute transport coordinates before narrowing, restore them only at the output boundary, and preserve authored locked poses. Retain complete stages and physical constraints. Treat elapsed time as a quality metric, comparing the same input, build, worker budget and machine. Record native hashes and use one CPU/GPU performance pass per input/version; repeats require a change, failure or spoiled measurement. Distinguish full pipeline time from native stages and review geometry plus quality when F32 chooses different poses.

For concurrency, reuse `run-pcb-layout-pool.ts`, `pcb-auto-place-v2/tree-subtree-pool.ts`, and existing native batch/refinement parallelism. Coordinate `PCB_LAYOUT_WORKERS`, `PCB_LAYOUT_SUBTREE_WORKERS`, `PCB_BOARD_PACKER_THREADS`, and `PCB_POST_PLACE_THREADS` under one CPU budget; avoid nested oversubscription and per-candidate workers. Start with `npm run typecheck` and relevant `tests/pcb-*.test.ts`; run selected `npm run test:pcb-layout -- <fixture>` only when that integration path matters.
